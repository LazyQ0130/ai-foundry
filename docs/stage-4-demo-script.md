# AI 研究 Agent｜三分钟演示脚本

**准备：**打开已完成 Smoke 的 HTTPS Demo，使用独立 demo 账号和虚构的「Git 恢复版本」知识文档。预先确认文档为 ready、MCP 可访问、当前账号没有待确认提议。知识搜索可用本机真实 Smoke 验证过的目标：“请只调用一次 search_knowledge 搜索我自己的 Git 恢复版本资料，然后直接根据结果回答一句话，不要再调用工具。”现场模型若选择直答，如实展示观察结果；不要更改 Tool 策略。

| 时间 | 操作 | 可以照着说 |
| --- | --- | --- |
| 0:00–0:20 | 打开首页和 Agent 区。 | “这是我的 AI 研究 Agent。它基于个人知识库工作，但模型不能直接读取数据库或替我决定权限。” |
| 0:20–0:45 | 打开虚构资料，演示「搜索我的知识库」。 | “我让它查自己的 Git 恢复资料。查询词可以由模型提出，资料范围由当前登录身份决定；看到的是短预览。” |
| 0:45–1:10 | 选择 MCP 公开参考，运行已验证的主题。 | “这条公开参考走 MCP 协议。远端提供内容，本地 Registry 仍决定它只是只读工具。” |
| 1:10–1:50 | 在可恢复 Run 输入：“请先搜索我自己的 Git 恢复版本资料，整理一条研究笔记，保存前让我确认。”开始 Run。 | “这里不是一次聊天：模型先搜索，再综合，然后提出标题和内容。现在停在 `waiting_approval`，数据库里还没有新增 Resource。” |
| 1:50–2:15 | 刷新页面，点「恢复最近 Run」，核对同一提议后确认保存。 | “刷新后提议还在，因为 Run 和 Action 已落库。我看清精确内容才确认；服务端执行的就是这份参数。” |
| 2:15–2:35 | 点「实验：重复发送同一确认」，观察同一 Resource。 | “请求可以重发，但同一 Action 对应的业务笔记仍是一条。” |
| 2:35–2:50 | 展示 Agent Eval 摘要与本机报告截图或安全数字。 | “固定评估有 20 个主案例、73 个子案例。跨用户泄露、未批准写入、重复确认写入是三个独立硬门槛，最近一次都为零。” |
| 2:50–3:00 | 指向 README 的 Known Limitations。 | “这还是一个诚实标注边界的作品：没有后台 Worker 或多实例 Lease，真实模型也可能直接回答。” |

**演示结束后可回答：**Production Smoke 证明这次部署能连通；本地 deterministic Eval 才负责安全与行为硬门槛。不要在真实线上演示数据库篡改、并发洪泛或限流攻击。
