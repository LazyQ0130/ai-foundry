## 三、必须改的（P1）

### P1-1 项目页「项目验收清单」自相矛盾：表头 6/6，下面 5 条全未勾选

- 位置：`src/pages/ProjectPage.tsx:305-325`（`<Tick checked={false} />` 硬编码），数据源 `src/data/site.ts:329-335` 的 `tasks` 带 `done: false`
- 实测（学完 6/6 后打开 `/project/assistant`）：
  - 卡片表头：**6 / 6** + 满额进度条
  - 同卡片列表：`1. 用第 0 课的 Starter 跑通本地运行` … `5. 保存阶段版本并整理 README`，**5 条全部是未勾选图标**且不可点
  - 左侧信息卡同时显示「待完成正式课程 **0 节**」
- 影响：学生在最有成就感的节点看到"我做完了"和"我一条都没做"同屏，且无法交互。
- 建议：`tasks` 改为由真实进度派生（第 1 条 ← s1-l0 完成、第 2 条 ← 6/6、第 3/4 条 ← 阶段自检、第 5 条 ← 存在 commit），或直接把静态清单改成不可勾选的需求说明（去掉对勾图标，改中性序号），避免"像清单却永远不勾"。

### P1-2 项目页交付物要求学生做课程里从没教过的事

- 位置：`src/data/site.ts:324`、`src/data/site.ts:328`
- 实测：项目页同时出现 `GitHub`、`演示录屏`、`stage-1-complete` 三个词
- 但课程正文里：
  - `s1-l5.md`（保存和恢复版本）明确写「**本节只用本机 Git，不需要 GitHub 账号或网上仓库**」
  - `s1-l5.md` / `s1-l6.md` 明确写版本说明**由学生自己写**，「不用学习一套命名格式」
  - `course-content/stage-1/*.md` **全文检索不到 `stage-1-complete`**（只在 `courses.ts`、`site.ts` 出现）
- 影响：学生上完课去项目页"验收自己"，会以为漏学了 GitHub、录屏和一个特定版本名。这是**课程口径与展示口径打架**，不是学生的问题。
- 建议：二选一——(a) 项目页的"交付物/完成标准"改为本阶段真实教过的东西（本机 Git 仓库 + 可运行的本地项目 + 一个自己决定的功能）；(b) 若确实要求 GitHub 与录屏，就在 1.5 或 1.6 里补上"把项目放到 GitHub"的步骤（哪怕只给三句话的指引），并把 `stage-1-complete` 写进 1.6 的正文。

### P1-3 Dashboard 学完后的主卡片让学生"去买"

- 位置：`src/pages/Dashboard.tsx:35,40`
- 实测（已开通 Stage 1、6/6 全完成）：
  ```
  CONTINUE LEARNING
  查看已开通课程
  阶段 1 · AI 原生开发入门            [已完成]
  通过微信联系管理员购买，确认开通后即可开始学习。   ← 与上下文矛盾
  [查看学习路径] [查看本阶段]
  ```
- 成因：`currentLesson` 为空（没有下一节）且 `user.entitlements.length > 0` 时，标题走"查看已开通课程"分支，但描述仍落在无权益兜底文案上。
- 影响：刚学完的学生被自己已经买过的课"告知去购买"。
- 建议：`desc` 按三态分支——有下一节 → 下一节描述；无下一节且已购 → 「本阶段已完成，可以进入下一阶段，或回看任意一课。」；无权益 → 保留原文案。标题 `查看已开通课程` 也建议改成陈述句（如 `阶段 1 已完成`），它现在读起来像按钮。

### P1-4 注册 / 登录限流在"一个班同时注册"的场景下会误伤

- 位置：`server/middleware/rate-limit.ts:3-8`
- 现状：`registerLimit` **5 次 / 分 / IP**；`loginIpLimit` **30 次 / 分 / IP**
- 风险：校园网 / 宿舍 / 机房普遍在 NAT 后面共用一个出口 IP。一个 40 人的班同时注册，第 6 个人开始拿到 429「请求过于频繁，请稍后重试」——**这条错误和课程内容完全无关，零基础学生无法自行判断是不是自己操作错了**。
- 建议：如果按班级/社群推广，注册限流按 IP 放宽（或对已知教室出口加白名单）；同时在第 0 课的 `:::stuck` 里加一条「提示请求过于频繁」，告诉学生等 1 分钟再试。

### P1-5 `npm run dev` 在本环境下 API 进程起不来（需你本机确认）

- 现象：`npm run dev` → vite 830ms Ready，但 `tsx watch server/index.ts` **无任何输出**，3001 端口无人监听，前端全部 `/api/*` 报 `ECONNREFUSED`。
- 对照实验（同一环境、同一 `DATABASE_URL`）：
  | 命令 | 结果 |
  | --- | --- |
  | `npx tsx watch server/index.ts` | ✅ 200 |
  | `npm run dev:server` | ✅ 200 |
  | `npm run dev`（concurrently 内） | ❌ 3001 无响应 |
- 结论：`tsx watch` 本身没问题，**是它被 concurrently 包一层之后起不来**。怀疑与本环境的非交互式（无 TTY）执行有关，**不排除你本地终端里一切正常**。
- 建议：你在自己的 PowerShell 里跑一次 `npm run dev` 确认。若同样复现，把 `dev:server` 从 `tsx watch` 换成 `tsx`（本地手动重启）或改用 `nodemon`。这条只影响开发体验，不影响学生。

## 四、建议改的（P2）

### P2-1 第 0 课缺"npm install 装不动"的兜底方案（我认为这是本次最有价值的优化）

- 位置：`course-content/stage-1/s1-l0.md`（安装章节 + `:::stuck` 的「找不到 package.json 或安装失败」）
- 现状：正文只写「网络超时应先查网络」「黄色 WARN、漏洞数量提示与安装失败不是一回事」，**没有给任何可执行的替代命令**。
- 事实：学生绝大多数在中国大陆，npm 默认源 `registry.npmjs.org` 在弱网下经常超时甚至长时间无响应。这是**零基础学生放弃率最高的一个点**——他还没看到任何页面，就先卡在一个只能看进度条转圈的终端里。
- 建议：在 `:::stuck` 里直接给一条可复制的命令，例如：
  ```bash
  npm install --registry=https://registry.npmmirror.com
  ```
  并说明「装完这一次以后不用每次都加」。顺带在这一节提示「解压目录不要放在 OneDrive / 网盘同步文件夹里，路径尽量不要带中文」——这两条都是本地实测过的常见翻车点。

### P2-2 1.3 的实验提示词"只制造这一处组合筛选故障"在实现上偏严

- 位置：`course-content/stage-1/s1-l3.md:60`
- 事实（上一轮隔离副本实测）：任何"选中具体标签时跳过重要条件"的自然写法，都会同时影响「教程 + 重要」（得到 3 条而非 2 条）。要严格只坏「工具 + 重要」，AI 必须写 `activeTag === "工具"` 这类特判。
- 影响：实验阶段学生只测「工具 + 重要」，不会卡住；但一个较真的 AI 可能反复自我修正，甚至回一句"做不到只坏一处"，把学生带偏。
- 建议：把该行收紧为可实现的描述，例如「制造一处组合筛选故障：**开启重要筛选后，再选某个标签时重要条件被跳过**」，并把「只坏工具这一处」从硬约束降为示例。

### P2-3 1.3 的 `:::stuck` 漏了"AI 主动说出 Bug 原因"

- 位置：`course-content/stage-1/s1-l3.md` 的 `:::stuck`
- 现有条目覆盖了「AI 制造的 Bug 和描述不一样」「AI 一上来就把 Bug 修了」「定位时 AI 直接开始改代码」，但没有「**AI 在准备阶段就告诉你哪写错了**」。
- 影响：这一节的教学目的是让学生先自己复现、自己描述；原因被提前说出来，"自己把它再做出来"就失去意义。
- 建议：补一条 stuck：「AI 直接说出了原因」→ 要求它重新准备一次，本阶段只需要"可以开始测试了"，原因留到定位环节再问。

### P2-4 手机端课时页约 13 屏，任务清单在最底部

- 实测：第 0 课 390px 页高 **10,837px**，1.6 是 **10,127px**；「标记为完成」在 y≈9,437。
- 已有缓解：顶部有「学习任务与进度」锚点（y≈81，带 `scroll-mt-20`），点了会跳到底部，功能上没问题。
- 建议：手机端可在首屏给一句进度提示（如「4 项任务待完成」），让学生知道下面有活要干；或者把任务清单做成可折叠的底部抽屉。不紧急。

### P2-5 干净机器上的首次 `npm install` 仍未实测

- 本轮只在已有 `node_modules` 的副本里跑过，未在**全新的 Windows + 干净 Node** 上测「解压 → `npm install` → `npm run dev`」全链路耗时。
- 第 0 课 `estimatedTime` 写「25～35 分钟（安装和下载等待另计）」——措辞已经把安装等待排除在外，但真实耗时未知。
- 建议：找一台干净机器（或新建 Windows 用户）实测一次，把首次安装耗时写进第 0 课，学生心里有底就不会半途放弃。

## 六、建议的动手顺序

1. **P1-3 + P1-1 + P1-2**（Dashboard 兜底文案 / 项目页验收清单 / 项目页交付物口径）——都只在 `src/` 里改，改动小、对学生感知最强，且不影响课程正文。
2. **P2-1**（第 0 课加 npm 镜像与路径提示）——只动一篇正文，但直接影响"能不能开始"。
3. **P1-4**（限流）——取决于你是否按班级推；要推就先改。
4. **P2-2 / P2-3**（1.3 的措辞与 stuck）——下一轮改正文时顺手带上。
5. **P1-5**——你本机跑一次 `npm run dev` 确认，再决定要不要动构建脚本。

## 七、本轮未覆盖

- 全新干净机器上的首次安装（见 P2-5）。
- 真实微信支付 / 退款流程（课程是私聊开通，无线上支付入口）。
- 弱模型 AI 在零基础学生手里的实际表现。本轮我是「学员 + AI 工具」双身份，验的是**环境与内容能否让人走通**，不等于一名新手配一个能力较弱的 AI 的结果。可复现的失败形态（如"把绿色都换掉"）已在正文的 stuck / check 里被预先防住。
