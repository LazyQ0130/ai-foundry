# AIFoundry Learning Visuals V1｜视觉规范

## 用途

用于把课程中的技术关系画清楚。每张图只回答一个主要问题，图内不放真实账号、连接串、密码、Cookie、Token 或完整付费正文。软件操作截图必须来自真实界面且完成脱敏；抽象关系图始终标示为示意。

## 视觉语言

- 浅米白背景，深蓝灰正文；蓝色和蓝绿色用于正常流程，绿色用于保存或验证通过，橙色用于等待与未确认，红色只用于拒绝、错误和风险。
- 使用留白、圆角分组框、简洁图标、连接线和单向箭头。箭头必须对应真实的数据或操作方向。
- 不使用人物、机器人、3D 装饰和伪造软件截图。背景图形不能压过技术关系。
- 中文优先；POST、GET、PATCH、DELETE、Prisma、PostgreSQL、Resource、User、Session、ownerId、HttpOnly Cookie、GitHub、Vercel 等词由确定性排版写入成品。
- 有并行角色时使用左右分栏；有时间顺序时使用上到下或左到右；不同来源的数据必须在图形上分开。

## 尺寸与交付

- 当前成品以 WebP 输出，主要为 1600 × 900；样板 S2-3-01 为 1672 × 941。按信息量决定画幅，不强求后续所有图同尺寸。
- 主标签在缩到 390px 课程阅读宽度后仍应可读。长说明放在正文 Alt 和简短 Caption 中，不在图里堆小字。
- 文件命名为小写课程图号，如 `s2-3-01.webp`，分别放在 `public/course-media/stage-1/` 和 `public/course-media/stage-2/`。
- Markdown 使用 `![描述实际关系的 Alt](/course-media/stage-2/s2-3-01.webp "简短结论")`。现有 Renderer 以 title 显示 Caption，并限制图片宽度不超过文章。
- 每张图需经过概念核对、实际生图、后期排版、文字与箭头复核、体积优化、正文集成、路径核对和真实课程页桌面/手机验收。没有做过的检查应明确写“待实测”。

## 供 Stage 3、Stage 4 复用

优先复制信息密度与配色规则，按新课的知识断点重新设计构图。不要机械沿用三条横向卡片；复杂 AI 调用、异步任务和权限边界需要各自准确的节点与箭头。
