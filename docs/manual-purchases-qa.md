## 浏览器流程

- 桌面 1440×1000 和手机 390×844 走通：访客选择方案 → 登录返回原方案 → 复制完整手机号及方案备注 → 选择收款方式 → 保存 / 放大二维码 → 上传截图 → 待核实 → 后台要求补充信息 → 用户重新提交 → 后台确认开通 → 个人中心及课程权限更新。
- 在 320、360、390、430 像素宽的页面截图中，两个收款码均可解码。二维码直接裁切自提供的原图，支付宝指向 `qr.alipay.com`，微信指向 `payapp.weixin.qq.com`。
- 检查收款码加载失败后重试、未配置收款码、剪贴板不可用、超大截图拒绝、付款方式切换及已购方案学习入口。
- 模拟前端尚未获取新开通权限的旧页面，确认服务端返回已购后会刷新账号并展示学习入口，避免再次付款。
- 桌面和手机未出现页面水平溢出；后台宽表在容器内横向滚动。浏览器完整流程及异常流程未出现未捕获的 JavaScript 错误。

## 上线前仍需运营者核对

使用支付宝和微信实际扫码，确认 App 显示的收款方与页面展示的“FY工作室”一致，并确认可以输入金额及付款备注。二维码解码验证不能代替收款方核验；此项未进行真实支付 App 验证，也无需为此实际转账。

迁移、收款配置与管理员处理步骤见 [扫码付款与人工核实开通](manual-purchases.md)。
