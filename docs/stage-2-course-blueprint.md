# Stage 2｜AI 全栈开发：课程实施蓝图

内部开发文档，2026-09-28。正式课程为 2.1～2.8 共 8 节，始终升级学生自己的同一个 Next.js 知识工作台。Stage 1 已有搜索、标签、重要筛选、当前数与总数、一个自选功能及 Git 保存点；资料通常仍来自静态文件。项目文件和组件结构以学生实际作品为准，不用初始 Starter 覆盖。Stage 2 可单独购买，但建议具备 Stage 1 自检能力及可运行的同规模项目；没有项目者须先准备项目。

最终作品：真实 API、Prisma 与 PostgreSQL、资料 CRUD、真实注册登录与 Session、服务端资源所有权检查、Loading/Empty/Error/Validation，以及可访问的部署地址。模型 API、AI 摘要和 RAG 属于 Stage 3。

| 课 | 输入与前置依赖 | 学生实际操作 | 可观察结果与验证 | 本课边界 |
| --- | --- | --- | --- | --- |
| 2.1 读懂全栈项目 | 已完成的 Stage 1 项目；搜索、筛选、统计和自选功能可用 | 只读查真实资料来源和展示文件；画当前/未来数据流；在现有页面加标题、简介、已有标签输入及预览；检查改动并存 Git 点 | 两次输入预览均更新；原数据数量与旧功能不变；刷新后预览消失；能解释页面、API、服务端、数据库各职责 | 不建 API，不接数据库，不用 localStorage 假保存，不覆盖个性化内容 |
| 2.2 浏览器怎么把数据交给服务端 | 2.1 的输入入口 | 创建第一个 POST `/api/resources`；页面发送请求，服务端检查输入并回 JSON；展示请求结果 | 浏览器开发工具与页面均能看到实际请求/响应；非法输入有明确回应；刷新不假称持久 | 不接 Prisma/PostgreSQL；实验仅在受控本地环境，用非敏感测试数据，不公开匿名写入口 |
| 2.3 让数据刷新和重启以后还存在 | 2.2 的真实请求链 | 配置 Prisma 和 PostgreSQL、数据模型和迁移；写入并重新读取首条资料 | 刷新、重启后仍能查询；核对数据库记录与页面；验证迁移 | 暂不要求完整编辑/删除；认证前只在受控开发环境用非敏感数据，不能公开匿名写库应用 |
| 2.4 完整 CRUD | 可持久化的资料模型 | 把列表读入数据库，完成创建、读取、修改、删除的页面与 API | 四个动作分别从数据库复验，刷新结果一致 | 不以临时数组或仅前端隐藏代替持久数据；不提前宣称用户隔离 |
| 2.5 注册登录 | 完整 CRUD 与用户表设计 | 注册、密码安全存储、服务端 Session、登录态和真实退出 | 新账号能注册登录；刷新保持会话；退出后受保护动作失效 | 不用浏览器 `isLoggedIn=true` 假登录；此时尚未把前端可见范围当所有权保证 |
| 2.6 资源所有权隔离 | 真实会话与资料 owner 关联 | 服务端按当前用户限制列表、读取、修改、删除和创建归属；用两个账号交叉验证 | A/B 各见自己的资料；猜对 ID 也不能操作他人资料 | 不能只隐藏按钮；所有权由服务端执行 |
| 2.7 失败状态 | 已有真实请求、会话与权限 | 为读取/提交加入 Loading、Empty、Error、Validation；保留可恢复操作路径 | 空库、慢请求、断网/服务异常、错误输入及无权限均能被实际触发并看到反馈 | 不以静态装饰代替真实状态；不引入 AI 功能 |
| 2.8 全栈交付 | 2.1～2.7 的同一项目及部署配置 | 配环境变量和生产库，部署并运行迁移；在公开地址复测注册、登录、隔离与 CRUD | 可访问 URL、完整操作记录、运行说明与 Git 保存点；生产错误状态可理解 | 部署前必须已有认证和服务端隔离；不公开 2.2/2.3 的匿名写实验 |

发布门槛：2.1～2.3 均在正文、A/B 本地项目、权限与课程页面通过后发布；2.4～2.8 保持占位且未发布。第 0 课不计正式课，四阶段正式课数量仍为 6/8/7/8，总计 29。
