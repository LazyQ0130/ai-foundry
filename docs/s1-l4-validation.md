## C–E. 主任务、概念与 Prompt

从 1.3 合格项目继续，只增加“当前显示 X 条 · 共 Y 条资料”。明确旧总数不是天然 Bug，这是新的展示需求。改过数据时使用实际数量；已在自由练习实现双数量的学生直接进入只读检查，不重复造功能。

文件：代码放在哪里；修改范围：本次实际碰了哪些地方；Diff：修改前后区别；代码与结果对应：最终列表数量决定当前数字，原始资料数量决定总数；无关改动：结果正确不代表每处改动都有必要。只讲到当前动作需要的深度，不要求默写代码。

三个 Prompt 原文见内部 prompts.json：功能修改、重新读文件解释本次修改、只检查修改范围。三个都不指定最终列表变量名或固定组件结构。只读检查需要当前文件与本次修改记录相互核对；正文要求修改前先保留关键原文，缺少旧记录时说明无法确认，不能编造修改前代码。Diff 面板是可选途径，不要求项目有版本仓库。
