## P0 — 会直接伤到成交与信任

### P0-1 价格页说「包含 6 节课」，付钱之后变成「1 节课」

> **定性**：这条的**数字**会随课程发布自动消失（6/8/7/8 一旦发齐，两边就一致了），
> 所以它不是"课程没写完"的问题。但它暴露的**两套口径混用**不会消失（见 C-2），
> 而且在课程发齐之前，它是你**对外收钱时唯一会被抓的把柄**。
> 如果这期间要开始卖，先把「包含 N 节课」换成不依赖发布进度的说法。

同一份课程，全站出现三种数字，**付款前和付款后正好是最大的那一对**：

| 页面 | 阶段 1 课时数 | 数据来源 |
| --- | --- | --- |
| `/pricing` | **包含 6 节课** | `courses.ts` 静态目录（正确，符合项目约定） |
| `/auth`→`/account` 我的课程与权限 | **1 节课** | API 已发布数 |
| `/courses` | 顶部「共 **29** 节课」/ 卡片「**1** 节课」 | 两者混用 |
| `/stage/stage-1` | 「课程列表（**1** 节课）」 | API 已发布数 |
| `/dashboard` | 「已完成 0 / **1** 节课」 | API 已发布数 |
| 首页价格锚点 | 「全套 ¥599（含 4 个阶段、**1** 节课）」 | API 已发布数 |

实测文本（`/pricing`）：
```
阶段 1 AI 原生开发入门 ¥99 包含 6 节课 · 1 个阶段项目
阶段 2 AI 全栈开发       ¥199 包含 8 节课 · 1 个阶段项目
全额课程 ¥599 包含全部 4 个阶段课程
```
实测文本（`/courses`）：
```
4 个阶段共 29 节课 …
阶段 1 … 1 节课   阶段 2 … 0 节课   阶段 3 … 0 节课   阶段 4 … 0 节课
```

**后果**：学员付 ¥99（或 ¥599）买到的，是 1 节可读课。这不是措辞问题，是**付款前后的数字对不上**，
售后必然产生纠纷，且退款条款恰恰是「开通后 72 小时内可无理由全额退款」，等于把纠纷挡在门口。

**根因**（两套课时数被当成同一个概念用）：
- 正确的那个：`src/data/pricing.ts:9-11`
  `const formalCount = (slug) => { const meta = getStageBySlug(slug); return meta ? formalLessons(meta.lessons).length : 0 }`
  —— 读 `courses.ts` 静态目录，稳定返回 6/8/7/8。
- 被绕开的那处：`src/pages/Home.tsx:282`
  `const lessonCount = catalogueStages.reduce((n, s) => n + formalLessons(s.lessons).length, 0)`
  —— `catalogueStages` 来自 `/api/stages`，只含**已发布**课，所以是 1。
  同一个文件 `Home.tsx:272` 已经调用了 `usePlans()`，却没用它的 `meta`。
- 其余页面的 `totalLessons` 同样来自运行时 `catalogue`（`Dashboard.tsx:12`、
  `AccountPage.tsx:136/184`、`CourseCatalog.tsx:26/75`、`LearningPath.tsx:59/90`、`LearningPath.tsx:163`）。

**建议**：统一到一个口径。对外销售口径用「课程总数」（静态目录），
已发布数量只作为「已上线 N 节 / 持续更新」单独表述，绝不用「包含」这个词。
在 courses.ts 全量发布前，`/pricing` 的「包含 6 节课」与站内其他页面**必然冲突**，必须二选一。

### P0-2 唯一的免费试看课，拿不到它唯一的核心资源

第 0 课是刻意设计成试看的（`isPreview: true`，实测**未登录也能读到全文**）。
但正文自己写着（`course-content/stage-1/s1-l0.md:96`）：

> 点击下面的「下载 Starter」，直接获取本课使用的 ZIP。第 0 课可以预览，
> **Starter 是 Stage 1 的付费课程资源，需要登录已开通 Stage 1 的账号后下载。**

实测（`GET /api/course-assets/stage1-starter`）：

| 身份 | 状态码 |
| --- | --- |
| 未登录 | **401** |
| 已登录、零权益 | **403** `STAGE_ACCESS_REQUIRED` |
| 已购 stage-1 | 200（`PK` zip 头，24,455 B） |

而第 0 课的 4 条学习任务清单是（`/lesson/stage-1/s1-l0`）：
```
1. Node.js 和 npm 均能显示版本号                      ← 能做
2. Starter 已解压，WorkBuddy 打开了正确的项目文件夹      ← 做不到（拿不到 ZIP）
3. 在这个项目文件夹中完成 npm install                  ← 做不到
4. 保持开发服务器运行，并在浏览器看到首页、试过搜索        ← 做不到
```

**后果**：试看用户读完一节内容详实的好课，得到的是一张**做不到的清单**。
试看课本该产生的那个「我真的做出了一个东西」的瞬间，被付费墙挡死了，
转化价值基本归零。而页面还提供「已完成本课」按钮，用户会勾掉一个自己根本没做的清单。

**建议**（三选一，需要产品决策）：
1. Starter 对试看开放（ZIP 本身不含答案，只是起点项目）；
2. 第 0 课的清单改成「开通后你要完成的 4 件事」，明确是预告，不再让人当场做；
3. 第 0 课提供一份无需项目即可完成的替代路径（例如纯浏览器内预览）。

## P1 — 自相矛盾 / 占位文案上了生产

### P1-1 FAQ 页有 10 个按钮写着「此问题的链接」

`/faq` 每个问答下面带一个链接按钮。有 `link` 字段的显示正常文案（「查看学习路径」「前往个人中心」），
**没有 `link` 字段的 10 条全部显示硬编码兜底文案「此问题的链接」**。

出现位置（`/faq` DOM 文本）：「课程是什么形式？」「需要准备哪些工具？」「课程是否永久开放阅读？」
「是否包含后续更新？」「是否包含人工答疑或辅导？」「怎样继续上次学习？」「进度是否跨设备保存？」
「遇到报错怎么办？」「付款后仍无法访问课程怎么办？」等。

来源：`src/pages/FaqPage.tsx:62`
```tsx
<Link to={`/faq#${faq.id}`} …>此问题的链接</Link>
```
对照 `src/data/help.ts`：只有 9 条配了 `link`，其余走兜底。

这是开发者视角的占位文案直接渲染给用户，10 处同时出现，观感是"没做完"。

### P1-2 同一页面上「29 节课」和「0 个课程」并存

`/path` 实测：
```
共 4 个阶段 · 29 节课
已完成 0 节课 / 共 29 节课
…
阶段 1 课程数量 1 个课程
阶段 2 课程数量 0 个课程
阶段 3 课程数量 0 个课程
阶段 4 课程数量 0 个课程
```
顶部说 29 节，四张卡片加起来 1 节。`/courses` 同样（第 26 行 29 vs 第 75 行 1/0/0/0）。

根因：`src/pages/LearningPath.tsx:59` 用从 `courses.ts` 导入的**静态常量** `totalLessons`（=29），
`:163` 用 `stageLessonCount(stage)`，而 `stage` 来自 `useProgress()`（= API 已发布 = 1）。
两个数在同一屏、同一个 import 块里（`LearningPath.tsx:6-11`），只是一个是常量、一个是运行时数据。

顺带：`价值 163` 的量词也错了，`${stageLessonCount(stage)} 个课程` → 应为「节课」。

### P1-3 第 0 课「已完成」，进度却是 0%

完成第 0 课（`POST /api/progress/lessons/s1-l0/complete` 返回 200，`completedLessons` 已含 `s1-l0`）后：

`/stage/stage-1`：
```
课程列表（1 节课）
开始前准备 … 已完成          ← 列表说完成了
…
0 / 1  本阶段进度  已完成 0 节课，共 1 节课  0%   ← 统计说 0
```
`/dashboard`：
```
尚未开通课程
阶段 1 · AI 原生开发入门 · 未开通
总体学习进度 0%   已完成 0 / 1 节课   下一步：查看学习路径
```

两个问题叠在一起：
1. **同屏矛盾**：列表里明明标着「已完成」，统计是 0/1、0%。
   （第 0 课被 `formalLessons()` 排除是符合项目约定的，问题出在**分母是他买不起的 1.1**，
   导致新用户的进度条永远为 0，且看不出自己已经完成过东西。）
2. **免费课入口在「我的学习」里完全消失**：新用户登录后的第一屏告诉他「尚未开通课程」，
   引导去「查看学习路径」，**完全没提有一节免费的第 0 课可以立刻开始**。
   转化漏斗里最关键的一步（让人先动手做点什么）在这里断掉。

### P1-4 `/projects` 用了第四种分母，且漏了 `isPrep` 过滤

`/projects` 阶段 1 项目卡片：
```
个人知识工作台
关联课程进度  1 / 2      ← 别的页面都是 0/1
```
根因：`src/pages/ProjectsPage.tsx:32-33`
```tsx
const doneTasks = s.lessons.filter((l) => l.status === 'completed').length
const totalTasks = s.lessons.length            // ← 没有 formalLessons() 过滤
```
`s` 来自 `useProgress()`，`lessons` 含 `s1-l0`（`isPrep`），所以分母是 2。

这违反了项目约定「统计一律用 `formalLessons()` 过滤 isPrep」（见项目记忆）。
结果：`/dashboard` = 0/1、`/stage` = 0/1、`/projects` = **1/2**，同一个进度三个数。

## P2 — 易踩坑

### P2-1 服务端 `/api/stages` 的 `status` 恒为 `'locked'`

`server/routes/courses.ts:13-14` 把 `status` 硬编码成 `'locked'`：
```ts
return { ...meta, status: 'locked', price: row.price, …,
  lessons: meta.lessons.filter(…).map((lesson) => ({ ...lesson, status: 'locked', … })) }
```
实测：**已购 stage-1 的账号**拿到的 `stage-1.status` 也是 `"locked"`。

前端不依赖它（`src/data/progress.tsx:50-56` 自己从 `entitlements` 派生），所以现在没坏。
但契约是误导的：将来任何按 `status` 渲染的页面/端（小程序、App）都会立刻出错。

### P2-2 未发布的课返回 404，掩盖了付费墙

实测：
- `GET /api/lessons/s1-l1`（已发布、未购买）→ **403** `STAGE_ACCESS_REQUIRED`「该课程属于 阶段 1，购买 / 开通后即可学习」 ✓
- `GET /api/lessons/s2-l1`、`s3-l1`、`s4-l1`（未发布）→ **404**「课程未发布」

不泄漏课程存在性是好事，但**付费学员无法区分「这门课还没写」和「我没买」**。
第 0 课正文提到「1.1 再让 AI 修改它」，学员点 2.1 会得到和"没买"一样的 404。

12 个路由实测 `scrollWidth == clientWidth == 390`，**全站无横向溢出** ✓。两处需要横向滚动：

### N-2（需确认）1.1 被一并设为免费课

`s1-l1` 现在是 `isPreview: true`，匿名可读整篇正文（实测 `GET /api/lessons/s1-l1` → 200）。

## C-3 的验收意见：占位没了，根因还在

`src/pages/FaqPage.tsx:63` 现在给**每一条** FAQ 都挂了 `<FaqPermalink>`：
```tsx
{faq.link && <Link …>{faq.link.label}</Link>}
<FaqPermalink id={faq.id}/>
```
`src/data/help.ts` 里 **19 条问题只有 9 条配了 `link`**，剩下 10 条的真实需求是「跳到相关页面」
（课程形式 → 课程目录、需要准备哪些工具 → 第 0 课、是否包含更新 → 服务条款…），
现在被一个**复制锚点到剪贴板**的通用按钮盖住了。

也就是说：**原来的 10 处「此问题的链接」不是被修好的，是被换掉的**。
结果页面上有 18 个「复制问题链接」，对「来了解课程的学生」几乎无价值。
建议：给那 10 条补真正的 `link.to`，`FaqPermalink` 只保留为开发/分享用途（或收进一个不显眼的位置）。
