# 制作标准：第二模块增补（作者侧）

基准仍为 [production-standard-v1.md](../module-one-review/production-standard-v1.md)，原文件不改版。其问题驱动、固定源码、分层讲解、实验反证、图源与三宽度、范围保护、三层结论已足够，无须为了版本升级重写。本增补把H05–H08遇到的架构/时序边界具体化，供H09–H30按相关性使用；不是每课强塞所有子系统的模板，也不是后续开发授权。学习效果标准仍待试读。

| 场景 | 作者具体动作与交付检查 | 这次的依据 |
|---|---|---|
| 解释抽象架构 | 同一例子列“定义/配置行/运行实例/能力值/所有者”；先给具体变化和可观察值，再命名。类比必须说明不能推出的边界 | Module/Plugin/Service/Entry/Fiber、realm非OS隔离 |
| 跨课复习 | 先列前课已解释深度；本课复习后必须交不同产出。核心首次定义在主线，不靠下一课或折叠补前提 | inject加载条件→持续变化；on分发→资源退出；Entry身份新增 |
| 版本差异 | 固定Commit/包版本/字节；遇文档概括与实现差异，列条件/分支/测试状态。换版本先做课程、图、题和实验的影响矩阵 | allSettled、next无一次性保护、config整体替换、minimal例外 |
| 真实执行时序 | 给输入→选择回调/状态→执行/等待→返回/失败；去程和回程分画；开始/完成/业务静止分列。状态表写明发生阶段和普通/根等适用范围 | H06环绕；M2-01加载校验 vs ACTIVE更新校验 |
| 身份与有效值 | 配置ID、运行uid分开；配置存在、effective值、服务可用性分别取证。更新、禁用/启用、模块替换别用一个“重载”遮盖 | 同Entry不保证同Fiber；Schema拒绝raw新/effective旧 |
| 错误和边界案例 | 选能推翻直觉的一成功一失败；比较相邻失败阶段。严格顺序给单一退出协议，反例显示已发生的动作；不要只查最终undefined | 漏next/漏return、逆序启动/并发完成、解析前/应用后/restore失败 |
| 测试证据 | 每项标A/B/C/D/E及实际子路径；静态、执行、只解析分开。模拟器与官方同输入对照也不能把前者升级为App Boot | test-evidence.md逐例互斥分级；D原生HMR仍NOT_RUN |
| 图与代码顺序 | 图前提出要观察的关系，短输入/程序后给预期，解释返回/失败再看长完整程序；图源错误改源并重导，caption不可代替改图 | h07-01实改源；13图任务各异；长夹具折叠 |
| 防教学简化混淆 | 标运行器、业务替身、删掉能力和格式；门闩控制何时完成，不直接改状态。测试命名写清实际对象 | ManualClock非模拟Fiber；平面Patch子集非官方Profile |
| 跨章节练习 | 模块至少三道因果综合题；给完整前提/层序/对象身份/失败阶段，要求中间结果、证据和修复，答案逐点给分与误答原因 | A依赖、B事件/资源、C组合/状态；分值和阈值未校准 |

交付复核继续执行原v1门禁：先登记P0/P1/P2，保存前文/差异/理由，重跑受影响实验/Renderer/视觉，历史失败不可覆盖。报告必须分别给作者材料、运行证据、真实学员效果结论，不合并成“全面通过”。所有阶段继续遵守不批量删除、保护用户改动、权限/价格/数据库/发布状态不动。

这些规则只有在相应机制出现时应用：H09重点是创建/发布/所有权，未必要再次做五模式表；后续出现恢复、工具、流、并发时再复用具体失败分层。保留v1稳定结构，比新增一套机械章节模板更能防止重复和认知负担上升。
