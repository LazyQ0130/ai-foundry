# 跨课综合题候选（未施测，未校准）

这些题仅供未来集中审查选用，不计入现有平台进度。参考要点是评审依据，不是机器中文关键词匹配。

1. **改模型但没有输出。** Bundle插入Provider/Consumer，Profile只写model的config，Home禁用Provider，Consumer依赖服务。逐层给最终树，再给两行状态及调用数。参考：config整体替换；Home开关后Provider条目在但不激活，Consumer可PENDING且调用0。类型声明、包安装与运行状态分开。要指出缺失的实际条件，不能只回答“配置有错”。

2. **取消观察器后主体执行了几次？** 采用H06 lost-next/lost-return两轨迹，随后把插件卸载。参考：主体0/1与结果丢失分别说明；H07撤销on只阻止未来选中，不能取消已进入的异步回调。H08稳定ID更新也必须尊重这个等待边界。只报最后undefined不给因果不算解释充分。

3. **服务回来，谁还是原实例？** 先稳定ID挂Provider与Consumer，禁用Provider再启用，最后显式dispose Consumer后再换服务。参考：Provider新Fiber、Entry可同一；Consumer第一次依赖恢复保留Fiber，显式dispose后不会复活。需用uid与state、apply/cleanup次数支持，不只比较显示名。

4. **一份更新为何留下两种配置？** 对有效数值配置提交字符串，Schema拒绝；另一次允许校验但apply抛错。参考：前者raw已新而effective/服务可旧；后者可能撤掉旧服务、保留新FAILED条目。区分失败阶段与更新拦截，不可统一说“失败则回滚”。

5. **设计三入口复用方案。** Web、一次性、SDK共用摘要与会话但入口不同，任选合理层次，声明有序Bundle与稳定ID、依赖、完整config覆盖和退出策略。参考：base+应用层是一种方案；minimal独立树是官方特例，不能强行套继承。解释测试成本和无HMR需重启的代价，不以Bundle越多越好评分。

6. **给绿色结果降级。** 提供H08的五模板解析和20项作者测试，要求写可对外使用的验证说明。参考：模拟器、真实Cordis/Loader、真实隔离Profile/App Boot各自通过；完整官方应用、原生HMR、模型/磁盘恢复未运行；试读和独立外审待做。把not-run计PASS或称安全审计通过属于关键错误，不能靠其他得分平均抵消。

未来评分可按“结果、因果、固定证据、边界与修复”四维收集样本；接受其他有效定位路线。先观察评分分歧再定分值/通过阈值，本轮没有声称量表已校准或学员已掌握。
