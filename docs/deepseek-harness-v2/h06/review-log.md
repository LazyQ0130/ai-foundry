# H06 作者问题与修订记录

日期2026-10-29。本课从新文件开始制作；无覆盖旧课或改写历史报告。以下是本轮发现与修正，当前无未决P0/P1。语义审查与作者工具错误分列，未将第一次失败删成“一次即通过”。

| 项目 | 风险/发现 | 处理与复验 |
| --- | --- | --- |
| 精确停止值 | 把0/空字符串按falsy视为继续会错；Waterfall也不采用该判据 | 默认正文、图二、十种值真实分发与false短路反例；变异0→false必须失败 |
| parallel完成/错误 | 不可写完成顺序等于注册顺序或首错即结束 | 双门闩固定B先完成；混合同步/异步错误仍等待第三位，再抛AggregateError |
| Waterfall箭头 | 单向数值传递或拒绝绕开外层会严重误导 | 六步变量表、三层51、图三双向及短路回A；正文/图注/alt交叉审 |
| 重复next | 不能推用其他框架第二次报错经验 | 实读shared cbs.shift；同步主体两次、B短路后A进C、异步共享游标三例真实执行 |
| 异常捕获 | return next的同步try不能捕获未来拒绝 | return await next与return next分别运行；emit/bail另以故障子进程留证 |
| 类型/运行模式 | 声明和@mode不会注册或强制分发 | 发射擦除、TS2769、故意emit bail契约事件；不建议生产错用 |
| 初始实验编译 | 首次strict检查出现5处错误：回调void与显式undefined，以及动态分发重载联合调用 | 为“继续”回调显式返回undefined；serial/bail按分支分别调用，不用any或删断言；原行为测试和strict复验通过 |
| 类型负例工具预期 | 最初预期TS2345，但本API重载报告TS2769 | 查看实际诊断后固定TS2769和错误文件归属，保留实际诊断文本 |
| 补强错误测试 | 增加bail同步throw后，ctx[mode]联合重载触发TS2349 | 分支调用ctx.emit/ctx.bail；27项真实行为、变异、两个故障子进程与strict全部重跑通过 |
| 源码检查器定位 | 初始needle误写interface Events在Context类型范围、dispatchToolBody(input)和decision.kind为ask | 回读精确行，改为Parameters<Events[K]>、mutableExec、gate.kind；未删语义检查，增加真实拒绝断言与blocked断言校验 |
| 内部诊断标签 | parallel的internal/dispatch实参为emit | 加入真实诊断测试与清单精度说明，不改上游、不把标签误读为不等待 |
| 阅读负担 | 细讲五模式和三项练习超蓝图时长 | 主线保持默认7292字，长程序/答案折叠；两处口述停顿及实践产出核对；120～160分钟只标估算 |
| 证据层级 | Harness示例与官方测试不能冒称本轮执行 | 表前、C答案、清单、报告均标静态选读；真实运行限vendor核心与课程夹具 |
| 最终门禁工具 | 初版要求所有屏宽代码必须滚动，1440px短片段本来就放得下 | 改为核滚动距离等于实际溢出宽度；无溢出应为0，手机溢出则须滚到末端，不强制制造溢出 |
| 暂存差异检查 | Node故意失败日志含行尾空白、TS诊断含额外尾空行 | 运行器仅规范这两份证据的行尾与尾空行；保留诊断/退出值/断言，重跑实验与暂存检查 |
