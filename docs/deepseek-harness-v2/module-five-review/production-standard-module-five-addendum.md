# 课程生产标准增补：状态与可靠性

本增补与[E生产标准](../E-production-standard.md)及前四模块增补并读，不覆盖其历史版本。适用于后续涉及Session、持久化、压缩、重试、取消或多执行器协作的教材。通用价值来自本轮多个边界交互的复核，而非给某个实验追加专用门禁。

1. **先事件再读模型。** Event Sourcing必须给输入事件、fold/当前状态、原始事实与派生状态的区别，至少一个替换后节点顺序不等于Seq数值顺序的例子。Snapshot/冻结、提交前检查与提交后观察分开说明。
2. **每个保证标明层与条件。** “已提交”“已保存”“已恢复”必须说明主体、确认点和失败范围。内存append、Handle接受、路由排空、后端flush、OS同步及介质断电不能互换；某JSONL实现细节不得推广所有Backend。
3. **恢复与Fork必须有事件轨迹。** 明确包含切点/Offset、inherited计数、marker与closer位置、开放尾处理、普通内存Fork与持久Agent分支。官方说明若与实现/测试不同，同时列证据，教材采用条件明确的固定版本规则。
4. **Compaction同时画两层。** 审计start/summary/end和承载摘要的Surface替换必须独立呈现，标选区/来源/工具配对/原日志保留，并展示至少一个失败或部分提交分支。不得宣传通用无损、永久删除或全原子回滚。
5. **重试说明预算所有者。** 标出错误资格、当前策略key、计数范围、延迟、Waterfall顺序和下游交接；不得用一个全局N概括独立插件。模型请求重新尝试与工具重复执行分开教学，always不得写成成功保证。
6. **取消需要可观察证据。** 展示signal发出、谁观察/转发、等待谁的结算、idle/dispose/close；至少覆盖退避等待和已启动工具。静态推演不写成动态PASS，虚拟计时不当性能测量；无通用外部强杀保证。
7. **未知效果采用保守表达。** 无结果不等于未执行，call不等于已dispatch，合成错误不撤销效果。跨前缀、Fork或恢复不能挪用另一路未来；幂等必须说明由外部系统或业务策略强制，不能仅在日志里写个键。
8. **真实持久化与等级分问。** 逐列标内存、接口、真文件、flush/close、同实例、新实例、Agent Resume、后续请求、语义修复、新PID/物理故障。真实JSONL多组件仍可为D；E要求完整应用边界的实际配置与原始记录。跨实例不自动等于跨进程，更不等于真实崩溃/断电。
9. **数量有身份与重复口径。** 给逐项测试名称/组件/fixture/平台/原命令/结果/等级/重合与剩余风险。历史重跑不叠加，跨课主题重合不凭感觉换算独立故障数。保留失败和修订前证据。
10. **学习负担与验证状态诚实。** 默认/展开字数、核心阅读与辅助源码、估计/实测时间分开；给可交付的阅读停点。Provider成本、E集成、学员、耗时、独立外审分别判定，不能拿作者测试替代。

验收应用示例：本轮以八层状态表、普通Fork/Resume两种顺序、双层压缩图、预算顺序反例、门闩工具排空、128条执行身份及未验证表落实这些要求。今后出现确认P0/P1仍阻断准入；“条件通过”不豁免该门槛。
