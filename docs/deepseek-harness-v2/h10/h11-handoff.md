# H10 → H11前置知识与衔接说明

本文件只交接前置能力与研发边界，没有开发H11正文、图片或实验。

进入H11前应能在不看答案时解释：同一Agent可以运行多Turn；候选Step先领Inbox并捕获模型选择/工具集，再等待Prompt assembly与pre-step；step/start之后先准备请求路线，成功后才投影并提交系统提示/接纳输入；从Session事实派生本次冻结请求；同Step retry不重跑候选也不重复接纳用户。

H11的输入问题是：H10已经定位的System Prompt assembly具体由哪些贡献构成、怎样形成最终Prompt？应重新读固定Commit的system-prompt及runtime-context，按H11蓝图确定边界。H10仅解释它们在Loop里的位置，不替H11指定构造算法或先写实现。H10 D09证明assemble计数，D06证明取消前不提交，不能升级成H11全部贡献/顺序/替换算法已验收。

前置自查：用multi轨迹指出三次组装与请求的位置；用retry轨迹解释为什么只有一次候选组装；用request取消轨迹解释“已开Step但无本次系统/用户消息”；再用D12说明模型选择是候选快照。答不出时回看H10的Step顺序、实践A/D与思考4/5，不需要先读未来课程补本节前提。

继续保留H12的Adapter/Streaming内部、H14工具守卫审批及完整执行流水线、H17事件溯源投影、H20完整取消/退避/恢复策略。真实模型、磁盘flush与崩溃恢复未由H10验证；不因局部C/D通过而改变证据等级。
