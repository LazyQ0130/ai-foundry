# H05 作者问题与修正记录

本轮没有修改 H01–H04、Stage 或平台文件。以下记录本轮材料及作者夹具的真实迭代，不重写旧报告。

| 项目 | 发现与处理 | 当前证据 |
| --- | --- | --- |
| 技术精度 | Primer 把插件概括成 Service 对象；真实 Plugin 联合类型和教程包含不提供服务的函数/对象插件 | 主线明确“插件不必提供 Service”，S01；不机械翻译概括 |
| 可用性 | super 登记实例不等价于异步初始化完成；await 当前挂载稳定也可能仍 PENDING | 主线说明，S09/S10/S12，门闩和缺失服务实测 |
| 属性访问 | 根 Context 的读取行为不能推广到独立插件；遗漏 inject 即使服务存在仍失败 | 限定本例兄弟插件，无祖先依赖；运行负例与 reflect 分支对照 |
| 类型夹具初版 | 将 vendor 源码和课程代码放进同一个 strict program，产生33条上游诊断；Cordis 自己显式关闭部分 strict 选项 | 未改上游、未删断言；按其包选项生成真实声明，再严格检查课程消费者；错误参数负例仍被拒绝 |
| 类型负例定位 | Windows 诊断文件路径的斜杠形式与预期字符串不同 | 规范化绝对路径比较；仍要求准确 TS2345 与对应负例文件 |
| 内容检查初版 | `.ts` 夹具误用 JSX，tsx 报解析失败 | 改用 React.createElement；没有改产品 Renderer |
| 复制/预览一致性 | Windows 剪贴板与原始 Markdown 的 CRLF/LF 差异导致逐字比较失败 | 作者读取统一 LF；复制只归一化换行、去最终换行，再与受测文件全内容比较；六文件均核，不放宽内容断言 |
| 完整性 | 短类型声明及 super 接线不宜只在折叠完整文件中出现 | 在默认正文补两个短片段；完整文件仍逐字同步受测源码 |
