# 给 H06 的接口交接

本轮仅完成 H05；此页是后续研发输入，不是 H06 正文或自动开始研发的授权。

学员应带走：一张插件/服务关系图；A 的接口与装配解释；B 的正常/缺失输出；inject 错误反例；能指出类型声明、实际注册、依赖声明、调用四个位置的笔记。作者测试只能证明对应程序行为，不能证明学员已经独立完成这些解释。

H06 的开场可沿用项目助手：一次工具动作发生时，日志想记录，界面想显示，策略还可能阻止它。让每个参与者彼此调用，会再次扩大耦合；此时需要约定事件怎样传播、是否等待、何时停止、谁能改变结果。

后续按固定源码逐个解释五种模式及 Waterfall；不直接把普通发布订阅或“上一个返回值传下去”的经验套过来。H05 没有教过这些语义，不能把它当作现成先修。必须再次核 `vendor/cordis/src/events.ts`、实际事件类型声明、真实调用点和测试。

H06 无需重讲 Plugin/Service/Context 全套定义；用一个短回忆任务恢复“服务是直接借用能力，事件让多个参与方按契约协作”。若读者仍混淆类型声明与运行登记，回到 H05 的无提供方案例，不用事件机制掩盖依赖缺失。

H07 保留生命周期、资源回收、依赖撤走与热重载；H08 保留 Profile/Bundle/Patch 组合内部规则。后续研发需重新确认试读与独立外审状态，不能把本轮 CONDITIONAL GO 升格为教学效果已验证。
