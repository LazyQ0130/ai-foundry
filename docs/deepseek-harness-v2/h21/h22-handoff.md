# H21 → H22 前置知识与停止点

正式下一课为《Workflow、Jobs、Goal 与任务调度》，目标是按生命周期区分四种任务抽象并画清组合。保持蓝图顺序；此页只交接，不包含H22正文、代码、图或发布。

进入H22前，学员须能交出一份执行单元契约：任务输入、Provider能力、确切父对象、childId/runId/messageId、parent或caller交付、预算/容量、中断与dispose所有者、失败后外部效果的核查方式。用本课X证明原工具回执和最终结果不在同一时刻。

Caller Delivery适合程序编排直接收集结果；Parent Delivery给父模型后续输入。两者不改变本地子目录成员事实，也不把Subagent变成Workflow。Workflow可消费这种运行能力，但还要自己定义脚本、预算、结果与失败处理；Jobs、Goal、Schedule不能仅因都叫任务而合并。

继续携带H17/H18/H20边界：历史重读不重放副作用；消息接受不等于完成或恰好一次；最终flush可能失败；未知外部结果不能盲目重新委派；新Agent不是旧Promise复活。容量满是准入拒绝，不能默认任意无限排队。

可复用本课C/D轨迹；外部四Provider、Host设置UI、独立Preset恢复、真实模型费用/性能、跨进程继续及E级完整应用仍无本课动态证据。H23通信载体与H24综合证据继续按正式规划。完成H21后停止，不自动开发H22。
