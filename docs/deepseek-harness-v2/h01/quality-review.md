## 首次概念解释审查

| 概念 | 通俗解释与案例 | 严格界定、源码与边界 | 理解题 |
| --- | --- | --- | --- |
| LLM | 研究助理提出比较或保存建议 | 模型服务接消息生成输出；`step()` 从输出提取调用后才分派；不自带宿主权限 | “说保存成功”应看什么；职责分工题 |
| Agent | 围绕目标，根据新观察继续行动 | 教学定义与官方运行实例语境分开；AgentFactory 注释；不必独立进程或每次用工具 | 四项分工与第一张图 |
| Runtime | 工作流程约束何时动设备 | 调度/状态/检查/分派/停止职责；不等于某一个类或 JS 引擎；确定性规则≠整个系统确定 | 审批边界与失败分支实验 |
| Harness | 提供完整工作环境 | 组织运行、状态和接入机制；默认循环也是插件；术语不强行互斥 | 更换模型为何不自动补审批；思考三 |
| Plugin | 可挂载的工作台能力 | 文档的服务/事件/可逆登记；不能把卸载登记理解为撤销文件写入 | 替换模型的收益、成本与安全边界 |
| Provider / Adapter | 供应方与转换接头 | `LlmRuntime.prepareCall` 按路由准备调用；接口统一不代表能力或行为一致 | 思考三的兼容性核查 |

没有将 V2 概念卡整份粘贴进正文；Cordis 只作底层框架定位，Context、生命周期、Waterfall 留后续。日志与模型历史先解释其用途，不提前引入完整投影算法或事件溯源术语链。

## 内容审读发现与修订

| 审查问题 | 最终处理 |
| --- | --- |
| 把 Stage 4 简化成只有循环，会否定旧课已经教授的边界 | 明确 A 是刻意删减的教学对照；正文点明 4.3、4.6、4.7 的已有成果 |
| 四个概念的嵌套图可能被读成部署层级 | 正文、图内、图注三处限定按职责组织，模型可以远端，Runtime 可属于 Harness |
| “确定性”可能暗示整个系统结果可复现 | 明确只指代码与配置规定检查规则，模型、网络及外部状态仍会变化 |
| 初学者会被 Turn / Step 的特殊情况打断 | H01 只读执行分派边界；复杂调度和生命周期留既定后续课时 |
| 一份日志可能被误称为恢复系统 | 明确内存、落盘、恢复和外部结果分别核对；B 不实现跨运行恢复 |
| catch 可能被误读成自动回滚 | 加入写后报错但笔记数为 1 的第五组；思考二要求分别解释两种失败 |
| 重新批准案例可能冒称恢复待审批动作 | 明确每组重新建立内存世界；没有实现 Resume 或持久消费 |
| 故意改 reject 后触发原始断言，学生可能以为工具坏了 | 说明固定基线的断言预期失败，先核对拒绝效果再还原，不改断言求绿 |
| 协作图连线压到“组装/返回、请求/输出” | 人工检查发现后移动线与标签，重新生成并重跑三种视口 |
| 未挂载 React 的静态预览会有不能工作的复制按钮 | 静态阅读页明确移除按钮；单独对真实 React 组件验证精确复制 |

长文件精读控制为三个核心源码文件加两个辅助文件。每站说明先找什么、为什么先读、输入/处理/输出与本课停止位置。没有大段官方源码逐行注释；唯一较长代码是可折叠的原创完整实验。

作者审读认为主线连续、没有重大跳步或冗余；这属于作者判断，不能证明真实学生已经读懂。可能仍需试读调整的地方是“通用 Agent 概念”与源码同名接口的转换，以及工具写后错误的理解速度。
