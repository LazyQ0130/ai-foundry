# 后续课程作者制作标准 v1.0

适用 H05–H30 的研发流程，不是本轮开发或发布授权。基于本次模块审查，**作者侧技术与编辑标准可冻结为 v1.0；学员教学效果标准仍待试读校准**。冻结意味着后续修改需注明版本、理由和影响，不意味着每篇按模板写完即合格。

本文件落实 V2 的 E 规范；存在精度差异时采用本轮更明确的证据边界。例如蓝图的 durable 概括不能替代 commit/flush 区分，导航路线不能标成运行调用链。保持既有 Renderer、目录与权限隔离要求。H04 先前准备包中“需试读/独立审稿才能冻结”的候选要求，本轮拆成作者标准冻结与教学效果待验证两层；没有伪造那两项已经完成。

## 一条主线，一项增量

每课先写一个真实工程问题、唯一核心目标和可观察的产出。导入用具体缺口，解释后再追源码，不以“本课你将理解”代替解释。正文按问题自然分段，不强制每课十段同名标题。末尾只交接下一问，标明本课停在哪里。

新增术语必须服务于本课问题。重要概念至少有：它解决的问题、一句人话、贯穿案例、准确技术定义、真实来源、类比失真边界、能揭露误解的问题。可以分布在相邻段落，不把七步表贴成正文。不必要的英文缩写删去；必要英文第一次附中文，用具体对象连接术语。

与上课重合时说明增量：职责→定位→时序→准备条件是四种任务。同一关键词可以短复习，不能重复整份定义、同一实验或无新增作用的图。优先修影响理解的段落；P2 修辞不构成整体重写理由。

## 旧知识回顾与阅读负担

回顾必须绑定实际 Stage 正文、位置与深度，通常设计 3–8 分钟，仅说明本课所需对比；不得把旧课 Run/Step、登录 Session 或 HMAC 机制直接说成 Harness 同名实现。原课链接可选，保留足够自足解释，不假定购买权限。

核心依赖不能只藏在可选折叠中。比如后文要比较包、模块与服务，主线就必须先给实际对照。可选语法补课、长程序和详细参考答案适合折叠，但决定安全/正确性的限制必须在主线可见。

每课统计默认正文、全部正文、核心概念、代码、精读片段与辅助引用、练习/思考/图数。数量只是负担信号。超过前课明显台阶时，给实际停顿、回忆任务和下一段起点，不只在时长栏写“可分两次”。实际时长、难度与学习效果未经试读时明确待验证。

## 源码精读与技术审查

1. 先锁 Commit、版本与字节，链接绑定固定 Commit 和准确行范围。更新版本需做受影响课程/图片/实验差异，不追 main 自动替换。
2. 精选 2–5 个核心源码文件；文档、配置、测试、辅助证据另列，不把全部引用数量说成必读数量。每站说明先看哪个符号、后看哪段、为什么这样读。
3. 函数按输入→处理/状态→输出→失败边界解释；精读短片段，不复制数百行再逐行注释。接口与实现、模块导出函数与类方法、真实类名均核对所属关系。
4. 调用链必须读条件、循环、回调、实参求值、await、catch/finally 与提前返回；选读测试的 setup/action/assertions 交叉核对。正则/AST/词法行号是防漂移辅助，不能独自证明语义。R01 表明“链接正确”仍可能类名错误；R02 表明“图正确”仍可能图注解释错。
5. 官方事实、教学简化、作者分析分开标。无直接依据的动机写待确认；文档与实现冲突登记，不能挑一句顺手的文档掩盖差异。
6. 证据至少含断言、源码/测试位置、适用条件、验证方式、状态。定位/选读/实际执行/端到端分开；未运行完整官方套件不得写“官方测试通过”。预览版未审计的边界保留。

## 图示质量

按解释需要选架构、流程、时序、包含、对比图；每图只承担一个主要认知任务。通常 1–3 张，数量不是合格门槛。图前提出问题，图后给读法与限制，alt 说明核心信息，图注不只重复标题。

先定义节点和边：职责容器不是进程，静态依赖不是调用，构建项目不是机器，实时通知不是持久消息。条件与省略影响结论时必须写出，箭头图例、正文、alt、图注四处交叉审。事件名与顺序都核固定源码。

保留可复现 SVG/生成脚本与 PNG；沿用现有色彩、字体和纵向分段，不为统一而改版。检查 1440/390/320 的实际课页宽度、原图交互、中文字体、文字边界和密度；实际看图记录具体样本，不用几何脚本替代方向审查。约 12.6px 的手机辅助文字只代表尺寸，不是所有人舒适阅读的证明，重要信息也要有正文。

正文、答案及私有图不写 public。`/course-media` 的本地映射不代表线上可用；未来接入前另审素材公开性、鉴权和授权，不能因路径规则满足就发布。

## 实验与思考题

优先一个可复制、零 Key、固定 fixture 的小实验，展示与本课主线直接相关的成功和关键反例。复杂子系统用确定性替身，列出删掉的能力与数据格式差异；不冒充官方实现或安全保证。完整程序与受测文件逐字同步，长代码折叠、块内横滚、实际复制精确。

测试应核行为：错误是否阻止执行、工具结果是否参与后续请求、请求快照是否被篡改、业务效果是否已发生。至少设计一个能让检查失败的错误答案/输入，不删断言求绿。避免测试只复述常量或搜到关键词就当调用链成立。官方 helper、独立 Mock、完整应用三者分开报告。

题目要求解释反例、预测路径、找证据或迁移场景；答案说清过程和边界，支持折叠。给分看论证与事实，接受其他有效定位路线，不靠中文关键词自动评价自由解释。模块测验应有跨课题；安全关键误解不被平均总分遮住。评分阈值和一致性未经试读时不称已校准。

实验只接触明确新建 fixture 与课程文件；不让模型命令碰个人 Home/凭据/私人资料。没有必要不编译全仓或调用真实 API；不执行递归批量清理。数据库、系统命令、真实费用或外部网络若后续专项需要，先明确必要范围和已有授权，不能从本轮 Mock 推断已获授权。

## 门禁、证据与发布前检查

| 门禁 | 必需证据 | 不允许的替代 |
| --- | --- | --- |
| 技术事实 | 固定字节/行界限，分支审阅，相关测试定位与执行状态 | 只校链接或术语出现 |
| 编辑与教学 | 目标→解释→实验→验收对应，前置依赖、反例、阅读路线 | 模板字段填满、机器测试全绿 |
| Renderer | 实际 parser/组件/CSS，五元字段与全局任务键，折叠/复制/代码横滚/原图 | 静态 HTML 有按钮却未挂载，或复制单句代替完整代码 |
| 视觉 | 成图实际查看、三宽度自动记录、图源与正文一致 | 只交提示词或占位路径，或者只跑文字越界脚本 |
| 实验 | 可复现命令、输入与预期、成功/边界证据，失败非零 | 声称 Mock 等于真实服务或完整官方套件 |
| 范围保护 | 开始 Git 状态、原文件哈希、明确修订清单、暂存 diff、独立提交 | `git add .`、覆盖 output、修改他人并行工作 |
| 真实效果 | 试读样本、耗时、无提示作答与迁移解释、评分分歧 | 作者自审冒称外审，代码测试代替理解 |
| 发布 | 后续明确授权、素材与权益/目录/进度/鉴权/线上测试 | 把研发 GO 自动当发布 GO |

P0 是技术事实错误、严重误导或关键链断裂，阻断作者交付；P1 是明显影响理解的跳步、图或练习缺陷，原则上修复并重跑受影响检查；P2 可登记后续。先登记问题及依据，再决定范围。保留前后 patch、理由与当前正文哈希；历史报告不重写成“当时没问题”。

对每次交付分别下结论：技术验证的范围；作者内容审查；学员效果。作者侧无未决 P0/P1 可 GO 进入下一节独立研发；试读/外审未做时总体只能带明确条件，不能宣称教学效果已证实。线上发布仍需单独验收。本轮仅冻结这套作者研发流程，H05 正文没有开始。
