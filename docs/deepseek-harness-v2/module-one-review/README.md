## 主要发现及处理

H03 的 `LlmService.prepareCall()` 与实际 `LlmRuntime` 类名不符，学生按符号找不到；已改正并增加所属类 AST 门禁。该课图注又把“继续下一 Step”的控制虚线解释成实时通知；实际图源正确，因此只改引图文字、alt 和图注。这两项说明链接正确、图能加载和已有测试通过都不能代替内容审读。

H01/H02 之间补了服务能力对象，以及 tools 包、index 模块和运行时服务的同一例证，避免把它们当三类文件夹或三个进程。H04 在启动链和配置来源之间加了可执行的暂停/复述任务，没有删去正确性边界，也没有扩大到插件内部算法。实验和十二张正式图片均保持原样；本轮重新生成的图片与原 PNG 完全相同。

四课分别解决职责、导航、执行和启动条件，有独立产出且能连接成系统认知。没有发现必须大段重写的重复。高密度集中在 H03 的接纳/结算/尝试边界，以及 H04 的环境/配置树/凭据三套规则；本轮给出分段和量化负担，不能据作者判断宣布实际难度已经平滑。

正式材料预计合计 380–520 分钟，比蓝图 250–340 分钟增加约 52%–53%；这项差异已公开记录，未回填旧蓝图来掩盖范围增长。综合测验再建议 60–90 分钟，均未实测。

## 审查证据怎样解读

准备材料包括 V2 的定位、全课路线、制作/视觉/概念约定，本模块逐讲规格，H01–H04 正文、完整程序及测试、答案、源图/成图、原源码清单/报告与衔接说明，H04 集中审查准备包，以及 Stage 4 对应正式段落。没有只凭原质量报告下结论。预览用实际平台解析与组件对当前正文重新生成和检查，不用独立仿造的阅读器代替。

顺序核对采用固定字节→实际分支→官方测试断言选读→限定 helper/Mock→图文交叉。机器记录只证明其覆盖范围；作者审读只证明本轮编辑判断。两者均不能证明学员真实理解。`evidence/manual-review.json` 明确同一作者和实际看图样本，没有虚构独立审稿或学员记录。

仍未验证：完整官方 Vitest/构建/打包 CLI/真实模型及协议握手、原生 HMR、OS 沙箱、真实提示注入综合防御、跨进程持久恢复、线上鉴权媒体与进度。版本是未审计开发者预览，不能把技术探针推广成生产安全认证。
