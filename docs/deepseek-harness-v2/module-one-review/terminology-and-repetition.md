# 术语、重复与类比审查

依据四课正文、源码与实际实验，而不是仅搜索词频。R 编号见修订前清单；下表的“通过”只指作者内容审读。

| 术语组 | 统一的阅读约定 | 容易误读处、处理与结论 |
| --- | --- | --- |
| Agent / Runtime / Harness | Agent 是围绕目标的行为与源码实例语境；Runtime 是推进、检查和分派等运行职责；Harness 组织这些运行能力 | H01 明确职责不互斥、不等于进程嵌套；后课沿用，没有把 Runtime 固定为唯一类 |
| Module / Package / Service | 代码模块的导入导出、包身份/入口与运行时能力对象分三层 | R03/R04 补主线实际例子，避免“服务”自动被理解为网络进程；完整 DI 留后课 |
| Service Definition / Provider / Consumer | 约定、提供实现、使用者；可在一包，也不必三个进程 | H02 的医院类比只帮找角色，不用来证明依赖注入算法；Provider 在 H01 模型商语境更窄，H02 明确泛指能力提供方 |
| Session / Model History / Event Log | Session 接受有类型有序事实；模型消息是有效表面的派生视图 | H01 是用途，H03 才讲细分；旧课登录 Session 与 Harness Session 不直接映射。并非所有事件给模型，append 不等于 flush |
| Turn / Step / Attempt | 一轮驱动边界、期间步骤、模型尝试分开 | H03 图与实验含零 Step、多 Step；H04 没有将启动当 Turn。一次 Step 可有多工具、也可重试；不是 API 次数计数器 |
| Plugin / Profile / Bundle / Patch | 可挂载能力、具名运行组合、配置/能力组合包、树修改清单分别承担不同问题 | H01 只预告插件用途；H02 定位组合；H04 才比较模板与来源。没有提前复制 H08 算法；minimal 不是 base+sdk |
| Host / Client / Launcher / Application | 执行宿主、消费客户端、准备并分派启动的程序、提供具体入口生命周期的应用层 | 编译 Host/Client 不是物理机器边界；SDK 与 ACP 传输相似不等价；CLI 可含多种模式，非每个 CLI 文件都“启动模型” |
| Dependency Graph | 图中先定义节点与边：源码引用、构建引用或对象调用 | 三类关系不互相推出。蓝图 H02 粗略“调用链”包含 workspace/paths；正式教材已经按三层解释，本轮标准要求以后不要沿用粗略串联 |
| Stream / committed / durable | 实时帧、Session 结算、持久写入分层解释 | R02 修复正文把控制虚线误说成通知。蓝图有 durable settlement 概括；正式 H03 的 flush 限定更精确，不回退为“已落盘” |
| LlmRuntime | 固定版本实际 LLM 服务类，prepareCall 为其方法 | R01 修正 H03 的不存在类名 LlmService；新增 AST 所属类门禁，哈希/链接正确本身抓不到这类错误 |

## 哪些重复保留，哪些不宜扩写

| 内容 | 四课的不同任务 | 决定 |
| --- | --- | --- |
| 模型提议不等于授权 | H01 分职责；H02 找执行器；H03 看检查发生位置；H04 选树不代表已安全 | 保留短提醒；不要每课再复制四词定义与同一审批实验 |
| 默认工具链 | H01 只找分派边界；H02 契约/提供方/消费方；H03 结算/反馈；H04 配置选中什么 | 是同一主线的不同视角，不是四遍相同课。后课精读须明确新增分支 |
| 日志不万能恢复 | H01 写后失败；H03 实时、提交与 flush；H04 就绪诊断与业务事实 | 保留关键限制；后续 H17/H18/H20 才讲算法，不在本轮扩写 |
| Profile 表与 minimal | H02 只导航模板；H04 才要求选择与解释反例 | 两表深度不同，可保留；不在 H03 插入启动配置讲义 |
| Node 环境、Key 与复制完整程序 | 每课独立实验可单文件运行；官方工具链和教学 Node 要求不同 | 独立阅读必需的短说明可重复，不能统一成一个官方版本要求 |
| 多处“未验证” | 防止把 Mock、UI、源码静态定位误说成生产验收 | 保留具体范围；不要用笼统免责声明替代边界解释 |

没有发现需要删除的大段逐字复述。字词相似不自动构成教学冗余；按目标、案例、证据和练习作用判断。正文最值得控制的是 H03 的边界分支和 H04 的配置来源密度，已提供分段，后续依据试读收紧而非为了短而删正确性条件。

## 类比的失真边界

研究助理/工作台解释提议与执行，不表示远端模型被部署在 Harness 内。园区与医院解释组织和三角色，不表示一个包一台服务器。待办篮解释 Inbox，不表示领取已经被模型看见。领料单/回执区分调用与结果，不把“有单据”当实际成功。H04 班次菜单解释组合与覆盖，不能代替源代码中的完整 config 替换规则；热重载的营业类比也不承诺所有东西随时可换。原文均给出限制，本轮不替换这些有用的类比。

仍待真实试读：读者是否能在更换案例后主动区分三个“接口”、两个 workspace、两个 Session 语境，以及 Provider 的宽窄含义。术语表的编辑通过不能证明迁移能力通过。
