## 一次集中试读的任务单

在看答案前依次完成下列任务；禁止用“所有脚本 PASS”替代口述。

1. 给一个“模型说已保存、但工具未被批准”的场景，解释职责和真实成功证据。
2. 从工具功能出发，找到接口、选中实现、调用方和一条实际测试断言，画出不同类型的边。
3. 画 README 请求：直接回答、工具反馈、输入拒绝三条，标出 Turn/Step、助手结算和工具结果；解释一次 Step 内重试的例外。
4. 选择完整 SDK 与 ACP，说明传输、协议和生命周期；再解释 minimal 的组合与权限例外。
5. 追踪 H04 的 B 夹具；换一个参数顺序、一个非法 dotenv 名字、一项字面量 config，先预测再运行。
6. 解释为什么“Web 能开”“dump 里有配置”“idle”“有会话日志”分别还不能证明什么。

建议记录原答案、修订后答案、提示次数、卡点位置与实际耗时，均不记录真实秘密。每项按 0/1/2 记录：0 无法解释或关键边界错误；1 主线正确但需提示；2 能独立解释依据和限制。该量表是候选审查工具，未经过效度验证，不冒充正式学习能力评分。

## 冻结前的决策材料

必须有技术证据新鲜度核对、至少一轮独立技术/教学反馈、代表学员试读及手机阅读反馈，明确需修订与保留的部分，再由项目负责人决定是否冻结。此处是本轮拟议门槛，不声称已获外部评审或学习效果验证。

候选待关注项：H03 的 Step/attempt 与实时/持久边界是否过密；H04 的普通环境、受管凭据、配置层是否需要分两次学；五核心文件是否能独立按顺序定位；长图是否降低全貌感；完整程序折叠后的阅读是否仍自足。

本轮作者只完成衔接与重复检查、技术门禁和准备包。集中审查未执行、学习时长未实测、标准未冻结；不安排自动后续任务。
