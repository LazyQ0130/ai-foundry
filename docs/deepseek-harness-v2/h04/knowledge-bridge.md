## 重复与边界判断

- 与 H01 共有 Runtime 与安全边界，正文只恢复一个概念，不再次解释模型能力为何不足，也不重复笔记保存实验。
- 与 H02 共有 Profile/Bundle 名称和构建产物；H02 解决“在哪里”，H04 解决“怎样选择、读取与生效”。用固定模板作为复习锚点有必要，不再次介绍全仓目录。
- 与 H03 共有“就绪不是任务完成”、服务共享；H04 没有 Turn/Step/流结算代码。项目助手场景延续，但交互需求从一次请求转到四类使用者。
- 六个启动概念先用直白问题解释。Kitchen 类比只用于 Profile/Bundle，明确配置涉及代码与副作用；不重复 V2 概念卡全文。
- H04 讲层序与整个 config 替换，是判断端口、dump、恢复必需的最低知识；不推导 Patch 算法、Loader 生命周期、HMR 失效与模块缓存细节。

## H05 的接口交接

交接问题：“不同 Profile 能组合不同能力，这些能力为什么能作为插件装配在一起？”

学生带走三份材料：五场景 Profile/入口/组合定位表；早/晚参数切分和配置追踪；来源限制、dump 与重启边界说明。H05 再沿 Context、Service、Plugin 解释装配契约；H06 解释通信，H07 解释生命周期，H08 才解释组合与重组的内部规则。

本课尚未完整实现任何这些后课。第一模块结束后需集中教学审查，见 [审查准备材料](module-one-review-prep.md)；制作标准状态为 CANDIDATE，不能由技术检查直接升级为冻结。

暂估 110～150 分钟，可分“入口/主线”“环境/练习”两次。真实时长、独立定位能力、多个配置来源能否被首次读者理解仍未验证。
