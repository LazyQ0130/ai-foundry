2026-10-29。结论：**作者侧教材与本轮技术检查完成，未发布；学员试读、实际时长与独立外审待完成。** 本报告由同一作者分轮核源码、正文与图片，不冒称独立审稿。

## 教学主线与覆盖

开场延续 H03 的项目资料助手，将需求换成四类使用者。先复习真实 Stage 1–4 的安装、开发服务、构建、生产变量和服务端凭据，再解释 CLI、Launcher、Profile、Bundle、Runtime、Application。五种 Profile 表对比入口、组合、传输与生命周期；SDK 客户端库、SDK 进程和 ACP 协议分开，minimal 例外给出明确的权限提醒。

五文件阅读路线从参数契约到分派，再到 Profile 准备、目录/包解析、宿主准备与挂载。后续围绕两种数据讲来源：普通环境先验证再查优先级；配置树按清单顺序应用。受管凭据放可选折叠区，避免把所有机制塞成一条覆盖顺序。dump、重启与 HMR 只解释使用边界，不展开 Cordis 容器或 Patch 算法。

真实错误表覆盖 Node、pnpm、名称、参数、模型/凭据、Bundle/插件、环境来源、配置不生效与旧构建产物。每项有现象、先查路径与有限恢复方式；没有建议删工作区、Home、lock 或个人数据。危险的 --from-default-profile 只解释替换语义，不作练习或默认修复命令。

练习 A 不是只猜名字：要求公共入口、应用提供方、按顺序的组合包和选择理由。练习 B 用固定内存数据追踪七项结果及三个反例，完整答案与校验程序可折叠。校验器只评分规定事实，不声称能评自由理由或部署能力。三道思考题有完整解释；课程末留模块一集中审查与 H05 问题，不自动进入后课。

## 技术核查与修订

| 容易讲错的点 | 本课采用的依据与限制 |
| --- | --- |
| 启动器参数始终全局有效 | 真实 Commander 15 解析验证首个未知 token 后都交给应用；晚放 overlay 不会由启动器偷偷领取 |
| 读源码行号就知道执行顺序 | O1 识别 runProfile 的参数内部有 loadLayeredEnv，先求实参再调用；O3 核 boot 真正执行 prepare 回调的位置 |
| 所有 Profile 都是 base + app | 固定模板确认 minimal 只有独立 Bundle；同一启动提供方可被不同树复用，默认 broad Shell 权限需单独说明 |
| SDK/ACP 就是 HTTP 服务 | 读取实际 JsonRpcLineTransport 和 ndJsonStream 接 stdin/stdout 的实现；协议互不等价；没有执行真实握手 |
| dotenv 像 Next.js 一样找文件 | 读取一次调用目录与 Home；先定 Home、先验证两文件，再物化；禁止来源即使被继承值遮住也拒绝 |
| 所有代理变量都像普通值 | Home 有指定代理名字例外，项目文件仍拒绝；CA/TLS 不例外；没有实际网络路由测试 |
| 凭据永远遵循 process 优先 | CLI 摘要与实际受管实现矛盾，依据 resolve 与 managed-first 测试；Headless/minimal 不套受管规则 |
| dump 完全只读、等于生效值 | prepareProfile 可写文件；表达式未求值、不解析应用 flag、另有运行期开关，不承诺脱敏或激活成功 |
| HMR 等于重读所有东西 | Web 配置重组与模块 root:[] 分开；其余模板禁用/未挂载；argv、env 和固定 overlay 不自动重读 |
| 任何插件失败都直接整树退出 | Bundle 有跳过并报告分支，后续 required/optional 激活审查不同；不把文档概括当完整实现 |

第一轮行号门禁发现 Headless patch 引用终点超出文件一行，已修正为 35–46。配图初稿为 minimal 留了独立容器，终审补上启动器选择该树的分支，避免误读成只能从 base 进入。完整程序中只解释教学子集，不把受限参数/表达式处理冒充通用官方解析器。
