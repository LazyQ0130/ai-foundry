# AIFoundry 产品评审报告

> **评审范围**：课程正文内容之外的**全部**产品环节（定位、流程、信息架构、交互、学习闭环、支撑体系）
> **评审方式**：逐页代码走查 + 本地实跑走查（2026-09-26）
> **优先级口径**：`P0` = 直接阻断转化或造成信任/合规损失，应尽快修；`P1` = 明显影响体验或增长；`P2` = 优化项

---

## 摘要

产品**骨架是完整的**：注册登录、权限控制、学习进度云端同步、个人中心、管理后台都跑通了，工程质量也在水准之上（鉴权在服务端逐次校验、写接口有 Origin 校验、密码用 Argon2id）。

但**从「流量 → 信任 → 付费 → 交付」这条链路上，有 4 个明显断点**，而且其中 3 个会直接损失收入：

| 编号 | 问题 | 优先级 |
|---|---|---|
| R-05 | 课程介绍页（Stage）**没有任何购买入口**，想买的人在这一页无路可走 | P0 |
| R-06 | 未购买状态显示为「**暂未解锁**」+ 锁图标，用户以为"学完自动开"，不会去付费 | P0 |
| R-08 | 阶段页承诺「**通过阶段测验（80 分及以上）**」「**参与课程讨论**」——这两个功能根本不存在 | P0 |
| R-07 | 收集手机号并收费，却没有**隐私政策 / 用户协议** | P0 |

**如果只做三件事**，按这个顺序：修 R-06 文案 → 补 R-05 入口 → 兑现或删掉 R-08 的承诺。

## 一、产品定位与目标用户

### R-01 定位表述三个版本互相打架

**现状问题**
同一件事在不同位置说法不同，受众画像不一致：

| 位置 | 表述 |
|---|---|
| 首页 Hero | 「面向**开发者**的 AI 原生学习平台」 |
| 页脚 / `index.html` description | 「面向**大学生和初级开发者**」 |
| `/path` 副标题 | 「一条结构化的 AI 原生开发者成长路径」 |

「开发者」暗示有基础，而「大学生 / 初级」暗示可能零基础。**这两个受众对内容深度、文案语气、定价锚点的预期完全不同**，现在等于同时对两拨人说话。

**为什么要改**
定位是所有下游决策的前提（讲什么、怎么说、卖多少钱）。定位模糊会同时降低两拨人的匹配感——有基础的人嫌浅，零基础的人觉得门槛高。

**优先级**：P1

**建议**
统一为一句话，并明确"前置于什么基础"。推荐：**「面向零基础大学生与初级开发者的 AI 原生开发成长平台」**，然后在首页 Hero 下方加一行「需要什么基础：会基本的电脑操作即可；不需要编程经验」——这行字对抖音来的流量价值极高。

---

### R-02 没有「我需要什么基础」的明示

**现状问题**
`/stage/:slug` 页有「进入前 / 学完后」的 `enterState` / `exitState`，信息是对的；但**首页、学习路径页、注册页都没有**。用户从抖音进来，第一眼无法判断"这适不适合我"。

**为什么要改**
零基础用户的最大疑问不是"这课好不好"，而是"我能不能学"。这个疑问不解决，后面所有说服都是空的。

**优先级**：P1

**建议**
首页 Hero 下加一行基础要求；注册页在表单上方加一句「无需编程基础，从第一节课开始带你做出可运行的项目」。

---

### R-03 完全没有信任背书

**现状问题**
全站找不到：讲师/作者是谁、有多少人学过、学员做出了什么、任何第三方评价。首页的"数据条"只有「4 个学习阶段 / 4 个阶段项目 / 22 节任务课程」——这些是**产品规格**，不是信任证据。

**为什么要改**
陌生流量付费的第一障碍是"你是不是骗子"。你现在唯一的信任来源是**微信里你本人的可信度**，而落地页完全没有承接这一点。对一个卖 ¥99–599 的课程，这是转化率低的关键原因之一。

**优先级**：P1

**建议**
按你手上真实有的材料，从易到难补：
1. **作者署名**（最易）：首页或页脚加「由谁做的」——你的实习经历、南邮身份、做过的项目。你在抖音已经用它建立信任，落地页要承接。
2. **作品集**：把你自己做过的东西（Vibe Coding Lab、这个站本身、实习项目）做成"我就是这么学出来的"证据链。
3. **学员成果**：有真实案例之前**不要编**，宁缺毋滥。可以用「已服务 N 位学员」这种可核实的表述起步。

---

### R-04 缺少品牌信息与合规页面

**现状问题**
页脚「关于」栏现在只有三个链接；没有**关于我们**、**服务条款**、**隐私政策**、**退款政策**。而这些页面在收费产品里是标配。

**为什么要改**
见 R-07（合规风险）。另外，没有"关于我们"意味着用户不知道在跟谁交易。

**优先级**：P1（隐私政策部分见 R-07，属 P0）

**建议**
新建三个静态页：`/about`（关于与作者）、`/terms`（服务条款）、`/privacy`（隐私政策），全部挂到页脚「关于」栏。条款内容可以简短，但必须存在且可从任何页面到达。

## 二、核心功能与用户流程

### R-05 【P0】课程介绍页没有购买入口，转化链在这里断掉

**现状问题**
`src/pages/StagePage.tsx` 中没有任何购买相关代码（import、按钮、弹窗全都没有）。而这一页是"看完课程介绍 → 决定买不买"的**天然落点**：首页 4 张阶段卡、学习路径 4 张阶段卡、课程目录的阶段标题，全都指向这里。

用户路径现在是：看到课程 → 进阶段页 → 看完介绍 → **没有购买按钮** → 只能自己想起来去点顶部"价格" → 再找一次。

**为什么要改**
这是纯粹的、可量化的收入流失。用户产生购买冲动的那一刻在阶段页，而你在那一刻没有任何承接。

**优先级**：**P0**

**建议**
在 Stage 页补两处，成本很低（`PurchaseModal` 已经是现成的、支持传 plan）：
1. **右侧栏常驻一张"开通本阶段"卡片**：价格 + 「立即开通」按钮，点开 `PurchaseModal`。已开通的用户则显示「继续学习」。
2. **课程列表底部再放一次**：「学完这个阶段能拿到什么」+ 开通按钮。

注意已开通用户要隐藏/替换为"继续学习"，避免看到已付费内容还在被推销。

---

### R-06 【P0】「暂未解锁」把付费门槛伪装成了进度门槛

**现状问题**
`locked` 状态的真正含义是**这个阶段没有购买权限**（`src/data/progress.tsx`：`const access = user?.entitlements.includes(stage.slug) ?? false`），但 UI 全程把它表达为"还没解锁"：

| 位置 | 文案 |
|---|---|
| `LearningPath.tsx:203` | `暂未解锁`（禁用按钮） |
| 各页锁图标 | 🔒 锁 |
| `StagePage.tsx:311` | `查看课程详情` |

「解锁」在用户认知里 = **学完前面的自动开**。用户会一直等一个永远不会到来的解锁，而不是去付费。

**为什么要改**
直接把"需要付费"这个信息藏起来了。这是转化率问题里最隐蔽也最致命的一条——用户不是不买，是**根本不知道要买**。

**优先级**：**P0**

**建议**
1. 全局把"未解锁"改成**"未开通"**，锁图标换成"需开通"或价格标签。
2. 未开通的阶段卡上直接显示**价格 + 「开通」按钮**，点击开 `PurchaseModal`。
3. `StagePage` 的「查看课程详情」按钮（指向需要权限的 lesson 页）会撞到权限墙，应改为「查看课程介绍」（留在本页）或直接改成开通入口。

---

### R-07 【P0】收集手机号并收费，但没有隐私政策与用户协议

**现状问题**
- `index.html`、页脚、注册页均无隐私政策入口。
- 注册页收集手机号，仅有一句「手机号用于登录，请妥善保管密码」。
- 注册流程没有协议勾选。

**为什么要改**
依据《个人信息保护法》，收集手机号属于处理个人信息，需**告知处理规则**并取得同意。收费产品没有用户协议，在发生纠纷时你没有任何约定的抓手。这是法律风险，不修等于裸奔。

**优先级**：**P0**

**建议**
1. 新建 `/privacy` 与 `/terms` 两个页面，内容不必长，但要说清：收集什么（手机号）、做什么用（登录与开课核验）、存多久、如何删除、联系谁。
2. 注册表单下方加勾选框：「我已阅读并同意《用户协议》与《隐私政策》」，未勾选禁用提交。
3. 页脚「关于」栏加入口。

---

### R-08 【P0】阶段页承诺了两个并不存在的功能

**现状问题**
`src/pages/StagePage.tsx:321-325` 的「完成本阶段要求」写死了四条：

```
完成 N 节课的学习           ← 唯一真实可算的
完成阶段项目并提交           ← 没有提交入口
通过阶段测验（80 分及以上）   ← 全站没有测验功能
参与课程讨论（可选）         ← 全站没有讨论功能
```

而且后三条的 `done` 全部硬编码为 `false`，永远不会变。

**为什么要改**
**虚假承诺比没有承诺更伤信任。** 用户会认真去找"测验在哪""怎么提交项目"，找不到之后的失望会直接转化为退款诉求或差评——对靠口碑和私域复购的小体量业务，代价很高。

**优先级**：**P0**（改动成本极低，收益/风险比最高）

**建议**
二选一，不要留着：
- **删**：只保留"完成 N 节课"这一条真实的，其余全部移除。
- **给**：如果测验和提交是你想做的功能，那就排进计划，在功能上线前不要先行承诺。

短期建议直接删，替换成一句真实的、可验证的话，例如「完成全部 N 节课后，你会拥有一个可展示的阶段项目」。

### R-09 忘记密码 = 账号作废

**现状问题**
`/account` 能改密码，但**没有任何找回入口**。密码 8–72 字符，忘了之后：没有邮箱、没有短信验证码、手机号又不验证，用户唯一的办法是找你人工重置。

**为什么要改**
用户流失在这里是**不可逆的**。而且每次都要你人工介入，等于给未来的自己埋维护成本。

**优先级**：P1

**建议**
按投入从小到大：
1. **短期**：登录页加一行「忘记密码？请联系管理员」，把微信二维码挂上去。虽然原始，但比现在的"什么都没有"好得多。
2. **中期**：接一个短信服务做验证码重置（也是 R-10 的前提）。

---

### R-10 手机号不验证，且注册时没提醒——会打断你的开课流程

**现状问题**
README 明确「手机号仅作为登录账号，当前不验证归属」。而你的开课流程是：**学生把手机号告诉管理员 → 管理员搜手机号开通**。

如果学生注册时把手机号打错一位（很常见），或者报给你的是另一个号，后台就**搜不到这个人**——钱收了，课开不了。而学生自己不知道填错了，因为系统从不校验、也不让他确认。

**为什么要改**
这条不是"体验问题"，是**直接卡住你的运营闭环**。用户越多越明显。

**优先级**：P1

**建议**
1. **最省事**：注册成功后，在结果页/个人中心显著显示「你的注册手机号：139\*\*\*\*0003，请确认无误——管理员将据此为你开通课程」（个人中心已有脱敏号码，把它前置到注册成功提示即可）。
2. 注册表单手机号输入做实时校验（11 位、`1[3-9]` 开头），格式不对立即提示，别等提交。
3. 有条件后接入短信验证。

---

### R-11 付款后没有任何状态可见

**现状问题**
用户在 `PurchaseModal` 点「我已完成付款」后，只出现一句静态文字（`PurchaseModal.tsx`：`setMessage('请联系管理员确认…')`），**不产生任何记录**，页面上也无处查看"我付了、在等开通"。

**为什么要改**
付款后到开通之间的空窗期，是用户最焦虑、最容易产生"我是不是被骗了"的时刻。没有任何状态反馈会放大这种焦虑。

**优先级**：P1

**建议**
1. 短期：付款弹窗里给出**明确预期**——「管理员通常会在 X 小时内为你开通，可用下方微信催一下」。
2. 中期：个人中心的「我的课程」里加一个「待开通」状态区（哪怕只是前端本地记录"我点过已完成付款"也能缓解）。

---

### R-12 管理员侧全靠人工，没有通知

**现状问题**
学生在微信付款 → 管理员需要自己想起来去 `/admin/users` 搜手机号开通。**没有任何提醒**。用户少时靠记性，用户多了一定会漏。

**优先级**：P2（当前规模能撑，但要知道这是天花板所在）

**建议**
加一个最轻的通知：管理员登录后，`/admin/users` 顶部显示「有 N 位用户尚未开通任何课程」的待办提示（把"注册了但没权限"的人筛出来即可），不用做推送系统。

## 三、信息架构与导航

### R-13 「学习路径」「课程」「我的学习」三个入口语义重叠

**现状问题**
主导航五项：我的学习 / 学习路径 / 课程 / 项目 / 价格。其中前三个的关系非常模糊，用户无法预判点进去会看到什么：
- **我的学习**（`/dashboard`）：继续学习卡 + 四阶段进度 + 总体进度环 + 阶段作品
- **学习路径**（`/path`）：进度概览 + 四阶段时间轴 + 四阶段卡片 + 学习方式 + 4 个项目
- **课程目录**（`/courses`）：总体进度 + 四阶段 + 每节课列表

**三页都在展示「总体进度 + 四个阶段」**，用户点哪个都能看到类似的东西，于是记不住哪个是哪个。

**为什么要改**
导航认知负担直接影响"用户能不能找到下一步"。现在三个入口互相稀释，等于没有主推路径。

**优先级**：P1

**建议**
明确三者分工，并在命名上体现：
- **我的学习**：只放"现在该干什么"——继续学习 + 待办，不做全局目录。
- **课程**（建议改名**「课程目录」**）：唯一的内容清单入口，看课找课都在这。
- **学习路径**：只讲"整体是什么样的"（4 阶段全景 + 学习方式 + 每个阶段产出），**不放个人进度**——进度归"我的学习"。

判断标准：**任意一页的用户问题应该是唯一的**（我现在该做什么 / 有哪些内容 / 这条路长什么样）。

---

### R-14 未登录用户与已付费用户看到的是同一套页面

**现状问题**
首页、路径页、课程目录页对"游客/已购用户"的呈现几乎一致：都展示进度条（游客恒为 0%）、都展示锁、都展示价格。

**为什么要改**
- 对**游客**：0% 的进度条毫无意义，"我的学习"这类入口也无意义，反而暗示"你已经有进度了"。
- 对**已购用户**：还在被推销已购买的阶段。

**优先级**：P1

**建议**
按登录态与购买态做三套呈现：**游客**（强调价值与基础要求，CTA 是"免费试看/注册"）→ **已注册未购**（强调路径与价格，CTA 是"开通"）→ **已购**（强调进度与下一步，CTA 是"继续学习"）。

---

### R-15 课程页硬编码了错误的课程名

**现状问题**
`src/pages/LessonPage.tsx:37-38`：

```ts
const COURSE_TITLE = 'AI 全栈开发实战'
const COURSE_DESC  = '从 0 到 1 构建一个真实可用的 AI 应用…'
```

这两个常量用在左侧目录卡的标题、以及每节课的面包屑上。**无论你打开哪个阶段的哪节课，左上角都写着"AI 全栈开发实战"。** 用户在第 1 阶段看到这个会直接困惑。

**为什么要改**
这是最容易被用户发现、也最损伤"精细度"观感的那类错误。同时它也违反了项目自己的约定（数据单一来源，页面不硬编码）。

**优先级**：P1（修复成本极低，一行的事）

**建议**
删掉这两个常量，改为从当前 `stage` 派生（`stage.title` / `stage.desc`），面包屑同理。

### R-16 没有全站搜索

**现状问题**
22 节课 + 4 个项目，无搜索。用户想找回"上次看到讲向量数据库的那节"只能逐页翻。

**优先级**：P2（内容量还小，可以缓）

**建议**
等内容扩到 40 节以上再做。届时在课程目录页加一个纯前端标题/描述过滤即可，不必上后端搜索。

### R-17 404 页文案像是系统坏了

**现状问题**
`src/App.tsx` 的 `NotFound` 写：「**这个页面还没有搭好**」，并且正文罗列了"平台目前已完成…页面列表"——这是**开发视角的文案**，不是给用户看的。

**优先级**：P2

**建议**
改成用户视角：「没有找到这个页面」+ 两个出口（回首页 / 去课程目录）。

## 四、交互与视觉体验

### R-18 同一节课程里有两套清单，一套能点一套不能点

**现状问题**
`LessonPage.tsx` 里有两处"清单"：
- **正文区「动手检查」**（第 294–304 行）：纯静态 `span` 方框，**点不动**。
- **右侧工作台「学习任务清单」**（第 440 行起）：可勾选、写数据库，勾满才能标记完成。

两处内容语义高度接近（都是"做完确认这些"），但只有一处能交互。

**为什么要改**
用户会先看到正文里那套，点不动之后产生"这站是坏的"的判断，甚至错以为功能没做完。这是典型的**自造困惑**。

**优先级**：P1

**建议**
二选一：
- 把正文的「动手检查」删掉，统一到右侧工作台（推荐，改动小）；
- 或把正文那套也接上同一份 `checkKeys` 状态，两处双向同步（成本更高，但能让用户在读完正文时立刻打勾，体验更顺）。

---

### R-19 「卡住了？」给的是站内锚点，而不是人

**现状问题**
学习页右侧「卡住了？获取帮助」的两个入口，分别是跳到本页的「排查建议」和「参考提示词」锚点——**都是用户已经看过的内容**。而用户真正卡住时，最需要的是**问人**。

**为什么要改**
你的产品承诺"陪跑、能问到人"，而这恰恰是相对免费教程的最大卖点。现在这个卖点在用户最需要它的时刻缺席了。

**优先级**：P1

**建议**
在这张卡片里加第三个入口：**「微信问管理员」**，点击弹出二维码（`PurchaseModal` 的咨询模式可以直接复用）。这一条对复购和口碑的价值可能超过很多功能。

---

### R-20 学习页的原生锚点与全局滚动逻辑可能打架

**现状问题**
`LessonPage.tsx` 用的是原生 `<a href="#lesson-help">` / `<a href="#lesson-prompt">`。而项目在 `Layout.tsx` 里有一套基于路由 `location.hash` 的统一滚动逻辑（为页脚锚点新增的）。原生锚点会改变 URL hash → 触发那套逻辑 → 可能出现**滚动两次或落点偏移**。

**为什么要改**
属于改动引入的潜在回归，不验证的话可能在长页面（课程正文很长）上表现为"点了跳到奇怪的位置"。

**优先级**：P1（需先验证是否真的发生）

**建议**
先实际点一次确认；如果确实冲突，把这几个锚点改成统一的滚动入口（或让全局逻辑识别"同页 hash 已由浏览器处理"时跳过）。

---

### R-21 表单校验反馈来得太晚

**现状问题**
注册/登录页手机号是纯文本框，无实时校验；密码规则只在下方写「8～72 个字符」，提交后才知道不合法。`AuthPage.tsx` 里没有任何输入时的校验逻辑。

**为什么要改**
注册是漏斗最窄的一环，每一次"提交失败重填"都在流失用户。

**优先级**：P2

**建议**
加输入时/失焦时校验：手机号 11 位且 `1[3-9]` 开头、密码长度、两次密码一致。错误信息就近显示在字段下方。

---

### R-22 加载与空状态是裸文本

**现状问题**
多处使用 `<p role="status">正在加载课程价格…</p>` 这类纯文字占位（首页、价格页、个人中心等），没有骨架屏或视觉过渡。

**优先级**：P2

**建议**
至少给主要区块加骨架屏（灰色的卡片轮廓）。首屏更重要的是**先渲染结构再填数据**，避免"整页空白 → 突然全部出现"的跳动。

---

### R-23 缺少全局操作反馈

**现状问题**
保存、复制、提交等操作的成功反馈都靠局部的文字或图标变化，没有统一的提示机制（toast）。

**优先级**：P2

**建议**
引入一个轻量的 toast（自己写 30 行即可，不必引库），统一承载成功/失败提示。

---

## 五、内容呈现与学习闭环

### R-24 产品承诺的「交付」环节在全站没有落点

**现状问题**
产品自己讲的学习方式是五步：**任务 → Prompt → 构建 → 检查 → 交付**（`data/site.ts` 的 `homePathSteps`，首页和学习路径页都在展示）。前四步在产品里都有对应载体，唯独**第五步「交付」没有任何功能承接**：
- 阶段项目的任务清单 `done` 全是 `false`，不可操作；
- 没有任何地方能让用户提交作品、拿到反馈、沉淀作品集。

**为什么要改**
这是**产品最核心的差异化承诺**（"学完能拿出作品去面试"）与**实际功能**之间最大的缺口。你的用户买课的真实目的不是学知识，是**拿到能写进简历的东西**。没有交付环节，"包就业/能写进简历"的隐含承诺就落不了地。

**优先级**：P1（价值最高的一条功能建议）

**建议**
按投入递增：
1. **最轻**：项目页加一个「我的交付」区块，让用户填**项目链接 / GitHub 地址 / 演示视频链接**，存起来即可。哪怕不做审核，能保存就已经形成"作品集"。
2. **下一步**：个人中心加「我的作品集」区，把 4 个阶段项目的交付物汇总成一页，**可分享**（一个链接发给面试官）。这一个页面就能成为最有说服力的营销素材。
3. **进阶**：交付后可以申请人工点评（正好接上你的私聊模式）。

---

### R-25 阶段项目的任务清单不可交互

**现状问题**
`data/site.ts` 里每个项目有 `tasks: ProjectTask[]`，全部 `done: false`，且项目页没有让用户勾选的能力。这些任务卡看起来像清单，实则纯展示。

**优先级**：P1

**建议**
复用已有的 `/progress` 任务勾选机制（课程正文已经跑通了同一套模式），把项目任务也接进去。用户已经习惯了这个交互，改造成本低。

---

### R-26 完成一课后没有正反馈与下一步引导

**现状问题**
标记完成后，界面只是按钮变成「已完成本课」并出现「进入下一课」。没有阶段性反馈、没有阶段完成庆祝、没有"你已完成 X%"的鼓励。

**为什么要改**
学习类产品最大的敌人是中途放弃。**正反馈是留存的主要手段**，而目前产品在这一环几乎为零。

**优先级**：P1

**建议**
分层加：
1. 每课完成：一句确定的反馈 + 下一步按钮（已有，可强化文案）。
2. **阶段完成**：一个明确的庆祝态（这一阶段 4 节课 + 项目已完成）+ 「查看你的阶段作品」+ 「进入下一阶段」。
3. 全部完成：一张可分享的完成凭证。

---

### R-27 学习数据没有出口

**现状问题**
用户学了多久、完成了什么、做过哪些项目，数据都在系统里，但**用户拿不走**——没有学习报告、没有可分享的进度、没有导出。

**为什么要改**
这些数据是你的用户拿去求职的**弹药**。让别人看到"我在学什么、学到了哪"，既是用户价值，也是你的免费传播。

**优先级**：P2

**建议**
个人中心加「生成学习报告」（一页可分享的图或链接）。

---

### R-28 封面/分享无预览卡片

**现状问题**
`index.html` 只有 `description`，**没有 `og:title` / `og:image` / `og:description` / `twitter:card`**。用户在微信里分享链接时，是一条没有任何预览的白链接。

**为什么要改**
你的主战场是**微信私域**——分享出去的链接长什么样，直接影响点击率。这是零成本的传播优化。

**优先级**：P1（改动极小，收益直接）

**建议**
在 `index.html` 补齐 og 系列标签，配一张 1200×630 的品牌图（`public/brand-board.png` 可以直接裁）。

---

### R-29 课程时长等元信息两处来源可能不一致

**现状问题**
课程的「预计学习时间 / 难度」来自服务端正文（`content.estimatedTime`、`content.difficulty`），而阶段页的「预计总时长」来自前端静态数据（`stage.totalDuration`）。两者没有关联校验，改了一处另一处不会跟着变。

**优先级**：P2

**建议**
要么让阶段总时长由课时时长求和派生，要么在内容检查脚本（已有 `npm run check:content`）里加一条一致性校验。

## 六、支撑体系（不在你列的五个维度内，但影响全部）

### R-30 【高】没有数据埋点，等于蒙眼开车

**现状问题**
全站**没有任何统计代码**（grep `gtag|analytics|posthog|umami` 无结果）。你不知道：
- 首页 → 注册 → 开通，每一步的转化率是多少
- 用户在哪个页面跳出
- 抖音来的流量在落地页停留多久

**为什么要改**
你的自述是"转化率偏低"。**没有埋点，"偏低"就只是一个感觉，你无法知道卡在哪一步、也无法验证任何一次改动是否有效。** 现在所有的优化都只能靠猜。这是我认为**最该优先补的基础设施**。

**优先级**：P1（重要性接近 P0，只是不阻断当前流程）

**建议**
1. 接一个轻量、隐私友好的方案（Umami 自托管 / 百度统计 / 或自己写一个极简的打点接口存进现有数据库）。
2. **只埋 5 个关键事件**就够用：访问首页、点击开通/咨询、打开付款弹窗、注册成功、进入某阶段课程。
3. 每周看一眼漏斗，再决定优化什么。

---

### R-31 没有版本管理，多人/多会话并行改动有覆盖风险

**现状问题**
项目**不是 Git 仓库**（README 明确说明）。而实际工作中已经出现"同一批文件在短时间内被不同来源改动"的情况（例如 2026-09-26 14:32–14:58 期间 `Layout.tsx`、`AccountPage.tsx` 等被另一来源重构，与正在进行的改动并行）。没有 Git 就无法对比、无法回滚、无法确认"到底谁改了什么"。

**为什么要改**
一次误覆盖就可能丢掉一整轮工作，且**无法恢复**。这是纯粹的工程风险，与产品无关，但会伤害所有产品工作。

**优先级**：P1

**建议**
立即 `git init` 并做首次提交（`.gitignore` 排除 `node_modules`、`dist`、`.env`）。之后每个改动一个 commit。这是投入产出比最高的一件事。

---

### R-32 前端零测试覆盖

**现状问题**
`tests/` 下的测试是后端集成测试（真实数据库 + Supertest），**前端交互没有任何自动化测试**。今天已经出现多次"改动后需要人工开无头浏览器验证"的情况。

**优先级**：P2

**建议**
不必上完整测试框架，先把**关键路径的手动检查清单固化成脚本**（登录 → 进课程 → 勾任务 → 标记完成 → 刷新后进度还在）。这类"冒烟脚本"能挡住大部分回归。
