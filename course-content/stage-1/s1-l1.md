## 先认识一下你手上的这个项目

你用过聊天 AI，可能习惯了让它给出一段答案。这次 WorkBuddy 已经打开本地项目，有了读写这个文件夹的权限，就能找到文件并把修改保存进去。

浏览器负责展示运行结果；你负责说清要改哪里，并亲眼确认。按下面顺序完成提示词 1、读它下面的解释，再做提示词 2。

```text
aifoundry-stage1-starter/
├─ app/
│  ├─ page.tsx
│  ├─ layout.tsx
│  └─ globals.css
├─ components/
│  ├─ ResourceCard.tsx
│  └─ icons.tsx
├─ lib/
│  └─ resources.ts
└─ package.json
```

<!-- 配图建议：真实目录截图，标出本次入口 app/page.tsx -->

### app/

aifoundry-stage1-starter 是项目文件夹。`app/` 是查找页面的起点；`app/page.tsx` 组织当前首页，中央标题就在里面。

`app/layout.tsx` 放页面共用的外框，也设置浏览器标签页标题。今天改的是页面里的大标题，标签页名字先保持原样。

### components/ 和 lib/

`components/` 放可重复使用的页面小块，这些小块叫组件。`ResourceCard.tsx` 负责一张资料卡片，`icons.tsx` 提供图标；`lib/` 放数据和辅助代码，这里的 `resources.ts` 保存了 9 条示例资料及标签。

看见卡片内容，可以顺着这里去找。

### package.json

它与 app、components、lib 位于同一层，记录项目需要的代码包和启动命令。这张地图不用背；现在只要能在文件列表找到 `app/page.tsx`，知道 AI 会在这些真实文件里改东西，就可以动手。

## 页面变了，刚才到底发生了什么？

第 8～11 分钟，停一下看刚才发生了什么：你发出需求 → WorkBuddy 读取项目、找到 `app/page.tsx` 并保存改动 → 正在运行的 Next.js 检测变化、更新页面 → 浏览器显示新内容。Next.js 是组织并运行这个网页项目的框架；React 帮它描述界面，TypeScript 帮代码表达和检查数据类型。

你现在只需把这条关系对应起来。

```text
你的需求
   ↓
WorkBuddy 读取并修改 app/page.tsx
   ↓
Next.js 检测到保存后的变化
   ↓
浏览器显示新的页面
```

![需求经 AI 修改项目文件，由 Next.js 更新浏览器页面](/course-media/stage-1/s1-1-01.webp "页面变化来自实际项目文件的修改")

### 找到刚改过的页面文件

让 WorkBuddy 打开或展示 `app/page.tsx` 中刚改过的几行，亲自找到新标题。`.tsx` 文件允许把页面结构和 JavaScript/TypeScript 逻辑写在一起，不是双击就能运行的普通 HTML 文件。

你会看到像 `<h1>我的学习资料库</h1>` 这样的写法（实际代码还带样式、换行），其中类似 HTML 的部分叫 JSX，用来描述页面应该出现什么；h1 在这里标出大标题。不要求手写语法，现在能指出「这一段文字对应刚才的大标题」就够了。

## 第二次修改：换一个颜色

读完「刚才发生了什么」再执行提示词 2；核对方块颜色，并确认第一次修改仍保留。

第 11～15 分钟：再改一个看得见的细节。这个项目用 Tailwind CSS 的类名控制很多颜色、间距和字号，类名写在 `className` 中；`bg-emerald-600` 表示一种绿色背景。

你不必背类名，告诉 AI 想要什么颜色就行。下面以蓝色为例，可以换成自己喜欢的颜色。

:::prompt{title="只改「知」字方块的背景"}

```text
保留刚才改好的标题和介绍。
请只把 app/page.tsx 中顶栏左侧、包着「知」字的方块背景从绿色改为蓝色。
保留白色的「知」字、大小和圆角；不要改标签按钮、搜索框或资料卡片的颜色，也不要改其他内容。
直接修改并保存文件，完成后告诉我具体改了哪个文件、哪个背景类名。
```

:::

回浏览器刷新，检查「知」字方块是否变蓝，中央的新标题和介绍是否仍在。蓝色示例通常对应 `bg-blue-600`；默认选中的「全部」标签也用了绿色背景，它应继续保持绿色。

让 WorkBuddy 展示改动所在的那一行，核对改的是包着「知」字的元素。这能说明为什么「把所有绿色都换掉」与本次需求不同。

:::stuck{title="哪里和预期不同？"}

### 页面没变

先刷新，再核对浏览器地址是否与当前终端的 Local 一致；让 WorkBuddy 报出刚改文件的完整路径，确认它与运行服务的 aifoundry-stage1-starter 相同，还要确认它保存了文件，而不只是回复代码。

### 变的是顶栏或浏览器标签页

指出「我要改搜索框上方的中央大标题」，让 AI 只修正这处并恢复本轮误改的文字，保留已正确完成的修改。

### 页面出现报错

先看运行 `npm run dev` 的终端，把错误文字、刚做的修改和预期页面一起发给 WorkBuddy，请它先定位本轮问题再修复；修好后重做同一个检查。

### 方块变蓝了，其他绿色也变了

指出标签或卡片的具体位置，让 AI 只保留「知」字方块的背景变化。

### 文件列表找不到 app/page.tsx

检查打开的是 `aifoundry-stage1-starter`，再让 WorkBuddy 展示文件的完整路径与相关片段；不要要求它另建一个同名页面。

:::

:::deepdive{title="为什么没改图片，方块也能换色？"}

「知」字方块在 `app/page.tsx` 里是一个带文字的页面元素，背景颜色来自 `className` 中的类名。项目的 `tailwind.config.ts` 会让 Tailwind 检查 app 和 components 下的相关文件，`app/globals.css` 引入样式。

改背景类名后，开发工具生成相应样式，浏览器就能画出新颜色。页面外观也可能受全局样式影响，并非所有样式都只来自一个类名；本次只需修改方块自己的背景。

:::
