在开始之前，先知道我们要做什么。接下来你会拿到一个已经写好起点页面的项目，把它放到电脑里，再启动它。

这份起点项目叫 Starter，名字是「个人知识工作台」。今天先让它显示出来，1.1 再让 AI 修改它。

第 0 课是准备课，不计入 29 节正式课程和学习完成率。

这一课做完，你能：

- 找到真正的项目文件夹，知道代码放在哪里
- 能在终端检查工具、安装依赖并启动项目
- 浏览器中看到标题、搜索框、标签和 9 张资料卡片

## 开始之前，先知道我们要做什么

浏览器里看到的标题、按钮和卡片，都来自项目里的代码文件。我们要走的路线是：项目文件夹 → 里面的代码 → Node.js 帮忙启动项目 → 项目在这台电脑上运行 → 浏览器通过 localhost 打开页面。

先看清下面的关系，然后边操作边认识用到的工具；不需要先学会编程。

```text
项目文件夹 → 里面的代码
                 ↓
          Node.js 启动项目
                 ↓
        本机的开发服务器
                 ↓
     浏览器通过 localhost 打开
```

### 项目和文件夹

一个软件项目可以先理解成放在一起的一组文件。文件夹负责收纳它们，里面有页面代码、资料数据和配置。

Starter 就是课程准备好的这一组文件。

### 代码和页面

代码是写在文件里的指令和描述，用来决定软件显示什么、怎么响应操作。浏览器展示运行后的页面；以后让 AI 改标题，改的是项目里的文件。

## 安装 Node.js，打开终端

这个项目需要 Node.js 帮忙在电脑上启动开发环境，不能靠双击页面文件完整运行。今天装好并确认它能用就够了，Stage 1 不要求你学习 Node.js 编程。

装好 Node.js。浏览器打开 [https://nodejs.org/en/download](https://nodejs.org/en/download)，选择适合自己系统、标有 LTS（长期支持）的安装包。

Windows 使用安装程序并保留 npm 选项，macOS 使用对应安装包。装完后再打开终端。

Starter 的最低要求是 Node.js 18.18，但新安装请选官网当前的 LTS，不要照着旧版本号找安装包。

### 终端是在干嘛？

先搞懂：终端是在干嘛？它是用文字命令让电脑执行操作的窗口，平时点按钮的动作在这里换成输入文字。Windows 可以从开始菜单搜索并打开 PowerShell，或在 Windows Terminal 中打开 PowerShell；macOS 在应用程序的「实用工具」中打开「终端」。

下文命令都输入这个窗口，一次一条，按 Enter 执行，不要写进代码文件、浏览器地址栏或 AI 对话框。

### 检查 Node.js 和 npm

在终端输入 `node -v`，按 Enter；看到版本号后，再输入 `npm -v`。两条都应返回各自的版本号，它们不必一样。

npm 随 Node.js 一起安装，这一课用它准备项目需要的东西、启动项目。命令前屏幕上已有的 PS、路径或 > 是终端提示，不用跟着输入。

```bash
node -v
npm -v
```

## 把 Starter 放到电脑里

### 准备 WorkBuddy

准备 WorkBuddy。浏览器打开 [https://www.workbuddy.cn](https://www.workbuddy.cn)，下载适合电脑系统的版本，安装并登录。

它是能读取和修改本地文件的 AI 工具。稍后要把项目文件夹交给它；仅把网页地址发给聊天窗口，还不足以让它找到你的代码。

### 下载并解压

下载并解压 Starter。如果已拿到课程提供的 Stage 1 压缩包，右键选择解压；不要直接在压缩包里操作。

也可以打开 [https://github.com/LazyQ0130/ai-foundry](https://github.com/LazyQ0130/ai-foundry)，在仓库的 Code 菜单选择 Download ZIP，解压后进入 starter，再进入 stage-1。若链接要求访问权限且无法进入，先联系课程提供方取得 Starter，拿到文件后再继续。

### 认准项目根目录

找到项目根目录。「根目录」就是这份项目最外层的文件夹：打开它，能同时看到 app、components、lib 和 `package.json`。

下载整个仓库时，应选里面的 `starter/stage-1`，不要选外层 ai-foundry 文件夹；外层也有 `package.json`，但那是课程网站自己的项目。在 WorkBuddy 中打开这个 stage-1 文件夹，让它回答「请只读取当前项目，告诉我完整文件夹路径和 `package.json` 的 name，不要修改文件」。

正确的 name 是 `personal-knowledge-workbench`。

<!-- 配图建议：解压目录逐层进入 starter/stage-1，圈出 app、components、lib、package.json；与 WorkBuddy 打开的路径并排 -->

### 让终端进入同一个文件夹

让终端也来到同一个文件夹。Windows 在文件资源管理器打开 stage-1，复制地址栏里的完整路径；回到 PowerShell 输入 cd，空一格，把路径放在英文双引号内。

例如 `cd "C:\Users\你的用户名\Downloads\ai-foundry-main\starter\stage-1"`。示例路径必须换成你自己的；cd 的意思是进入这个文件夹。

macOS 同样使用 cd 加带引号的实际路径。Windows 再输入 dir，macOS 输入 ls，确认列出 app、components、lib 和 `package.json`。

WorkBuddy 打开了文件夹，不代表另开的终端也已经进入它。

Windows 路径示例（请换成自己的实际路径）：

```powershell
cd "C:\Users\你的用户名\Downloads\ai-foundry-main\starter\stage-1"
dir
```

## 安装项目需要的东西

先搞懂：这次要安装什么？做软件会使用别人写好的代码包，叫作依赖；这个项目用到的 Next.js、React 等就属于依赖。`package.json` 记录需要哪些包，`npm install` 负责把它们准备好。

现在在刚才确认过目录的终端输入 `npm install`，按 Enter，等它结束并重新出现可以输入命令的提示位置。它会生成 `node_modules` 文件夹，用来放这些包；暂时不用逐个打开。

```bash
npm install
```

## 把项目第一次跑起来

启动项目。在同一个终端输入 `npm run dev`。

这里的 dev 是 `package.json` 中已经定义好的启动任务，它会运行 Next.js 的开发服务器：一个持续运行、把项目页面提供给浏览器的程序，也方便修改代码后很快查看结果。看到 Ready 和 Local 后，找到 Local 旁边的完整地址；这次终端会一直运行，不会像安装结束那样回到等待输入的位置。

```bash
npm run dev
```

### localhost 和端口

先搞懂：localhost 为什么能打开网页？localhost 指你自己的电脑，地址里的 3000 是区分服务的端口，可以当作这个项目的门牌号。把终端显示的 Local 地址，例如 [http://localhost:3000](http://localhost:3000)，输入浏览器地址栏再按 Enter；这一步输入的是地址，不是终端命令。

如果显示的是 3002，就使用 3002。这不是已发布的公开网站，发给朋友也不会打开你电脑上的项目。

:::task{title="打开页面并试试搜索"}

先别继续下一课，确认页面确实出现。你应看到「个人知识工作台」、绿色「知」字方块、搜索框、标签按钮和 9 张资料卡片。

保持「全部」选中，输入 Excalidraw，应只剩对应卡片；清空搜索词，应回到 9 张。这里页面上的总数显示仍是「共 9 条资料」，今天检查卡片是否变化即可。

### 这个终端先别关

保留运行 `npm run dev` 的终端，可以最小化。它像项目的发动机，关闭它通常也会停掉开发服务器；届时浏览器再次访问或刷新就可能失败。

下次继续学习时，重新打开终端、进入同一个 stage-1 文件夹，再执行 `npm run dev`，并按新显示的 Local 地址打开页面。依赖已装好时通常不用重做 `npm install`。

需要主动停止时，在运行服务的终端按 `Ctrl+C`。

:::check{title="确认可以进入 1.1"}

- `node -v` 和 `npm -v` 分别返回版本号；你知道这两条是终端命令
- 终端和 WorkBuddy 指向同一个 stage-1，`package.json` 的 name 是 `personal-knowledge-workbench`
- `npm install` 结束后返回输入位置；`npm run dev` 显示 Ready 和 Local，并保持运行
- 按实际 Local 地址能打开页面；搜索 Excalidraw 只剩一张卡片，清空恢复 9 张
- 能用自己的话说出：文件在项目里，开发服务器正在运行，浏览器通过本机地址显示页面

:::

:::stuck{title="按看到的现象排查"}

### node 提示无法识别

先关闭旧终端，重新打开后检查 `node -v`；仍失败再检查 Node.js 是否安装完成。

### PowerShell 提示 npm.ps1 无法加载或禁止运行脚本

保持在当前项目目录，把 `npm -v`、`npm install`、`npm run dev` 分别换成 `npm.cmd -v`、`npm.cmd install`、`npm.cmd run dev`，不必为此修改系统脚本策略。

### 找不到 package.json 或安装失败

先用 dir（macOS 用 ls）检查当前目录；目录正确再把执行的命令和完整错误交给 WorkBuddy，要求它先说明原因。网络超时应先查网络；黄色 WARN、漏洞数量提示与安装失败不是一回事，判断是否完成还要看是否有 `npm error` 及能否启动，不要直接运行自动升级修复命令。

### 浏览器无法访问

先看启动终端是否还在、是否出现 Ready，再核对 Local 地址，端口变化就打开新地址；没有 Ready 且有报错时，先处理该错误。

### 页面内容不对或 WorkBuddy 找不到文件

核对两边的完整路径，以及 `package.json` 的 name，确保进入的是解压后的 `starter/stage-1`。

:::

:::deepdive{title="安装和启动，每次都要重做吗？"}

Node.js 是安装在电脑上的工具，通常不必每个项目重装。`npm install` 为当前项目准备依赖，第一次拿到项目或依赖变动后才需要再做；`npm run dev` 则是在本次学习时启动服务。

关闭服务不会删除已经保存的代码。下次从同一个文件夹启动，就能接着改。

:::
