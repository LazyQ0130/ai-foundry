上一节你已经做出了一个真的筛选功能。但真实开发里更麻烦的问题，往往不是“页面打不开”，而是“页面能用，但某种操作组合以后结果不对”。今天我们就故意留一个问题，然后把它修回来。

如果你的项目还没有“只看重要资料”，先完成 1.2，再继续这一节。沿用自己的项目，让 WorkBuddy 或你正在用的 AI Coding 工具打开同一个文件夹，保持 `npm run dev` 运行，浏览器打开终端显示的 Local 地址。

你的控件可能是复选框，也可能是按钮。下面说“开启”，就是把它切到只显示重要资料的状态；代码不需要和别人一样。

## 页面能打开，也可能有 Bug

页面能打开，按钮能点，搜索、标签也都能用。但把几个操作放在一起，结果可能就错了。

:::concept{title="Bug 不一定有报错"}

程序能运行，但行为和预期不一样，也可能是 Bug。今天不会故意弄出白屏或红色错误，我们要找的是列表里出现了本不该出现的资料。

:::

## 什么叫“能稳定复现”

:::concept{title="用同样的步骤把问题再做出来"}

如果每次按同样的操作顺序，都能看到同样的问题，这个问题就是可以稳定复现的。先记住这个动作：**把问题再做出来。**

:::

再刷新一次，确认空搜索、全部标签、重要关闭。开启重要筛选，再点工具，看看是不是仍然出现那两条资料。

还会出现，我们就掌握了一条很有用的信息。“这个页面怪怪的”几乎没有信息；“刷新 → 开启重要筛选 → 点击工具 → 错误显示两条工具资料”清楚得多。AI 可以沿着你实际做过的步骤去检查。

如果第二次结果不同，先记录两次的操作和差别，检查有没有残留搜索词或忘记切回全部。不要为了套上示例，告诉 AI 自己看到了并没有出现的结果。

## “坏了，帮我修”为什么信息太少

看看这个请求：

> 筛选坏了，帮我修一下。

AI 知道你怎么把问题做出来的吗？不知道。它得猜是开关没反应、标签失效，还是某种组合出错。所以别只说哪里坏了，还要说清怎么坏的。

用自然中文补四件事就够：

1. **之前是什么状态**：页面刚刷新，搜索为空，当前标签是全部，重要筛选关闭。
2. **我做了什么**：开启「只看重要资料」，再点击「工具」。
3. **我以为会怎样**：应该显示 0 条，因为工具资料都不重要。
4. **实际发生了什么**：仍显示 Excalidraw 和 Raycast。

:::concept{title="预期和实际"}

预期是本来应该发生什么，实际是真正发生了什么。把两者放在一起，别人才知道差在哪里。再补一句“刷新后按同样步骤试了两次，都一样”，就把能否重复出现也说清了。

:::

## AI 找到了什么

读完它的回答，试着说出两句话：问题大概发生在哪？为什么单独都正常，放在一起会出错？

比如：“可能在资料列表的筛选逻辑里。组合使用时，有一道条件没有按预期起作用。”能说到这个程度就够，不需要逐行看懂所有代码。如果解释太绕，让它用你刚才看到的两张卡片来说明。

AI 可能发现几个筛选条件组合错了，也可能找到其他造成同样行为的原因。**它给出的是一个判断，还需要用修复后的结果验证。** 不同工具、不同项目写法，不一定会制造或找到同一种代码错误。

### “同时满足”和“满足一个”不是一回事

如果 AI 提到 `&&` 或 `||`，先这样理解：`&&` 是两边都要满足，`||` 是满足其中一边就行。

我们希望留下“既是工具，又是重要资料”的内容；“是工具，或者是重要资料”会放进不该出现的卡片。但这只是帮助理解的例子，不代表你的 Bug 一定是某个符号写错了。

## 卡住了怎么办

:::stuck{title="按你看到的现象处理"}

### AI 制造的 Bug 和描述不一样

先停在实验准备这一步。把实际卡片、开关状态、标签和操作顺序告诉它：“请调整到单独正常、组合错误的实验状态。刷新后开启重要再点工具，要显示 Excalidraw 和 Raycast，控件仍开启；不要改数据或其他功能，也不要透露原因。”然后重新做 A、B 和组合测试。

### 重要筛选或标签单独也坏了

实验环境还不合格。要求它先恢复“全部标签下重要为 3 条、重要关闭时工具为 2 条”，保留约定的组合故障。其他重要加标签组合受到同一处逻辑错误影响可以接受；不能跳过单独测试，也不能改资料的重要标记来凑数量。

### AI 在实验准备阶段提前透露了 Bug 原因

先不要继续询问原因，仍亲手执行复现步骤、记录实际现象；已经看到的解释不能代替自己的观察。必要时可以让 AI 重新准备实验，但不必为了遮住答案反复制造故障。

### AI 一上来就把 Bug 修了

告诉它：“这一步只想制造实验问题，不要修复。请重新准备前面约定的组合 Bug，单独筛选与搜索保持正常，不要增加独立故障，完成后只说可以开始测试了。”再亲手核对，别凭它的回复往下走。

### 定位时 AI 直接开始改代码

告诉它：“请先撤回本次定位阶段擅自做的修改，保留之前的项目和实验问题；现在只解释原因和要检查的位置。”重新复现后，再读它的判断。

### 修完以后仍然错误

把原来的复现步骤、当前实际结果，以及 AI 刚才的修改说明一起交回给它。要求先重新定位，不要反复发送“还是不行”，也不要扩大到整页重写。

### 组合 Bug 修好了，搜索却坏了

明确说：“保留当前组合筛选修复，只处理搜索被影响的问题。”补上你输入的词、当前标签、重要是否开启，以及预期和实际卡片。处理完再检查原来的组合 Bug 和搜索。

### 浏览器或终端真的出现红色错误

把浏览器错误页或运行 `npm run dev` 的终端中的完整错误一起发给 AI，说明刚才做了什么。错误很长时复制完整的关键错误块，保留开头、文件位置和相关上下文；不要只截最后半句、只说“报错了”，或自己先删一堆代码。先恢复能正常运行，再继续实验。

:::

:::deepdive{title="&& 和 || 为什么会影响筛选结果"}

`A && B`：A 和 B 都满足。`A || B`：A 或 B 至少一个满足。

把 A 当作“是工具”，B 当作“是重要资料”。Excalidraw 满足 A，不满足 B：要求两者都满足时，它不会留下；只要求至少一个时，它会留下。

这个例子只说明两种关系的差别。实际代码也可能把条件分成几步，或在某个分支漏掉判断；要让 AI 根据你的当前文件定位，不能只凭页面现象认定是某个符号。
