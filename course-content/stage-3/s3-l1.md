## 今天，AI 第一次住进你的产品

Stage 1 和 Stage 2 里，WorkBuddy 或 Codex 是你的开发搭档：它帮你写代码，你的知识工作台本身并不会向模型提问。今天的结果不同：你在**同一个已完成的全栈知识工作台**输入一句话，页面向自己的 API 发请求，服务端再调用模型，回答回到页面。先看清这个结果，再动手。

本课只增加一个简短的「AI 试验区」：问题输入、`询问 AI` 按钮、Mock 或真实模型标记、回答、可获得的 token 用量和受控错误。它暂时不保存对话，不读取资料库，也不做流式输出。你原来的标题、排序、筛选、统计、注册登录和资料 CRUD 都要继续存在。

:::concept{title="开发时用 AI，与产品运行时用 AI"}
WorkBuddy 或 Codex 帮你修改源码，参与的是开发过程。本课的模型调用发生在学员产品运行时：登录用户点击按钮，你的服务端带自己的 Key 请求 Provider，再把受控结果送回页面。两者的账号、费用和数据边界不同。
:::

## 你从哪里开始？

### 情况 A：你已经完成 Stage 2

继续自己的知识工作台。优先保留自己的页面、Git 历史和部署成果，先检查登录、Resource CRUD 与用户隔离。

### 情况 B：你没有可用的 Stage 2 完成版

下载 Stage 3 Starter，从这份 Stage 2 完成状态的干净基线开始。它包含三次迁移、登录和资料功能，不含本阶段 AI 功能。使用 Starter 不等于已经学会 Stage 2；它只提供后续课程依赖的工程起点。

## 先看清一条请求经过哪里

```text
Browser → POST /api/ai/answer → Next.js Server → Model Provider
Browser ← JSON answer         ← Next.js Server ← Model Provider
```

![浏览器向 Next.js 服务端提交问题，服务端读取 API Key 调用模型，浏览器只收到整理后的回答](/course-media/stage-3/s3-1-01.svg "API Key 只存在于服务端")

API Key 像服务器调用模型的密码。页面可以让登录用户触发请求，但不能拿到这个密码。服务端从 `process.env` 读取 Key；浏览器只向**自己的** `/api/ai/answer` 发 `{ "input": "..." }`，不会直接带 Key 请求 Provider。模型返回的原始响应也不应整个送到页面，接口只返回 `kind`、`text` 和有值时的 `usage`。

:::warning{title="API Key 只能留在服务端"}
API Key 不能进入浏览器、复制给 AI 的 Prompt、Git、截图或公开日志。只在被 Git 忽略的服务端环境文件配置；提交前检查暂存范围。
:::

## 先用 Mock 做出完整入口

先让 AI 只读检查当前页面、Session 与同源写保护，再让它在原项目内小范围改动。无论你的页面做过哪些调整，保留你自己的布局和功能。服务端最终检查输入为字符串、去掉首尾空格后非空、最多 2000 字符；客户端提示只是辅助。登录用户每分钟最多约五次调用，避免按钮错误或连续点击造成大量付费请求。

:::prompt{title="在现有工作台加入最小 AI 试验区"}

```text
先检查我当前知识工作台的页面、currentSession()、rejectCrossOriginWrite()、unauthorized()、.gitignore 和现有功能，不要覆盖我的标题、排序、筛选、统计或 Resource CRUD。然后在原项目中加入最小 AI 试验区与 POST /api/ai/answer：页面有输入、询问 AI、idle/loading/success/error、Mock/真实模型标记、回答和可获得的 token usage；请求期间禁止重复提交。Route 先检查同源和登录，只接受 JSON 的 input 字符串，trim 后非空且最多 2000 字符；忽略客户端提供的 userId、ownerId、Key、model、baseUrl 或 max_tokens。建立仅供服务端导入的 TypeScript Provider 层，提供 generate()；默认 deterministic Mock，明确返回 kind: mock，绝不冒充真实模型。真实调用限制 max_tokens=256，超时可配但只允许 1000～30000 ms，不自动重试。按登录用户做约 5 次/分钟的简单限流，并说明进程内 Map 只适用于本地/单实例，不是多实例全局计费保护。服务端错误只返回安全短句，不返回 Key、Authorization Header、Provider 原始响应或堆栈。不要安装无关依赖，不实现流式、结构化输出、Embedding、RAG 或对话历史。先在 Mock 模式构建并验证原有功能，报告改动文件和实际结果；不要操作 Git。
```

:::

本地被 Git 忽略的服务端环境文件先设 `AI_PROVIDER_MODE=mock`。Mock 应每次对同一输入返回相同的固定示例，并在页面写出「Mock 模式 · 未调用真实模型」。这一步只证明 **页面 → 自己的 API → 服务端** 通了，不算真实模型验收。

## 用 Mock 验证边界，不花真实 token

登录后输入一个短问题，看到 Mock 标记和固定回答。提交空白问题和超过 2000 字符的问题，应得到输入提示；直接构造 HTTP 请求也应被服务端拒绝。连续发送六次合法 Mock 请求，应能观察到一次 `429`；等一分钟再试。退出登录后，AI Route 应返回 `401`。伪造跨站 Origin 的写请求应返回 `403`。原来的资料列表、CRUD 和用户隔离仍要正常。

:::stuck{title="Mock 没有按预期返回"}

先看浏览器 Network 中自己的 `/api/ai/answer` 状态码，再看是否仍登录。`400` 查输入与 JSON，`401` 查 Session，`403` 查请求 Origin，`429` 等窗口过去再试；不要通过删除认证或同源检查来消除错误。

:::

## 再配置自己的真实 Provider

本课程已在 **阿里云百炼 China (Beijing)** 真实验收 `qwen3.7-flash`。这是本课程当前使用并实际验证过的参考配置，日后可以根据你自己的账号与模型可用性调整。使用你自己的百炼账号、北京地域 Workspace、额度和 API Key；账号注册、实名认证或额度配置耗时不计入本课时间。不要把 Key 发给 AI、贴进聊天、写入课程文档或截图完整值。

在**自己项目**已被 `.gitignore` 排除的本地服务端环境文件配置下面的变量；`AI_CHAT_BASE_URL` 要从自己 Workspace 对应的官方 OpenAI-compatible 接口配置取得，示例占位符不是可用地址。

```text
AI_PROVIDER_MODE=real
AI_CHAT_BASE_URL=<自己北京地域 Workspace 对应的兼容接口 Base URL>
AI_CHAT_API_KEY=<只在本机填写自己的 Key>
AI_CHAT_MODEL=qwen3.7-flash
AI_TIMEOUT_MS=20000
AI_CHAT_DISABLE_THINKING=1
```

`AI_TIMEOUT_MS=20000` 是经过真实模型调用验证的课程默认值；Adapter 只允许 1000～30000 ms。`AI_CHAT_DISABLE_THINKING=1` 仅对已验证的 `qwen3.7-flash` 发送 `enable_thinking:false`，不是所有 Provider 的通用参数。代码固定 `max_tokens:256`，不接受浏览器控制。保存后立即运行 `git status`，确认环境文件未进入待提交列表；如果出现，先修好忽略规则再继续。重启本地服务使配置生效。

## 发出第一次真实问题

登录自己的工作台，输入：`用两句话解释为什么 Git 能帮助我在代码改坏后恢复。` 点击一次「询问 AI」。在 Network 中确认请求发往**自己的** `/api/ai/answer`，HTTP 为 `200`；页面标记「真实模型」，回答非空，有 usage 时显示 total tokens。不要把 Mock 的成功写成真实模型成功。课程参考实现跑通过，不代表你的账号已经完成真实调用；仍要亲自在自己的项目里验证。

:::check{title="真实调用证据"}
- 当前页面仍是同一个 Stage 2 工作台，旧功能可用。
- Network 中的目标是自己的 API，状态为 200，`kind` 为 `real`。
- 回答非空；usage 若 Provider 返回则可见，若没有则不伪造数字。
:::

## 检查 Key 的边界

看浏览器 Network 的请求与响应、客户端页面源码、`git diff` 和 `git status`。它们都不应出现真实 API Key、Authorization Header 或完整 Provider 原始响应。可以搜索变量名 `AI_CHAT_API_KEY`，确认它只在服务端配置读取处使用；**不要复制真实 Key 到搜索框、终端或聊天里做检查**。`NEXT_PUBLIC_` 前缀会把配置带给浏览器，所以绝不能创建 `NEXT_PUBLIC_AI_CHAT_API_KEY`。

## 失败时页面应该说什么

模型不可用时，按钮应结束等待，页面显示简短可理解的错误；401、超时等由服务端映射为受控信息。不能把原始 Provider 错误、堆栈或 Key 原样返回。课程参考实现已检查无效 Key 与超时边界，本课不要求你销毁 Key 或反复花费 token 来制造失败。Mock 中的空输入、限流、未登录和跨站请求，已经能安全验证大部分边界。

进程内 Map 限流是本课的**本地或单实例基础保护**。Serverless 多实例不会共享这份 Map，不能把它称为全局可靠的计费系统。上线前要依据实际部署规模补充共享限流和预算控制；本课只要求理解并验收当前基础保护。
