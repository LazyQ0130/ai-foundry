## 今天，AI 第一次住进你的产品

Stage 1 和 Stage 2 里，AI 开发工具或 Codex 是你的开发搭档：它帮你写代码，你的知识工作台本身并不会向模型提问。今天的结果不同：你在**同一个已完成的全栈知识工作台**输入一句话，页面向自己的 API 发请求，服务端再调用模型，回答回到页面。先看清这个结果，再动手。

本课只增加一个简短的「AI 试验区」：问题输入、`询问 AI` 按钮、Mock 或真实模型标记、回答、可获得的 token 用量和受控错误。它暂时不保存对话，不读取资料库，也不做流式输出。你原来的标题、排序、筛选、统计、注册登录和资料 CRUD 都要继续存在。

:::concept{title="术语预告：结构化、流式、Embedding 与 RAG（3.2～3.5）"}
先完成正文操作，再展开「给 AI 的技术备注」核对实现规格；名称可以照抄，验收不能省。这里只预告：3.2 才把回答拆成固定字段，3.3 才逐段显示回答，3.4 才准备 Embedding（表示文本含义的一组数字），3.5 才用 RAG（先找自己的资料再回答）。现在不用记后几课的配置，也不要提前把这些功能加到本课。
:::

:::concept{title="开发时用 AI，与产品运行时用 AI"}
AI 开发工具或 Codex 帮你修改源码，参与的是开发过程。本课的模型调用发生在学员产品运行时：登录用户点击按钮，你的服务端带自己的 Key 请求 Provider，再把受控结果送回页面。两者的账号、费用和数据边界不同。
:::

## 先看清一条请求经过哪里

这次有两个服务端角色：**你自己的服务端**负责登录、输入检查和保护 Key；**模型服务商（Provider）**收到合格的问题后运行模型。下面的 Browser 是浏览器，Next.js Server 是你自己的服务端，Model Provider 是模型服务商。代码中的 Provider 层则是你项目里专门负责“把请求发给服务商、整理结果”的模块。

```text
Browser → POST /api/ai/answer → Next.js Server → Model Provider
Browser ← JSON answer         ← Next.js Server ← Model Provider
```

![浏览器向 Next.js 服务端提交问题，服务端读取 API Key 调用模型，浏览器只收到整理后的回答](/course-media/stage-3/s3-1-01.webp "API Key 只存在于服务端")

API Key 像服务器调用模型的密码。页面可以让登录用户触发请求，但不能拿到这个密码。服务端从 `process.env` 读取 Key；浏览器只向**自己的** `/api/ai/answer` 发 `{ "input": "..." }`，不会直接带 Key 请求 Provider。模型返回的原始响应也不应整个送到页面，接口只返回 `kind`、`text` 和有值时的 `usage`。

:::warning{title="API Key 只能留在服务端"}
API Key 不能进入浏览器、复制给 AI 的 Prompt、Git、截图或公开日志。只在被 Git 忽略的服务端环境文件配置；提交前检查暂存范围。
:::

## 先用 Mock 做出完整入口

**Mock（模拟实现）**是产品里的固定测试替身。例如输入一个问题，它按预先写好的规则返回示例，让你先检查按钮、请求、等待和错误提示。本课要求它在服务端工作，必须经过自己的 API；页面上写死一段答案不能证明这条路径已通。相同输入得到相同 Mock 结果叫“确定性”，方便重复检查；它不证明真实模型已经回答。

后面会用到的 **Stub（测试替身）**主要帮我们控制某个依赖的回复，例如让本机模型接口故意返回坏 JSON 或超时。两个名称的用法在项目间可能不同；本课程里 Mock 用来稳定演示正常及固定故障路径，Stub 用来控制依赖回复、检查真实处理代码。它们都不能代替最后的真实调用。

先让 AI 只读检查当前页面、Session 与同源写保护，再让它在原项目内小范围改动。无论你的页面做过哪些调整，保留你自己的布局和功能。服务端最终检查输入为字符串、去掉首尾空格后非空、最多 2000 字符；客户端提示只是辅助。登录用户每分钟最多约五次调用，避免按钮错误或连续点击造成大量付费请求。

先补需求，再让 AI 开发。必要约定：从完成的 Stage 2 项目继续。调用必须经过服务端，Session 与同源检查保留；API Key 不能进入浏览器。

:::deepdive{title="给 AI 的技术备注：模型问答的接口与限流"}
接口与字段可照抄给 AI；你仍要检查未登录拒绝、输入边界、限流、Mock 标记和 Key 不进浏览器。

本节固定接口是 POST /api/ai/answer，只接收 input（trim 后 1～2000 字符）；Provider 复用 generate()。每用户约 5 次/分钟，服务端返回受控错误，默认 Mock。
:::

:::concept{title="模型 Token、用量与限流各在数什么？"}
这里的模型 **token** 是模型处理文字时使用的小单位；它与 2.5 的随机登录 Token 同名，但这里用于数文本用量，不是登录凭证。一个 token 不固定等于一个汉字或单词，实际用量按服务商返回的 usage 看。

输入用量数问题和模型收到的提示，输出用量数模型产生的内容。`max_tokens=256` 限制输出 token 数，不是“最多 256 个汉字”；达到上限可能留下不完整回答。**限流**则限制同一用户在一段时间内能发多少请求，本课约每分钟 5 次。请求次数、文本 token 数与实际费用要分别看，usage 缺失时不能编一个数字。
:::

## 用 Mock 验证边界，不花真实 token

登录后输入一个短问题，看到 Mock 标记和固定回答。提交空白问题和超过 2000 字符的问题，应得到输入提示；直接构造 HTTP 请求也应被服务端拒绝。连续发送六次合法 Mock 请求，应能观察到一次 `429`；等一分钟再试。退出登录后，AI Route 应返回 `401`。伪造跨站 Origin 的写请求应返回 `403`。原来的资料列表、CRUD 和用户隔离仍要正常。

先按[Network 三步操作](/environment#network)打开面板，过滤 `answer`，**再**点击提交，查看 Headers 的状态码和 Response。不能只看页面颜色判断请求是否被拒绝。

## 检查 Key 的边界

看浏览器 Network 的请求与响应、客户端页面源码、`git diff` 和 `git status`。它们都不应出现真实 API Key、Authorization Header 或完整 Provider 原始响应。可以搜索变量名 `AI_CHAT_API_KEY`，确认它只在服务端配置读取处使用；**不要复制真实 Key 到搜索框、终端或聊天里做检查**。`NEXT_PUBLIC_` 前缀会把配置带给浏览器，所以绝不能创建 `NEXT_PUBLIC_AI_CHAT_API_KEY`。

## 失败时页面应该说什么

模型不可用时，按钮应结束等待，页面显示简短可理解的错误；401、超时等由服务端映射为受控信息。不能把原始 Provider 错误、堆栈或 Key 原样返回。课程参考实现已检查无效 Key 与超时边界，本课不要求你销毁 Key 或反复花费 token 来制造失败。Mock 中的空输入、限流、未登录和跨站请求，已经能安全验证大部分边界。

进程内 Map 限流是本课的**本地或单实例基础保护**。Serverless 多实例不会共享这份 Map，不能把它称为全局可靠的计费系统。上线前要依据实际部署规模补充共享限流和预算控制；本课只要求理解并验收当前基础保护。
