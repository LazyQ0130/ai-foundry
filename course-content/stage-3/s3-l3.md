## AI 已经会回答，为什么还要等？

3.1 的问答会先显示「正在等待…」，模型写完后，整段答案才突然出现。回答正确，等待时的体验却仍然迟钝。这一课让同一个知识工作台多一个**流式模式**：输入「用几句话解释 Git 为什么能帮助我安全试错。」，点击「开始生成」，先看到「正在连接模型…」，然后看着答案一段段长出来。你还可以在中途点「停止生成」。3.1 的普通模式与 3.2 的结构化资料建议继续保留。

```text
Git
Git 可以
Git 可以记录每次修改……
```

这不是打字机动画。每段文字要在服务端收到模型新内容后才进入页面。今天关注用户能观察到的变化与边界；无需先钻进 SSE 或 HTTP Chunk 的细节。

**流式**可以理解成“内容还在生成，就先把已经产生的部分送来”。一次请求可以分多次收到片段，不是浏览器每出现一个字就重新问一次模型。一个片段也不保证恰好是一句话，所以应用还需要明确的完成或错误信号，不能把“暂时没有新文字”当成生成完成。

## 先用 Mock 把体验做出来

从你完成的 3.2 项目继续。让 AI 先检查已有问答、建议区、Provider、认证、同源保护与共享限流，以及你自己的页面调整。保持同一个问答输入框，增加「普通模式 / 流式模式」切换，不需要再堆一个几乎一样的输入区。先使用 `AI_PROVIDER_MODE=mock`；固定的四段短文字、每段约 800 毫秒，就足够让你看到状态变化，也不会消耗真实额度。

上一课最后使用真实模式，先按[模式切换步骤](/environment#stage3)停止 A、保存 `.env` 的 `AI_PROVIDER_MODE=mock`，再在同一项目根目录 `npm run dev`，等 Ready 后才开始下面的开发和测试；数据库地址不改。

先补需求，再让 AI 开发。必要约定：流式接口是服务端到浏览器的持续传输；取消必须关闭上游连接，不能只隐藏页面。

:::deepdive{title="给 AI 的技术备注：流式传输与取消"}
传输格式可照抄，不必先背协议名；你要观察逐段出现、停止向上游传递、旧结果不覆盖新结果、失败不冒充完成。SSE 是模型服务发流的格式，NDJSON 是本应用发给页面的逐行 JSON 格式。

本节固定接口是 POST /api/ai/stream，只收 input（1～2000 字符）。Provider 用 SSE，应用向浏览器用 meta/delta/usage/done/error NDJSON；取消沿 AbortSignal 传递，旧 generation 不得覆盖新结果。
:::

## 亲手停止一次

再次用 Mock 开始生成，在第二段出现时按「停止生成」。页面立即显示「已停止生成」，保留已经收到的部分文字，后续文字不再追加，也不能显示「生成完成」。取消是一种用户选择，不应变成红色失败提示。

接着迅速开始请求 B。请求 A 的某一段可能已经在网络路上，单靠 `busy=true` 守不住这种情况。给每次生成一个递增编号；每次写入页面前检查编号是否仍属于当前请求。A 被取消后，即使最后一段晚到，也必须忽略，B 只显示 B 的回答。

```text
A 开始 → A 收到一段 → 停止 A → B 开始
                             A 迟到：忽略    B 新段：显示
```

![请求 A 流式输出后被取消，请求 B 用新编号开始，A 的迟到片段被忽略](/course-media/stage-3/s3-3-01.webp "取消后旧请求不能污染新的流式回答")

:::concept{title="流式问答的六个界面状态"}

`idle` 是尚未开始；`pending` 是已请求但尚未收到正文；`streaming` 是正文正在增长；`completed` 是收到正常结束；`cancelled` 是用户停止；`failed` 是连接、Provider 或数据出了问题。取消与失败都可能发生在首段之前或之后。

Provider 因输出长度上限停止也属于 `failed`，不是 `completed`。页面可以保留已收到的部分文字，但不能把截断的答案标成完整结果。

:::

![流式响应中的接收、取消与旧响应隔离](/course-media/stage-3/s3-l3-stream-guide.webp "流式响应中的接收、取消与旧响应隔离（教学示意）")

看图核对：请求 A 的迟到片段应该被丢弃。取消和响应归属检查共同保护请求 B 的显示，不能只看停止按钮是否变灰。

## 主动制造中途失败

:::deepdive{title="为什么 generation id 能阻止旧请求污染新请求？"}
每次开始生成都递增编号。收到文字时，先比较这段文字所属编号和当前编号；取消 A 后启动 B，即使 A 的网络响应迟到，编号已不同，页面会忽略它。AbortController 负责尽量停止网络工作，编号负责保护最后一次状态写入。
:::

用本地 Provider Stub 先送一段，再送一条坏事件或直接断开，不必反复花真实 token 制造故障。页面应显示「生成中断，以下是已经收到的部分内容」，并保留那一段；状态是 `failed`，绝不能伪装成 `completed`。如果在第一段之前收到 Provider 401 或 5xx，页面显示受控错误，不回显 Provider 原文或 Key。

沿用 [3.2 的 Stub 操作与 `npm test` 入口](/lesson/stage-3/s3-l2)，让 AI 将“首段后坏事件／断开、首段前 401/5xx、输出长度截断、取消使上游关闭、A 迟到不污染 B”加入现有测试，导入实际 parser、Route 与页面请求编号逻辑。测试自己启动本机 Stub、使用假 Key，结束自动关闭，不改 `.env` 或正式 Route 的保护。运行 `npm test`，这些拒绝／取消断言通过且失败数为 0、退出 0 才算；并按上文亲手停止 Mock。若要亲眼观察中途失败，让 AI 提供一个**仅本机测试用、明确命令启动与 Ctrl+C 恢复的预览入口**，不能让公开 API 接受任意故障或 Provider 地址。测试失败先按案例定位，恢复合法 Stub 后重跑；不将 done 当作断流的默认结果。

登录、Origin、JSON、输入长度与限流都在开始流之前检查，所以仍用正常 HTTP 401、403、400、429 等状态。回答开始发送后，HTTP 状态不能再改；应用自己的流用 `error` 事件告诉页面后续失败。

## 再接真实模型

确认 Mock 和 Stub 通过后，在被 Git 忽略的本机 `.env` 按环境说明配置自己的 Workspace；Key 只留在服务端，绝不贴到聊天、课程、代码或浏览器。用已配置的 Chat 模型提一个短问题，观察第一段延迟、收到的文本段数、总耗时和是否有 token usage。不要把完整回答写进验收日志。再发一条短请求，收到首段时停止，检查之后的页面新增段数为 0，并用本地 Stub 确认取消使 Provider 连接关闭。

真实配置须明确含 `AI_PROVIDER_MODE=real`；保存后先 Ctrl+C 停旧 dev，再 `npm run dev` 等 Ready，核对本次响应为 real。结束真实观察后要回 Mock 复验时，也把模式改回并按相同顺序重启。不要只刷新网页切模式。

当你只看页面时，整个数据流可以记成：

```text
百炼逐段返回
   ↓
服务端 Provider 解析
   ↓
你自己的 meta / delta / usage / done / error 事件
   ↓
浏览器逐行读取并更新当前这次回答
```

百炼怎样发流，与产品怎样告诉页面「有新文字、结束、出错」是两层事。未来换模型时，页面只需继续理解自己的事件。`usage` 若在流尾出现，就显示 total tokens；没有 usage 也允许正常完成。3.2 的 `summary / tags / confidence` 仍走普通 `generate()` 与严格 Schema；这节不处理流式 JSON。

:::stuck{title="一直停在正在连接，或者文字突然消失"}

先查 `/api/ai/stream` 的 HTTP 状态：401 看登录，403 看同源，400 看输入，429 等共享限流窗口。若是 200 但没有逐段显示，用本地 Stub 检查 Route 是否把每段立即写出、浏览器是否按行读取；不要假设一次 `reader.read()` 就是一条完整事件。中途断开时保留 partial text，并确认错误走 `error` 事件。取消后仍有文字，检查 AbortSignal 与 generation id 两条防线。

:::

:::task{title="理解核对：停止、结束与半截回答"}
先用自己的话回答，拿不准再展开答案。

1. 只显示了半截回答，连接就断了。页面应该说完整成功，还是说明中断？
2. 用户主动点停止，已经显示的文字应该怎样标明状态？
:::

:::deepdive{title="核对答案：停止、结束与半截回答"}

1. 说明中断或受控错误。已经收到的文字可以保留，但不能当成完整成功。
2. 明确标为已停止，保留的文字也不冒充完整回答。仍要检查停止后不会继续更新当前结果。
:::

## 验证并保存版本

运行 `npm test`、`npm run build`，再回归普通问答、结构化建议、资料 CRUD 和不同账号的数据隔离。课程 Prompt 复制后核对完整再使用；自己的产品在普通窗口和缩窄到约手机宽度的窗口各看一次，确保切换、状态与停止按钮仍可用。最后看自己项目的 Git diff：应是本课 Provider、Route、页面与测试的必要改动，不应出现 `.env`、Key、完整模型输出或构建缓存。本课无需改数据库 schema／migration，原有功能仍正常，再提交自己的版本。

完成本课后，你的 AI 问答不再只会等待整段答案；它能让用户看见生成进度、主动停止，并在失败或旧请求晚到时保持当前视图可信。下一课才会进入新的能力，本课停在流式体验。
