## AI 会回答了，但还没读过我的资料

3.1～3.3 的知识工作台已经能问答、输出结构化建议，还能逐段显示回答。可是你粘贴在自己资料区的内容，并不会自动成为模型能寻找的知识。今天只做一件事：把一篇你自己的非敏感文本变成能保存在数据库中的向量分块。

先看要验收的动作：按下文准备好数据库、完成页面开发，再在新增的入库区粘贴一篇非敏感资料，等它显示「已入库」和分块数量。**Chunk** 就是从整篇资料切出的小片段；**Embedding** 是用一组数字表示这个片段，方便下一课查找。这里只存好片段，3.5 才拿问题去检索，当前不用提前学习检索算法。

为什么要有这组数字？“保存代码版本”和“记录代码历史”用词不同，意思却接近；Embedding 模型按它学到的规则生成数字，让应用能比较问题与资料的接近程度，先找候选。数字由模型生成，不需要你为每块手填关键词或算公式；原文仍保存在 Chunk 中。

:::concept{title="1024 维：每个片段有 1024 个数字"}
**向量**在本课就是按顺序组成的一组数字；**维度**是这组数字有多少个。3 个 Chunk 意味着 3 个资料片段，每块各有一组 1024 个数字，不是整篇必须有 1024 字、也不是要切成 1024 块。

这组数字用于寻找可能相关的资料，不是给资料加密，也不保证能找到正确答案。要放在一起比较的向量必须来自同一模型并保持相同维度；数据库可以存有不同模型的记录，检索时要先筛出匹配的一组。
:::

这里的**建立文档索引**是把“分块→生成向量→检查→保存”做完，让资料可供后续检索。`indexing` 是还在处理，`ready` 是整篇处理成功，`failed` 是处理失败；仅在数据库建了一行文档，不能就说已入库。数据库用于加速查找的索引属于另外的实现细节，本课不加进阶向量索引。

:::deepdive{title="给 AI 的技术备注：文档到向量表的名称"}
下面的模型名和列类型可照抄；完成后仍要按正文核对 ready、分块数、真实模型以及 `vector_dims=1024`，不能只看名字猜测已入库。

```text
一篇完整资料 → KnowledgeDocument → 多个 Chunk
                                      ↓
                               每块生成 Embedding
                                      ↓
                           PostgreSQL vector(1024)
```

:::

![一篇非敏感资料切成分块，逐块生成 Embedding，检查为 1024 维后存入 PostgreSQL pgvector](/course-media/stage-3/s3-4-01.webp "文档分块到向量数据库的完整路径")

完成时，你应该能在页面看到「已入库、分块数量、所用模型、1024 维」，也能从数据库读到每块的 `vector_dims=1024`。分块数量由你的文本决定，不必刚好是 3。先不做提问或检索。分两次完成：第一次准备数据库，第二次建立索引；安装、下载与系统重启的等待另计。

:::warning{title="只用非敏感资料练习 Embedding"}
真实 Embedding 会把文本发送给模型服务商。课程实验只使用非敏感资料；不要上传公司内部、隐私、密码或其他不该离开本机的文本。
:::

用自己的话简短回答，拿不准再展开答案。本课的实际操作与验收仍要完成。

1. 一篇资料切成 3 个 Chunk，每个 1024 维。3 和 1024 分别数什么？
:::

:::deepdive{title="核对答案：Chunk、Embedding 与维度"}

1. 3 数资料片段；1024 数每个片段向量中的数字。不是切成 1024 块，也不是规定原文有 1024 字。

## 第一部分：从现有项目加上能存向量的数据库

### 先准备一个真的支持 pgvector 的数据库

数据库仍负责保存资料，但这次还要能保存“表示文字意思的一组数字”。**pgvector** 是让 PostgreSQL 能存放和比较这组数字的扩展。先把库准备好，不需要先懂向量数学。

**先选路线，不必先安装 Docker 再决定。** 已有可用 Docker，沿路线 A；没有 Docker、WSL 安装受阻或不熟悉 BIOS，直接到下方路线 B 使用独立 Neon。注册／连接从[免费环境页第 5 项 B](/environment#tools)也能完成，不要求先学其他付费课。Docker 只是本地运行数据库的一种办法，不是本课向量入库的必考概念。

如果 3.1 已按环境页准备好独立的 Stage 3 云库，沿用同一份库和现有账号／资料；不要另开空库再误以为旧资料丢失。两条路线仍须启用 pgvector、增量迁移、真实写读与隔离、Mock／真实 Embedding 和数据库测试，不能把向量换成普通文本来跳过要求。

云路线学员直接从下方「路线 B」继续，全部路线 A 的安装、compose、容器 SQL 命令都跳过。后面的通用 Prisma 命令仍在完成 3.3 的**原项目根目录**运行。下一课和 3.7 继续沿用这份库，跨课步骤与失败恢复见[Stage 3 全程路线](/environment#stage3)。

### 路线 A 第 1 步：安装并确认 Docker 可以运行

1. 按[官方 Windows 安装说明](https://docs.docker.com/desktop/setup/install/windows-install/)或 [Mac 安装说明](https://docs.docker.com/desktop/setup/install/mac-install/)下载 Docker Desktop。Windows 使用安装器；Mac 在「关于本机」确认是 Apple 芯片还是 Intel，再选对应安装包并按提示安装。
2. Windows 安装器若询问后端，选 **Use WSL 2（使用 WSL 2）**。按安装器提示完成安装和必要的重启。启动 Docker Desktop，等待引擎启动；不要只安装完就关掉。
3. 打开一个新终端（Windows PowerShell 或 macOS 终端），输入：

```bash
docker version
```

**成功标志：既有 `Client` 部分，也有 `Server` 部分，且没有连接失败。** 只有 Client 说明命令已安装，但数据库运行所需的引擎还没启动。

:::stuck{title="Docker 提示 WSL 更新、虚拟化不可用或连不上引擎"}
- **WSL needs updating**：在 Windows 开始菜单找到 PowerShell，右键「以管理员身份运行」，输入 `wsl --update`；完成后按提示重启并重新打开 Docker Desktop。若提示 WSL 未安装，按[微软 WSL 安装说明](https://learn.microsoft.com/en-us/windows/wsl/install)运行 `wsl --install --no-distribution` 并重启。这些是系统准备命令，不要求在项目目录运行。
- **Virtualization support not detected**：在 Windows 任务管理器的「性能 → CPU」查看「虚拟化」是否启用。未启用时按电脑厂商说明开启；不熟悉 BIOS 操作可以直接选下面的 Neon 路线，不必卡在本机安装上。
- **Cannot connect／error during connect**：先打开 Docker Desktop，等引擎启动，再试 `docker version`。若连 Client 都没有或提示命令找不到，确认已完成安装，再打开新终端。
:::

### 路线 A 第 2 步：在自己的 3.3 项目启动数据库

继续使用**你完成 3.3 的项目**。另开终端，按第 0 课的方法 `cd` 到它的根目录；Windows 用 `dir`、macOS 用 `ls`，确认能看到 `package.json`。新终端不会自动来到项目目录。

Stage 3 Starter 随包提供 `compose.yaml`。若自己的项目还没有，在编辑器中新建与 `package.json` 同层的 `compose.yaml`，粘贴下面内容并保存；**已有配置时先核对，不要覆盖其他服务**。这是文件内容，不是终端命令。课程配置固定使用已在本地验收过的 PostgreSQL 17 + pgvector 0.8.6，数据库名为 `stage3_learning`，端口只绑定本机。示例口令只用于本机学习，不用于共享或生产环境。

```yaml
services:
  db:
    image: pgvector/pgvector:0.8.6-pg17
    environment:
      POSTGRES_DB: stage3_learning
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: stage3-local-only
    ports:
      - "127.0.0.1:55433:5432"
    volumes:
      - stage3_pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d stage3_learning"]
      interval: 5s
      timeout: 3s
      retries: 12
volumes:
  stage3_pgdata:
```

回到**这个项目目录的终端**，一次运行一条：

```bash
docker compose up -d
```

启动命令完成后查看状态：

```bash
docker compose ps
```

第一条首次需要下载数据库镜像，等待下载完成；`-d` 表示后台运行，命令结束不等于数据库关闭。**成功标志：第二条列出 `db` 服务，状态为 `Up`／running 且健康状态为 `healthy`，端口包含 `127.0.0.1:55433`。** `health: starting` 时等几秒再运行 `docker compose ps`。

:::stuck{title="找不到 compose.yaml、下载失败或 55433 已被占用"}
`no configuration file provided` 表示目录不对或文件还没保存；回到能看到 `package.json` 和 `compose.yaml` 的目录。镜像下载失败时先检查网络和 Docker 的错误，未下载完成不能继续。如果端口已被其他项目占用，先确认那个项目是什么；不要删除容器或数据库。可选下面的独立 Neon 路线，或请 AI 只读定位冲突后说明最小调整，连接串端口也要随之匹配。
:::

### 路线 A 第 3 步：直接用容器内的 SQL 工具

**不需要另装数据库客户端。** 在同一项目终端运行以下命令，打开容器自带的 `psql`。它是输入数据库命令的窗口：

```bash
docker compose exec db psql -U postgres -d stage3_learning
```

**成功标志：提示位置变成 `stage3_learning=#`。** 接下来输入的是 SQL，不是 PowerShell／Shell 命令，也不用把提示位置一起复制。一次一条粘贴并按 Enter：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
SELECT extversion FROM pg_extension WHERE extname = 'vector';
```

第一条返回 `CREATE EXTENSION`；若扩展已存在，出现 notice 也正常。第二条的 `extversion` 应有一行 `0.8.6`。看到结果后输入下面这条退出，回到普通项目终端：

```text
\q
```

如果结果停在 `(END)`，先按 `q` 离开结果浏览，再输入 `\q`。退出 SQL 工具不会停掉数据库。后面每次说“在学习库执行 SQL”，都可以用同一条 `docker compose exec` 打开这里，查完用 `\q` 返回。

### 路线 B：用独立 Neon，跳过 Docker 安装

1. 已按环境页建立独立 Stage 3 库的学员，确认同一项目、branch、database 后沿用，直接做第 2 步。其他学员打开 [Neon 控制台](https://console.neon.tech/)，注册或登录自己的账号并完成验证。点击 **Create project（创建项目）**，新建**单独的 Stage 3 学习项目**，例如 `aifoundry-s3-practice`，选择可用地区和默认数据库后确认。看到新项目总览，记下项目和数据库名；不要连接自己的 Stage 2 公开演示库或其他生产库。
2. 在该项目找 **Postgres database → SQL Editor**，选择这份学习库的 branch 和 database。把下面两句放入编辑区，点 **Run**，不必回到路线 A 找命令：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
SELECT extversion FROM pg_extension WHERE extname = 'vector';
```

**成功标志：扩展版本查询返回一行非空版本号**；云端版本以实际结果为准，不必等于 Docker 的版本。不在网页 SQL Editor 输入 `docker` 或 `\q`。

3. 在同一项目点 **Connect（连接）**，旧界面也可能写 **Connection Details（连接详情）**。选择相同的 branch（分支）、database（数据库）和默认 role（连接账号），使用 Direct／unpooled 直连地址，有 Connection pooling 开关时关闭它。复制完整 PostgreSQL 连接串，保留 TLS 等末尾参数，不把 `****` 遮罩当密码。由你本人填写本机 `.env`，不必另装客户端。入口有变化可查[官方连接说明](https://neon.com/docs/get-started/connect-neon)和 [SQL Editor 说明](https://neon.com/docs/get-started/query-with-neon-sql-editor)；只核对连接参数，不照抄其他 Prisma 主版本的安装、adapter 或 db push 示例。详细免费起步步骤见[环境页第 5 项 B](/environment#tools)。

本课程最终参考项目已在独立 Neon PostgreSQL 17 + pgvector 环境中完成四次 migration 与真实调用；这不替代你对自己项目的验证。两条路线都不要使用 AIFoundry 平台库或作者数据库，也不需要作者连接串或 Secret。

### 让自己的项目连接这份学习库

`DATABASE_URL` 是项目找数据库的地址。先在运行开发服务的终端按 **Ctrl+C** 停止服务（Windows/macOS 都一样）。在编辑器打开与 `package.json` 同层的 `.env`；没有就新建 `.env`，不要命名为 `.env.txt`。其他配置保留，只替换或新增一条 `DATABASE_URL`。

**路线 A 严格使用上面原样配置时**，本机可直接填这一行；这是课程公开的本机练习口令，不是云端密码：

```text
DATABASE_URL="postgresql://postgres:stage3-local-only@127.0.0.1:55433/stage3_learning?schema=public"
```

**路线 B** 则把值换成你本人从新建 Neon 项目复制的完整连接串。不要把 Neon 地址与上面的本机地址拼接，也不要手改密码或丢掉末尾参数。如果本机 Docker 配置的口令／端口已经改过，连接地址必须对应实际值。

保存文件后，在项目终端运行 `git check-ignore .env`，应输出 `.env`；再运行 `git status --short`，待提交列表不应包含 `.env`。若检查不符，先不要提交；让 AI 核对 `.gitignore` 含 `.env*` 规则及该文件是否已被跟踪，只修复这份配置的忽略／跟踪问题，不打印值、不删除文件，重新检查通过后再继续。

若项目有 `.env.local`，也核对其中没有同名旧连接：Next.js 优先读取它，Prisma 默认读取 `.env`，不要让两者指向不同库。另开的终端如果以前设置过 `$env:DATABASE_URL`／`export DATABASE_URL`，请关闭它再开一个新终端并重新 `cd`，避免旧值覆盖文件配置。

**换连接地址不会自动复制旧数据库的账号和资料。** 在这份独立学习库先准备旧结构，之后才新增本课向量结构。还没让 AI 创建第 4 次迁移时，在项目终端一次执行一条：

```bash
npx prisma migrate deploy
```

成功后检查状态：

```bash
npx prisma migrate status
```

状态正常后生成访问代码：

```bash
npx prisma generate
```

生成成功后启动应用：

```bash
npm run dev
```

前三条分别应用已有迁移、检查状态、生成数据库访问代码。**成功标志：旧三次迁移已应用，状态显示 `Database schema is up to date`，生成提示含 `Generated Prisma Client`；最后服务显示 Ready 和 Local 地址。** 任一条失败先停下来排查，不继续启动。若已做过本课，可能已有四次迁移，不要为凑“三次”删除历史。

在浏览器顶部地址栏输入终端显示的 Local 地址。沿用 3.1 同一云库时，先登录原测试账号、读取原资料并记下 ID，不必重注册；只有本课确实新建了学习库时，才注册该库的新测试账号、保存一条非敏感资料并刷新确认还在。新库没有旧账号是正常现象；原库没有被搬走或清空。稍后按原 ID 只读核对，证明新增向量结构没有破坏旧功能。

选择本地 Docker 或独立 Neon，执行 `CREATE EXTENSION` 和 `SELECT extversion`；记下自己的数据库类型与扩展版本，再继续修改 Prisma schema。别把两个环境的 `DATABASE_URL` 混用。

:::stuck{title="CREATE EXTENSION vector 报“扩展不存在”"}
本机普通 PostgreSQL 可能没有安装 pgvector；改用课程提供的 pgvector Docker 环境，不要删除 migration。Neon 上先确认连接的是正确的独立项目和支持该扩展的 PostgreSQL 环境。不要把 `vector` 改成 `text` 或 `float[]` 假装完成，也不要删除 `CREATE EXTENSION` 或用 `db push` 绕过 migration。

从你完成的 3.3 项目继续。保留已有的 User、Session、Resource、你自己的页面变化、普通问答、结构化建议和流式问答。`Resource` 是原来的资料卡片，不要改名或改造成知识文档；新增 `KnowledgeDocument` 和 `KnowledgeChunk`。文档属于一个已登录用户，分块属于一篇文档，`position` 从 0 依序递增，同一篇文档内不能重复。

:::deepdive{title="Prisma 为什么使用 Unsupported(vector)？"}
Prisma 6.19.3 的 schema 不把 pgvector 列当作普通标量字段处理，所以在模型里标记 `Unsupported("vector")?`，而正式 SQL migration 建立真实的 `vector(1024)` 列。读写向量走参数化 SQL，并让数据库检查维度；这个标记不是把向量退化成文本或数组。
:::

:::deepdive{title="给 AI 的技术备注：文档与分块的表、字段和接口"}
实现名称与长度可照抄；入库完整才 ready、向量维度一致、只读本人的文档以及历史迁移保留都必须验收。

本节固定模型是 KnowledgeDocument → KnowledgeChunk；同文档 position 唯一，vector(1024)，状态 indexing/ready/failed。GET/POST /api/knowledge/documents，title 为 1～100、content 为 1～6000 字符；保留历史 migration，禁止 reset。
