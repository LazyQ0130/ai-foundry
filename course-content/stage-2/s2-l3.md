2.1，你只在浏览器里预览资料。2.2，浏览器真的向 `/api/resources` 发出 POST，Next.js 服务端检查并回答 `saved: false`。现在刷新页面，刚才的资料依然不在正式列表，因为服务端还没有把它写到长期存储。这节才让它留下来。

继续使用**你完成 2.2 的同一个项目**。不要重下 Starter，也不要用示例 `app/page.tsx` 覆盖自己的页面。你的输入组件、排序或清除筛选、原始资料和个人标题都要保留。只用非敏感测试内容；没有账号与所有权检查的匿名写入接口，仅在受控本地环境运行，不作为公开应用部署。

**这节可以分两次完成，不必一次做完。**第一次只做练习数据库配置、Prisma 6.19.3 安装、`Resource` 模型、迁移和 Client 生成，看到表存在后就停；不要先改 POST 或页面。第二次从同一个项目和同一个练习库继续，把已有 POST 接到数据库，增加 GET 和页面展示，再做刷新、重启与失败验证。两次各预留约 45～60 分钟；Neon 注册、PostgreSQL 安装和依赖下载的等待另计。下面各有停止点、恢复步骤和证据，不要求为了赶时间跳过核对。

## 服务端收到了，为什么刷新后还是没有？

2.2 的服务端把输入检查一遍就回了 JSON；它没有记录下一次请求还能查到的资料。页面里的 React 状态也会随刷新消失。我们需要让服务端写入数据库，再通过**另一次 GET 请求**读回来。是否保存成功，以数据库写入结果和重新读取为准，不能只看按钮变绿。

## 第一次认识 PostgreSQL 和 Prisma

### 数据库负责留下什么

**PostgreSQL** 是这次真正保存资料的数据库。资料写入后，关闭浏览器、刷新页面或重启 Next.js，数据库里的记录仍可被下一次请求查询。**持久化**说的就是这种跨请求、跨页面运行时间的保存。

本课可以先把数据库中的一张**表**理解成按固定项目记录信息的表格：每一行是一条资料，每一列记录标题、简介或分类这类字段。例如两篇标题相同的笔记可以是两行，数据库用不同 ID 区分它们；标题相同不会自动变成同一条记录。页面卡片是读出这些记录后的展示。

### Prisma 在中间做什么

**Prisma** 是服务端与数据库之间的助手。你先让 AI 描述“一条资料有哪些内容”，再让它在数据库中建好存放位置，最后让保存按钮真的往里面写。写好描述不等于建好表，建好表也不等于页面已经能读到资料。

这三步各有一个代码名称：`schema.prisma` 描述“表要有哪些字段”；**migration（迁移）**把创建或调整表的步骤应用到数据库；**Prisma Client**让服务端代码实际读取／写入记录。这里的 Client 是一个数据库访问代码包。迁移不是把旧笔记搬到新电脑，也不是替你备份资料，已有数据仍要按正文核对。

:::deepdive{title="给 AI 的技术备注：结构文件、迁移与数据库调用"}
下面的文件和实现名称可照抄给 AI，不必先背；实际建表、写入、刷新后仍能读取的检查都要完成。

`schema.prisma` 是描述资料字段的文件；Migration（迁移）把这个定义应用到实际数据库；Prisma Client 是服务端调用数据库的代码入口。下文 Prompt 会保留这些名字，你需要理解的是“描述结构 → 建表 → 写入和读取”三个动作。
:::

:::concept{title="这节真正的数据路径"}

```text
当前表单 → POST /api/resources → 服务端校验 → Prisma 写入 PostgreSQL
                                                   ↓
数据库资料展示区 ← GET /api/resources ← Prisma 从 PostgreSQL 读取
```

原始 9 条示例资料暂时仍来自原文件。它们不自动进入数据库；你的项目若已改过示例数量，以自己的原始数量为准。

:::

## 给自己的项目准备数据库

本课主线选 [Neon 的免费 PostgreSQL](https://neon.com/pricing)，只需要一份独立的练习项目和数据库，不要求购买付费计划。免费额度、可用地区和注册条件可能变化，创建前以其页面为准。如果该服务在你所在地区不可用，下面给出从零安装本地 PostgreSQL 的替代路径；Docker 不是前置条件。内部参考在隔离的本地 PostgreSQL schema 上验证，不能把教学平台自己的数据库当作你的知识工作台已完成的功能。

### 第一次在 Neon 建立练习库

这一小段只准备数据库和本机配置，**还不创建资料表**。浏览器打开 Neon，编辑器打开你完成 2.2 的知识工作台；两边不要混成 AIFoundry 教学网站的项目。

1. 打开 [Neon 控制台](https://console.neon.tech/)，注册或登录自己的账号；邮箱验证和第三方登录按页面提示由你本人完成。
2. 找 **Create project（创建项目）**，练习名可用 `aifoundry-s2-practice`，选择可用地区和默认数据库后确认。**成功标志：进入新项目的 Dashboard（项目总览），能看到刚才的项目名。** 注册失败或网络不可达时，改走下面的本地 PostgreSQL 路线。
3. 在项目导航找 **Connect（连接）**；旧界面也可能写 **Connection Details（连接详情）**。弹窗里选择当前 **branch（数据库分支）**、**database（数据库名）** 和 **role（连接账号）**，这次用新项目已有的默认项，记住它们即可，不必另建分支。按[官方连接说明](https://neon.com/docs/get-started/connect-neon)找到 PostgreSQL 连接字符串，复制**完整地址**，保留末尾参数。密码如果显示成 `****`，先用受控页面提供的显示或复制入口取得真实值，不能把星号当密码，也不要手工重拼地址。
4. 在编辑器找到与 `package.json` 同层的 `.env`。**没有就新建名为 `.env` 的文件，开头有一个英文点，没有 `.txt` 后缀**；可以用文件栏的新建文件入口，或让 AI 只创建空文件，再由你本人填写。如果文件已经存在，保留其他配置，只新增或替换一条 `DATABASE_URL`，不要重复写同名项。

下面内容写入 **`.env` 文件，不是终端**。双引号内换成你本人从控制台复制的完整地址，然后保存（Windows：Ctrl+S；macOS：Cmd+S）。这段是格式示意，不能原样使用：

```text
DATABASE_URL="这里粘贴你自己复制的完整连接字符串"
```

如果项目还有 `.env.local`，确认里面没有同名的旧连接配置：Next.js 会优先读取它，而 Prisma 默认读取 `.env`，两处不一致会让页面与迁移连到不同数据库。让 AI 只核对文件和键名，不回显地址。若以前在终端设置过数据库环境变量，关闭那个终端再开一个新终端，避免旧值覆盖文件配置。

5. 在**另一个项目终端**先按第 0 课的方法 `cd` 到同一个知识工作台目录。Windows 输入 `dir`，macOS 输入 `ls`，确认能看到 `package.json`，再检查：

```bash
git check-ignore .env
git status --short
```

**成功标志：第一条输出 `.env`，第二条的待提交列表没有 `.env`。** 如果没有被忽略，先让 AI 补好 `.gitignore` 中的 `.env*` 规则并重新检查；已被跟踪的情况按文末排障处理。不要把地址写进 Prompt、聊天或 Git。

6. 回到 Neon 项目，找 **Postgres database → SQL Editor（SQL 编辑器）**；旧界面可能直接显示 SQL Editor。选择与 Connect 一致的 branch 和 database，把下面的查询粘贴到编辑区，点 **Run（运行）**：

```sql
SELECT current_database();
```

**成功标志：结果出现一行数据库名，与你在 Connect 选择的相同。** 此时只证明控制台能连到库，本机连接还要通过下文 Prisma 迁移验证。入口找不到时对照[官方 SQL Editor 说明](https://neon.com/docs/get-started/query-with-neon-sql-editor)。

完成下文建表迁移后，回到这个 SQL Editor，替换编辑区的查询，再点 Run：

```sql
SELECT COUNT(*) FROM "Resource";
```

刚迁移且未写入资料时，`count` 应为 0；随后保存一条资料会增加。若提示表不存在，先完成下文迁移，再核对选择的数据库，不要反复创建项目。

### 没有 Neon、Docker 或现成 PostgreSQL：在电脑上安装 PostgreSQL

Neon 仍是本课主线。若 Neon 注册或连接不可用，**不必先安装 Docker**；可在自己电脑上装 PostgreSQL，完成本课及 2.4～2.7 的本地练习。

**Windows：**从 [PostgreSQL 官方 Windows 下载页](https://www.postgresql.org/download/windows/)进入其推荐的 EDB 图形安装器。安装 PostgreSQL Server 和 SQL Shell（psql），记住安装时自己设置的 `postgres` 密码；默认端口通常是 `5432`，若被占用，记下实际端口。安装后从开始菜单打开 **SQL Shell (psql)**，服务器填 `localhost`，数据库先填 `postgres`，端口填实际端口，用户名填 `postgres`，密码只在本机提示处输入。看到 `postgres=#` 后，一次一条运行：

```sql
CREATE DATABASE aifoundry_s2_practice;
\c aifoundry_s2_practice
SELECT current_database();
```

最后一条应返回 `aifoundry_s2_practice`。若提示数据库已存在，先核对它是否就是**自己的本课练习库**，不要删除或重建其他项目的库。将知识工作台项目根目录 `.env` 的 `DATABASE_URL` 设为 `postgresql://postgres:你安装时设置的密码@localhost:5432/aifoundry_s2_practice?schema=public`（端口按实际值替换）。这是**占位示意**，不可原样使用；密码若含 `@`、`#`、`/` 等特殊字符，要按 [Prisma 6 连接 URL 规则](https://www.prisma.io/docs/orm/v6/reference/connection-urls)进行百分号编码。不要把真实值贴给 AI、截入图片或提交到 Git。

在项目根目录确认 `.gitignore` 忽略 `.env*`，并核对 `git status` 没有 `.env`。完成下文固定版本的 Prisma 安装与模型后，对这个**已核对名称的练习库**运行 `npx prisma migrate dev --name init_resource` 和 `npx prisma generate`。回到 SQL Shell，确认已经连接 `aifoundry_s2_practice`，执行 `SELECT COUNT(*) FROM "Resource";`；刚迁移且未写入资料时应为 0。若不是 0，先核对是否连接了已有练习数据的库，不要清表。

**macOS：**从 [PostgreSQL 官方 macOS 下载页](https://www.postgresql.org/download/macosx/)选择 EDB 图形安装器；它同样包含 PostgreSQL Server 和 pgAdmin。安装时记下 `postgres` 密码与端口。在 pgAdmin 中连接本机服务器；若没有自动列出服务器，用 **Register → Server**，在 Connection 填 `localhost`、实际端口、用户名 `postgres` 和自己设的密码。选默认 `postgres` 数据库打开 Query Tool，执行上面的 `CREATE DATABASE`；再选新建的 `aifoundry_s2_practice` 数据库打开 Query Tool，用 `SELECT current_database();` 核对目标。随后按相同的 `.env`、Prisma 迁移与只读 `COUNT` 步骤操作。若选该官方页面列出的 Postgres.app，则以其实际本机用户名、端口和数据库连接信息替换示意值，不能照抄 EDB 的 `postgres` 账号。

本地 PostgreSQL 只替代 **2.3～2.7 的受控练习库**。它不会因为 Git push 自动变成公网数据库；2.8 仍需独立的生产云 PostgreSQL 和部署连接，不要把自己电脑的 `localhost` 地址填进 Vercel。本课程已验证的数据库路线为 Neon 和指定的本地 PostgreSQL 环境。其他云数据库尚未完成课程全流程验证，暂不作为推荐替代路线。

### 连接信息放在哪里

走 Neon 主线时，在控制台确认**专供本课使用**的数据库，记下非秘密的项目名与数据库名，把控制台的 PostgreSQL 连接地址放入知识工作台根目录的本地 `.env`。走本地备用路线时，用上文自己创建的练习库和本机连接地址。两种路线的键名都为 `DATABASE_URL`；不要把真实地址贴进聊天、README、源码、截图或 Git。告诉 AI“本地 `.env` 已由我配置”，不提供真实值。地址中可能包含数据库密码。

先检查 `.gitignore` 是否覆盖 `.env*`，再用 `git status` 确认 `.env` 没有进入待提交文件。如果曾经提交或公开发送过真实地址，停止继续传播，并在数据库服务商处轮换凭证；只补 `.gitignore` 不会撤回已泄漏的密码。不要用 `NEXT_PUBLIC_DATABASE_URL`：`NEXT_PUBLIC_` 会让值进入浏览器可用的配置。只有服务端的 Route Handler 与 Prisma 读取 `DATABASE_URL`。

:::warning{title="迁移前先核对目标"}

请在 Neon 控制台或本机数据库工具中核对正在连接的是**专用练习库**，不是生产库，也不是你或 AIFoundry 平台正在使用的业务库。让 AI 只报告主机、数据库名等非秘密标识，不输出密码或完整连接字符串。遇到迁移错误先诊断，**不要**运行 `prisma migrate reset`、`drop database`、清空表或删迁移历史来“修好”它。

:::

### 安装与初始化，先停下来检查

参考项目是 Next.js 15.5.26、Node.js 24.16.0、TypeScript 5.9.3，已实测 Prisma CLI 与 Client **6.19.3** 可生成、迁移、构建。选择这个明确版本，避免无条件安装当时的最新主版本；如果你的 Node/Next 已不同，先让 AI 对照 [Prisma v6 系统要求](https://www.prisma.io/docs/orm/v6/reference/system-requirements)核对兼容性，不要照抄别人的 `package.json`。参考项目的安装方式是把 `@prisma/client` 与开发依赖 `prisma` 都固定为 6.19.3，并让现有包管理器更新锁文件。

“初始化”只是准备配置文件，不代表数据库已经建好。先看项目里是否已有 `prisma/schema.prisma` 和本课配置的 `.env`，已有就增量修改。`prisma.config.ts` **有则核对，没有不必补一份来凑齐文件**；不能仅凭有没有它判断安装失败。若使用 `npx prisma init --datasource-provider postgresql`，它还可能联网获取初始化模板，模板不一定适合本课固定版本。卡在下载或生成了别的版本写法时，停下这条命令，让 AI 按下面约定直接准备文件，不必重装或重复初始化。

:::deepdive{title="给 AI 的技术备注：固定版本的初始化边界"}
先确认本项目 CLI 与 Client 都是 6.19.3。允许直接建立 `prisma/schema.prisma`：本课使用 `prisma-client-js` 生成器、PostgreSQL datasource 与 `env("DATABASE_URL")`，Client 导入保持 `@prisma/client`；再加入下面要求的 Resource 模型。若已有 `prisma.config.ts`，先检查其实际加载路径、依赖和环境变量，避免与 schema 或 `.env` 冲突。保留学员已有 `.env`，只检查变量是否齐全，不覆盖或输出连接串。文件准备完仍须执行后面的正式迁移、generate、status 和真实读写验收，不能用创建文件代替它们。


## 给这次可用版本留一个保存点

按 1.5 的方法自己核对 Git 状态、忽略文件和变更范围，再亲手保存可恢复版本。迁移与锁文件通常应保存；`.env`、`node_modules`、`.next` 和测试数据库内容不能进入提交。若 `.env` 曾被跟踪，不要继续提交或公开同步，先处理凭证轮换与跟踪问题。不要让 AI 自动运行恢复或删除命令。

## 下一节：完整管理自己的资料

现在有了数据库写入和读取，但还没有完整编辑、删除，也没有账号和所有权隔离。2.4 才处理完整资料管理；2.5、2.6 再处理登录和服务端所有权检查。当前匿名写入练习继续留在受控本地环境。

:::deepdive{title="为什么 POST 成功后还要再 GET？"}

POST 的 201 证明服务端认为创建完成。再 GET 并核对同一 ID，可以证明新的请求确实从持久存储读到了它；刷新和重启进一步排除“只在当前页面状态里”的误判。若 POST 成功而 GET 因网络故障失败，不要自动重发 POST，先恢复读取确认数据库现状。

:::

## 卡住了怎么办

:::stuck{title="按失败发生的位置排查"}

### 数据库服务无法连接

先看练习库控制台是否可用、主机与端口是否正确、当前网络是否允许连接；再用只读连接测试。区分“Next.js 没启动”和“Next.js 启动了但 Prisma 连不到库”。不要把完整地址贴进求助消息。

### DATABASE_URL 格式错误

确认根目录 `.env` 的键名正好是 `DATABASE_URL`，一行完整、没有多余空格或断行，连接类型为 PostgreSQL。只报告解析错误和非秘密主机信息，不让 AI 回显值。改完重启开发服务器和 Prisma 命令。

### 数据库账号或密码错误

在服务商控制台核对该练习库的账号和连接方式，必要时重新复制到本地 `.env`。不要通过浏览器表单、截图或聊天发送密码；已公开的凭证要在服务商处轮换。

### Prisma 安装后命令不可用

回到项目根目录，检查 `package.json` 中两个 Prisma 包版本及依赖安装结果，用 `npx prisma --version` 核对本项目 CLI。不要全局装一个不同主版本来绕过错误。

### Prisma Client 尚未生成

确认 schema 已保存、迁移目标正确，在项目根运行 `npx prisma generate`，然后重启 Next.js。若仍报导入错误，检查实际生成位置与服务端导入路径，不要在浏览器组件直接导入 Prisma Client。

### Migration 执行失败

先看错误代码与数据库目标，确认当前是专用练习库、schema 和迁移文件一致。不要用 reset、drop、清表或删迁移记录解决；请 AI 只读解释冲突后再决定最小修复。

### 服务商不允许创建 shadow database

确认报错是否指向 shadow 权限，而不是密码或网络。查服务商与 Prisma 官方说明，考虑专门的隔离 shadow 目标或已有本地 PostgreSQL；不要拿日常业务库当 shadow，也不要给不可信的数据库账号扩大权限。

### POST 返回成功但 GET 查不到

核对 POST 的 `id`、GET Response、两个请求实际使用的 `DATABASE_URL` 目标与 schema，以及 GET 是否仍读静态资料或缓存。不要先再点一次保存；用只读数据库查询确认记录到底在不在。

### 数据库实际保存了，但页面没有更新

先单独调用 GET 确认记录，再看页面是否在 POST 成功后调用 GET、是否读取这次 JSON、是否把列表错误单独显示。点“重新读取”即可重查，不要重发 POST 制造重复资料。

### 刷新后新资料消失

区分输入框清空与数据库列表消失。检查刷新后的 GET 是否发出、是否 200、数据库查询是否仍有该 ID、是否意外换到了另一个库；不要用 localStorage 遮掩。

### AI 把地址放进 NEXT_PUBLIC_

停止运行与公开同步，检查代码和构建产物是否包含真实值。让 AI 只移除本轮误加的公开配置，改为服务端读取 `DATABASE_URL`；若值已公开，先在服务商处轮换。

### .env 出现在 Git 待提交文件中

先不要 commit。确认真实文件名与 `.gitignore` 的 `.env*` 规则，再检查它是否早已被 Git 跟踪或选入暂存区。只处理这个明确文件的跟踪状态；若曾推送，按泄漏处理并轮换凭证。

### AI 把原来的九条资料覆盖了

停下继续修改，比较 `lib/resources.ts`（或你项目的实际源文件）的本轮差异与旧版本，让 AI 仅修复本轮误改。重新核对原列表数量和自定义资料，不要整项目恢复覆盖其他工作。

### 数据库断开时仍显示保存成功

查看 POST 的实际状态码和 Response；若是 503/500，检查页面是否忽略 `response.ok` 或沿用上次成功状态。若仍是 201，检查 Route Handler 是否在 Prisma 写入完成前就返回，或在 `catch` 中伪造了成功。

### Stage 1 筛选或自选功能损坏

先比对原始资料列表与页面本轮差异，确认数据库展示区是否错误地混入旧列表计算。修复仅限本轮改动，再按原项目实际功能逐项测试搜索、标签、重要、统计和排序/清除筛选。

:::
