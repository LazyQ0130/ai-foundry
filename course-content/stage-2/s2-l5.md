2.4 的资料已经可以增删改查。可是谁发来的请求？打开页面的人都能直接调用数据库资料接口。继续使用你完成 2.4 的项目和专用练习库，保留已有记录、页面功能和迁移历史。本课只引入**用户名、密码、服务端 Session**，不重新下载 Starter，不把项目推倒重做。

## 数据库已经有资料，但服务端知道你是谁吗？

现在直接请求 `GET /api/resources`，接口只看请求和数据库，不知道当前使用者的身份。给页面藏起按钮并不能保护 API：别人仍能直接发 HTTP 请求。本节要让服务端先判断请求是否带着有效登录会话，没有就返回 HTTP **401**，再决定是否运行原有 CRUD。

## 注册和登录真正解决什么？

**注册**创建用户账号；**登录**验证密码并建立一段可持续的会话。每次请求，服务端根据会话找到当前 User。这里的认证（Authentication）回答“你是谁”。

### 身份认证不等于数据归属

**登录解决的是“你是谁”，2.6 才解决“哪些资料属于你”。** 本课的 Resource 没有 `ownerId` 或 `userId`。Alice 和 Bob 登录后暂时仍看到同一批资料，这是刻意保留的中间状态，不是可以正式交付的多人资料隔离。

:::concept{title="这一节的两张表"}

`User` 保存账号与密码哈希；`Session` 保存会话的 Token Hash、所属用户和过期时间。浏览器持有原始随机 Token，服务端只拿它的哈希查数据库。`Resource` 维持 2.4 的结构。这里使用服务端 Session + HttpOnly Cookie，不引入 JWT 或第三方登录。

:::

## 密码为什么不能原样存进数据库？

数据库中如果存明文密码，读取数据库的人就能直接得到它。服务端用随机 **salt** 和 Node.js `crypto.scrypt` 生成 `passwordHash`，验证时再计算并用 `timingSafeEqual` 比较。哈希不能作为“查看原密码”的方式。你需要理解存储边界，让 AI 实现并验证工具函数；不必自己手写密码学算法。密码至少 8 个字符，给出合理最大长度即可，不需要“大写+数字+特殊符号”的组合规则。

不要把真实密码、测试密码、数据库连接串或密码哈希放进截图、日志、提示词、Git 或验证报告。实验使用自己的非敏感练习账号。

## 第一次建立 User 和 Session

### User 保存什么

在原有 Prisma `Resource` 模型旁增量新增 `User`：`id`、唯一 `username`、`passwordHash`、`createdAt`，以及与 Session 的关系。用户名只接受 3～24 位英文字母、数字或下划线。本课不做邮箱、头像和找回密码。

### Session 保存什么

新增 `Session`：`id`、唯一 `tokenHash`、`userId`、`expiresAt`、`createdAt`。它通过 `userId` 指向 User，删除用户时关联 Session 应被清理。用 `randomBytes(32)` 生成原始 Token；数据库只存 `SHA-256(token)`。会话可设为 7 天，过期即不再识别。

## 注册一个真实账号

用 Next.js Route Handler 建立 `POST /api/auth/register`。服务端验证 JSON、用户名字符与长度、密码类型与长度；重复用户名回 409。注册成功后先安全哈希密码，再创建 User、Session、设置 Cookie，并只返回公开用户字段，例如 `id`、`username`。注册后直接进入登录状态，不用再填一次密码。`passwordHash`、`tokenHash` 与原始 Token 都不能出现在返回 JSON 中。

## 登录以后，浏览器怎么保持身份？

`POST /api/auth/login` 查找 User、验证密码，成功后创建**新的** Session 并设置 Cookie。错误用户名和错误密码统一返回 401 与同一条提示，避免让接口告诉旁人某个用户名是否存在。

### HttpOnly Cookie

Cookie 保存原始随机 Token，设置 `HttpOnly`、`SameSite=Lax`、`Path=/`。生产环境还要 `Secure`；本地 HTTP 开发环境不能强制 `Secure` 导致无法登录。普通页面 JavaScript 不能通过 `document.cookie` 读取 HttpOnly Cookie，也不需要把 Token 存到 `localStorage`。浏览器会在同站请求中自动携带它。


### 刷新为什么仍然登录

React state 一刷新就重建。页面启动时调用 `GET /api/auth/me`：服务端读 Cookie、哈希 Token、查 Session、检查 `expiresAt`，再返回公开用户信息。只要 Session 有效，刷新甚至重启 Next.js 后仍能认出用户；无有效会话回 401。

## 做出 /me 和退出登录

`POST /api/auth/logout` 不能只清 React state；它必须让数据库中的当前 Session 失效并清除浏览器 Cookie。用刚才的旧 Cookie 再请求 `/api/auth/me` 和资料 API，应立即是 401。还要在隔离练习库里将一个**专用测试 Session** 的 `expiresAt` 改成过去，验证它也返回 401；不要清空整张表。

:::deepdive{title="为什么数据库里不保存 Session Token 原文？"}

原始 Token 是会话凭证，拿到它可能直接冒充用户。数据库只存 Token Hash；即使只读数据库内容外泄，也不会直接得到浏览器的原始凭证。Cookie 仍需安全属性与有效期，哈希不是万能防护。

:::

## 亲自验证未登录和已登录

先退出并直接请求四个数据库资料方法：GET、POST、PATCH、DELETE 都应 401，尤其 DELETE 不能碰到旧记录。然后登录，用自己新建的可删除练习记录完成四种操作；刷新后确认数据来自数据库。再次退出，持旧 Cookie 的请求也应立即 401。静态示例资料和 Stage 1 的页面功能仍可正常阅读。

:::check{title="用结果证明身份真的由服务端维护"}

- 注册后 `/me` 返回公开用户；刷新与重启 Next.js 后仍能识别有效 Session。
- 数据库密码哈希不等于原密码，tokenHash 不等于 Cookie 原始 Token。
- 退出和过期会话都回 401；未登录四种资料 API 都回 401。

## 再注册一个 Bob

用两个**专用练习账号**做实验。Alice 登录后读取数据库资料；退出，确认资料 API 回 401；Bob 注册并登录，再读取。你会发现 Bob 看到 Alice 刚才看到的那批记录。这是本节预期结果。不要使用真实个人密码，不把测试密码写进报告。

### 为什么 Bob 现在还能看到同一批资料？

服务端现在只问“请求来自一个已登录用户吗？”。`Resource` 还没有所属用户字段，查询也没有按用户过滤。不能在前端假装隐藏 Bob 的记录来充当隔离。2.6 会增加资源所有权，在服务端回答“这条资料是不是当前用户的？”。

认证确认身份；授权与所有权决定这个身份能做什么、能看哪条资料。本课只给资料 API 加“必须已登录”的门槛。按资源所属用户检查是下一节的工作。

## 保存当前版本

先看 Git diff：应是 User/Session 增量迁移、认证工具与接口、Resource 登录保护及最小页面 UI。确认没有改 Stage 1 Starter、平台账号、价格、支付、进度算法或 Resource ownership。按你的项目习惯保存可恢复版本；Git 只保存代码，**不会自动备份数据库资料**。

## 下一节：每个人只能看到自己的资料

2.5 已让服务端知道“你是谁”，也让未登录请求无法直接操作资料。2.6《每个人只能看到自己的资料》才会为 Resource 增加归属并在服务端实现隔离。

## 卡住了怎么办

:::stuck{title="注册返回 500 或数据库报错"}

检查专用数据库连接、迁移状态、User 与 Session 表是否存在。不要运行 `migrate reset`，也不要清空原有 Resource。

:::

:::stuck{title="用户名已存在，或登录一直提示错误"}

刚注册过的用户名直接去登录。确认输入与注册时一致；数据库中的 `passwordHash` 不是原密码，不能把它填进密码框。错误用户名和错误密码本来使用同一提示。

:::

:::stuck{title="passwordHash 看起来像乱码，Cookie 在 document.cookie 中找不到"}

哈希不可用于查看原密码。HttpOnly Cookie 本来就不应被页面 JavaScript 读取；在浏览器 Application / Storage 的 Cookie 面板检查属性，但不要复制真实值到聊天或截图。

:::

:::stuck{title="刷新后掉登录，或登录后资料 API 仍是 401"}

依次检查 Cookie 是否设置、Path 与本地 Secure 配置、请求是否带 Cookie、服务端是否用相同 Cookie 名和 Token Hash 查询、Session 是否存在且未过期、`/api/auth/me` 返回什么。不要改用 localStorage Token 掩盖问题。

:::

:::stuck{title="退出后旧 Cookie 还能访问资料"}

这是失败。检查 logout 是否真的删除当前 Session、清 Cookie，以及所有资料 Route Handler 是否在执行 CRUD 前查 Session。

:::

:::stuck{title="AI 把秘密字段返回页面，或提前给 Resource 加 ownerId"}

用户 JSON 只能有公开字段，删除 `passwordHash`、`tokenHash` 和原始 Token。Resource 的 ownerId/userId 是 2.6 内容；撤回这部分越界改动，保留本节 User/Session。

:::

:::stuck{title="Bob 看到了 Alice 的资料"}

本节预期如此：已有认证，尚无资源所有权隔离。记录观察结果；不要偷偷在前端过滤。下一节再由服务端解决。

:::
