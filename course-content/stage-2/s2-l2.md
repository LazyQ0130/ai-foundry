## 浏览器和服务端是怎么说话的？

### 什么是请求与响应

浏览器是你填写和操作的地方。它发给服务端的信息叫**请求（Request）**；服务端接收、检查后回来的信息叫**响应（Response）**。前端发出资料，不代表服务端一定收到或接受。要等实际响应，再判断结果。

:::concept{title="这次通信经过哪里"}

```text
浏览器中的标题、简介、标签
          ↓  POST 请求
Next.js 的 /api/resources
          ↓  检查数据、返回 JSON
浏览器读取响应并显示结果
```

这一节的终点是“服务端已收到”，还没有数据库保存。

:::

### POST 和 JSON 是什么

**API** 是前端和服务端交互的约定入口。本次用 `POST /api/resources`，意思是向这个入口提交一份资料。**JSON** 是双方交换结构化数据的常用格式：这次请求里有 `title`、`desc`、`tag`，响应里会有是否通过、服务端收到的资料和“尚未保存”的说明。现在不用学习所有请求方法。

<!-- 配图建议：浏览器 → POST /api/resources → Next.js 服务端 → JSON 响应 → 浏览器；成功与失败都从服务端返回。 -->

## 建立第一条真正的 POST API

### 先让服务端收到资料

先只做接口，**暂时不修改页面**。下面 Prompt 的文件路径适用于常见 App Router；若你项目已做过相同接口，先检查其真实行为，符合要求即可复用。向接口发送的资料类似：

```json
{"title":"我的第一条新资料","desc":"这是我从网页填写的内容","tag":"文章"}
```

服务端检查通过后，应回 JSON，说明已收到且 `saved: false`。它不应编造数据库 ID 或返回“保存成功”。

:::prompt{title="创建真实的 POST 接口"}


### 不合格的数据不能直接通过

浏览器可能发来空标题、空简介、不在列表中的标签、错误类型，甚至格式错误的 JSON。服务端要自己检查。尤其 `tag: "全部"` 是筛选按钮，不是一条资料的分类。

:::deepdive{title="前端已经有输入框，服务端为什么还要检查？"}

有人可以绕开页面，直接向接口发请求。即使页面限制了输入，服务端也不能默认收到的内容合法。本节先做最小的类型、必填、长度和分类检查；完整安全与权限在后续课程继续做。

:::

## 为什么刷新以后还是没有保存？

本课的 `saved:false` 是事实：服务端接收并检查后立即返回，没有写数据库，也没有写入原始资料文件。服务器收到，不等于数据库保存。刷新后本页输入、预览和接收结果可以消失；2.3 才解决长期保存。

## 卡住了怎么办

:::stuck{title="先看发生在哪一步"}

### API 文件放错位置

核对真实项目根目录与 App Router 的 `app/api/resources/route.ts`，文件名是 `route.ts`。若页面放在其他目录，让 AI 根据当前项目结构指出位置；不要再建一个 Express 工程。

### 浏览器请求返回 404

先看地址是否正好是 `/api/resources`，再看开发服务器是否运行于当前项目、路由文件是否在 `app/api/resources/route.ts`。修正路径或重启开发服务器后重试。

### 浏览器请求返回 405

路径已找到，但请求方法不匹配。检查 Network 中是否为 POST，以及 Route Handler 是否导出 `POST`；不要把请求改成 GET 来绕开。

### 请求返回 400

看 Response 中的 `error`，再核对 Payload 的类型、空格、长度和标签。400 可以是正确拒绝；按错误修正输入，不要把服务端验证直接删掉。

### 页面仍然只是本地预览

如果 Network 没有 POST，说明“发送”没有调用真实接口。确认点的是发送按钮，不是预览按钮；让 AI 找到发送事件与 `fetch`，不要用本地回显冒充。

### 服务端显示成功，但页面没有更新

看 Network 的 Response 是否真的有 `ok:true` 和 `resource`。若有，让 AI 检查页面是否等待、解析并展示这次响应；不要从旧预览对象硬填结果。

### 网络连接失败

确认开发服务器是否仍运行、Local 地址是否正确。连接恢复后重新发送；失败时页面不应显示上一次的“已收到”。

### JSON 读取失败

看 Response 是否真的是 JSON，是否返回了开发服务器的错误 HTML 或空响应。让 AI 展示状态码和响应类型，再修对应的 API 或解析错误；不要把解析异常吞掉后显示成功。

### 输入错误时服务端仍返回成功

直接用终端发送空标题或坏标签，排除页面拦截。若仍为 200，检查 Route Handler 的服务端类型、空白、长度与分类验证，再重测。

### AI 擅自接入数据库

先看本轮改动及依赖，要求只移除本次超出范围的数据库代码，保留你原有项目内容和已验证的请求链；不要整项目恢复。

### AI 修改了原始 resources 数据

### 刷新后资料消失

正常。`saved:false` 意味着服务器只收到并回应，没有长期保存。检查正式资料没有增加即可；不要加 localStorage 掩盖这个现象。
