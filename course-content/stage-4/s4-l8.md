## 先知道怎样算完成

本课允许两种如实交付的结果。先看清自己的条件，再继续整理作品；缺少云服务条件时不用编造一个线上地址，也不能省掉本机验收。“部署准备完成、尚未独立上线”的状态，下面称为 `deployment-ready only`。

先读懂交付清单中的三个词：**README** 是项目附带的使用说明文件；**production build（生产构建）**把源代码处理成适合正式运行的产物，本机构建成功仍不等于别人能访问；**Smoke（冒烟检查）**是在实际运行环境里走一小组主要路径，确认登录、调用、确认保存等链路连得通。Smoke 不代替 4.7 的完整安全评估，真实 HTTPS Smoke 也不能用本机页面冒充。

| 状态 | 必须留下的证据 | 可以怎样介绍作品 |
| --- | --- | --- |
| 上线 | 共同要求通过；在真实 HTTPS 地址完成后文检查，记录部署版本、五次迁移、MCP HTTPS 和数据库变化 | 提供实际 HTTPS URL，只声称已验证的结果 |
| 准备 | 共同要求通过；本机生产构建成功，部署配置、迁移顺序和未验证项写清 | 标记尚未上线，使用下方固定记录；不把 localhost 当线上作品 |

选择部署准备完成时，分别写入：

- README：`Live Demo: not published yet`。
- 部署检查记录：`Production deployment not independently completed`。

**两条路径共同必须完成：**作品 README、架构与工具风险清单，三分钟演示，当前项目的测试与 production build，4.7 的完整 20 主案例／73 子案例评估及三个安全硬门槛，本机权限、写入审批、刷新恢复与重复确认实验，生产配置检查和已知限制说明。实际线上 Smoke 只有真实部署后才能记录为通过。

缺少云数据库、平台权限、域名或 Provider 凭证时，可以选择第二条；还没做的云端迁移、HTTPS／模型调用检查要明确列为未验证。**deployment-ready only 是这次课程交付的诚实状态，不是线上已经通过，也不降低任一路径的权限和写入安全要求。**

无论选哪条路径，都只勾选已经实际完成的验收项。部署模板中的空值不等于生产凭据已配置；需要以后填写的变量与还没运行的线上检查，分别记为待配置、未验证。

第三条勾选验收的是**配置核对工作已经完成**：所有必需变量的用途、注入位置、实际配置或待配置状态明确，数据库隔离策略与五次迁移部署顺序完整。上线分支仍须真实配置并验证；准备分支可以有待配置值，但不能缺清单／策略／步骤，也不能把待配置写成已配置。第四条单独记录线上 Smoke 或诚实的准备状态，不能靠第三条勾选冒充已上线。

```bash
git push -u origin HEAD
```
