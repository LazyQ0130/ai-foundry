## 把部署条件写成可核对的清单

生产数据库需要 PostgreSQL 和 pgvector，不能用本机 `127.0.0.1:55433`。`.env.example` 应列全 `DATABASE_URL`、`AGENT_APPROVAL_SECRET`、`MCP_AUTH_SECRET`、`MCP_REFERENCE_URL`、`MCP_ALLOW_LOCAL_HTTP`、Provider endpoint/Key/模型、Embedding 维度与超时。Application Secret 与 Provider Key 都只在服务端，两个 Secret 使用不同随机值，不写 `NEXT_PUBLIC_*`。

真实 Demo 使用 `AI_PROVIDER_MODE=real`、`qwen3.7-flash`、`text-embedding-v4`。保留 `tool_choice=auto`、`enable_thinking=false`、`parallel_tool_calls=false`；模型如果直答，记录它实际走的路径，不硬改成强制 Tool。生产 `MCP_REFERENCE_URL` 指向自己的 `https://<host>/api/mcp/reference`，不要开启 `MCP_ALLOW_LOCAL_HTTP`。

现有 `vercel-build` 顺序是 `prisma generate → prisma migrate deploy → prisma migrate status → next build`。确认五次 migration、schema up to date、KnowledgeChunk 向量列可用。生产库不做 `migrate reset`、`migrate dev` 或 `db push`。如果使用 Vercel Preview，给 Preview 和 Production 分别配置不同的 `DATABASE_URL`：Preview build 也可能跑 `migrate deploy`。没有第二个云库时，可以先只部署 Production，不用生产库做 PR 预览实验。

:::prompt{title="核对部署配置，不触碰 Agent 执行逻辑"}

```text
检查 README、.env.example、package.json 与当前部署目标：列出 Application Secret、Provider Secret 和普通配置；确认生产 AI_PROVIDER_MODE=real、MCP URL 为 HTTPS、MCP_ALLOW_LOCAL_HTTP 未开启；确认 Preview 与 Production 数据库隔离或 Preview migration 不启用；保留 vercel-build 的 migrate deploy/status；确认五次 migration 和 pgvector。不要输出 Secret 值。若云数据库、项目权限或域名缺失，只标记 deployment-ready，不能写假 URL，也不能把测试库当生产库。
```

:::

写 `docs/stage-4-demo-script.md`，按首页、个人搜索、MCP、搜索到提议、刷新恢复、人工确认、重复确认、Eval 与限制安排约三分钟。站在同学或面试官面前照着读一遍，删掉自己说不出口的术语。把 `budget_exhausted`、`paused`、`failed`、`cancelled`、`waiting_approval` 的页面提示过一遍：用户应看到可理解的状态，而非白屏、堆栈或原始 Provider JSON。
