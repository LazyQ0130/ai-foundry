你现在需要理解的只有三件事：工具提供“读一条公开参考”的能力；MCP 是调用它的接入方式；**能用哪些工具仍由自己的应用决定**，外部服务不能自动获得写资料的权限。

MCP 约定了“询问服务提供哪些工具、按规定格式调用工具、收回结果”的通信方式。可以把它理解为双方使用同一张操作单：本地应用填写允许调用的工具和参数，MCP 服务执行并返回参考资料，自己的 Runtime 仍检查结果和后续动作。统一格式方便接入，并不证明外部资料可信，也不替用户批准写入。

## 刚才哪一层做了什么？

`research_reference` 是一项**能力**；MCP 规定客户端如何发现和调用外部能力。模型仍向本地 Agent Registry 提出工具名。Registry 固定允许的工具及 `risk=read`，adapter 才通过 MCP Client、Streamable HTTP 到达 Server。服务端把远端结果缩成严格的三字段对象，以 `role:tool` 数据交回模型。

:::concept{title="Tool 和 MCP 各负责什么？"}
Tool 是 Agent 能提出的具体动作，例如读取一条公开参考。MCP 是客户端和外部服务发现、调用这类动作的协议。接入协议不会替应用做授权：本地 Registry 仍决定开放哪个 Tool、用什么参数、按 read 还是 write 处理。
:::

4.2 的 `search_knowledge` 留在本应用中，因为它需要当前 Session 和 ownerId 数据库过滤。本课 MCP Server 只提供公开资料，不接收用户身份。**MCP 统一接入方式，不授予远端服务应用权限。**

![本地 Registry 固定权限，MCP Client 经协议边界调用公开参考，结果严格校验后作为 Tool 数据返回](/course-media/stage-4/s4-4-01.png "Local Registry → MCP Adapter → Streamable HTTP → MCP Server → strict result → role:tool")

:::concept{title="术语预告：stdio（进阶连接，不是本课前置）"}
现在不用记另一种连接方式的配置，也不用安装或启动第二个服务。stdio 是另一种连接方式：Host 启动本地子进程并通过标准输入输出通信。本课产品路径使用 Streamable HTTP，练习 endpoint 由同一个 Next.js 服务承载；独立进程部署留到进阶实践。不必再给 UI 添加 stdio 开关，也不使用旧 HTTP+SSE 方案。
:::

这些是本机测试操作：让 AI 增量接入 4.2 的 `npm test`／`npm run test:db`，由测试进程启动故障 MCP Server、签发测试凭证并逐项改 audience／scope／时间；本机 Stub 使用假 Key，Token 留在内存。依次运行两条命令，检查每项在工具执行前被拒绝、调用计数／数据库增量和退出 0；失败后恢复合法替身再跑。测试退出自动关闭自建服务，日常项目仍可按上面的正常 MCP 步骤完成，才是恢复成功。不在浏览器复制 Bearer，也不把故障开关接到公开 endpoint。

再用隔离 HTTP 测试依次去掉 Bearer、修改签名、让它过期、换 audience 或 scope，并发送不符的 Host/Origin。这些请求都应在 MCP Tool 执行之前被拒绝。浏览器不能提交 MCP URL、Token、scope、audience 或工具名来替换服务端配置。不要复用 4.3 的 `AGENT_APPROVAL_SECRET`：人工确认与服务间鉴权是两种不同凭证。本机 loopback HTTP 只供课程开发与测试；独立部署使用 HTTPS，并另行完成部署边界验证。

## 再试真实模型

试真实模型前先保存 `AI_PROVIDER_MODE=real` 与自己的 Chat 配置，Ctrl+C 停 dev，再 `npm run dev` 等 Ready，核对 MCP URL 仍是该服务的实际端口。恢复 Mock 也按同样顺序；MCP 的独立 Secret 不随模型模式切换重新生成。

先完成 `npm test`、`npm run build`、隔离 PostgreSQL 路由验收和本地 Provider Stub。Stub 要证明真实 HTTP MCP 往返以及模型第一次 `tool_calls`、第二次 `stop`；MCP 结果在第二次请求中是 `role:tool`，`tool_choice=auto`、`enable_thinking=false`、`parallel_tool_calls=false`。

随后使用本机已配置的 Chat 模型（真实模式），请它先调用 `research_reference` 查询 `RAG` 的公开参考，再简短回答。理想结果是 `2 model / 1 MCP / 1 tool / 0 embedding / 2 Provider units`。模型可能直答；可换少量更明确的自然语言任务，如实记录，不把 `tool_choice` 改成强制调用。MCP 服务仍是本地 deterministic HTTP Server；不要将 API Key、Bearer、Cookie、原始响应或完整 Prompt 写进 Git。
