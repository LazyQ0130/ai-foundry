## 先看两条路，再写循环

在今天做完的实验区，选「直答演示」并运行一次，你会看到 `completed`、模型 1 次、工具 0 次。接着选「Tool 演示」再运行：模型先提出 `echo_research_topic`，服务端验证并执行，将结果作为 `role: tool` 回给模型，模型再回答；这次是模型 2 次、工具 1 次。同一个按钮出现两种路径，这就是本课要做的最小 Agent。

能循环本身没有价值。真正重要的是：**模型只能提出动作，真正执行动作的是你的服务端代码。**你的服务端决定工具名单、参数是否有效、能否执行、还能走几步以及何时停止。

![普通 AI 与受限 Agent 的两条调用路径；模型提出动作，服务端验证后才可执行](/course-media/stage-4/s4-1-01.png "Model decides ≠ Model has permission")

## 第一步：只给模型一个无副作用工具

先在服务端定义 `echo_research_topic`。输入只有 `topic`，输出只是回显收到的研究主题；它不读知识库、不写数据库，也不访问网络。模型可见的是名字、说明和 JSON Schema；真正执行函数、风险标记和严格 Zod Schema 留在服务端。浏览器不能给服务端传任意工具名或用户 ID。

:::prompt{title="建立唯一的只读 Tool Registry"}

```text
请在这个 Stage 4 Starter 中新增服务端 Tool Registry，只注册 echo_research_topic。它的输入是 { topic: string }，去掉首尾空格后要求 1～80 字符；输出为固定回显，不访问数据库或网络。模型可见 name、description、JSON Schema；服务端保存 strict Zod Schema、risk=read 和 execute(validatedArgs, { signal })。校验 tool_call_id、tool name、arguments 最大 2048 字符、JSON、缺字段、类型与额外字段。未知工具、坏 JSON、空字符串和多余 ownerId/userId 一律拒绝。不要实现任何其他工具、审批、MCP 或数据库表。先不要操作 Git。
```

:::

先让 Mock 故意给出 `{"topic":"Git"}`，观察回显。再给出 `{"topic":"Git","ownerId":123}`，应被严格拒绝。这样你看到的不是模型「答应守规矩」，而是应用真的挡住了越界参数。

## 第二步：让模型选择回答或提出工具

把模型决策放进有界 `for` 循环，默认最多 **4 个模型步骤、3 次工具执行**。每次模型调用前依次检查取消、上限与预算。模型若直接回答，返回 `completed`；若提出一个工具调用，先验证，再执行，结果作为 `role: "tool"` 数据回传，进入下一轮。一次返回两个工具时整轮拒绝，绝不能偷偷选第一个。

```text
Goal → Model ──直答──────────────→ completed
             └─一个 Tool Call → Validate → Policy → Execute
                                              ↓
                              Tool Result（数据）→ Model → Stop
```

:::prompt{title="实现最小受限 Agent Loop 与 Provider 接口"}

```text
请继续这个项目，新增清晰的 agent-runtime 和 agent-provider 文件。Agent Loop 使用有界 for，不用 while(true)。默认 maxAgentSteps=4、maxToolCalls=3；每次模型调用前检查 AbortSignal、限制和 Provider budget。只支持 direct answer 或恰好一个 echo_research_topic Tool Call；多个 Tool Call 整轮拒绝，执行次数为 0。工具结果只作为 role:tool 回给模型，不升级为 system 指令。返回 completed、failed、cancelled、max_steps、max_tools、budget_exhausted 等明确状态及受控步骤摘要。真实模式复用现有 ai-provider 的服务端配置、超时、错误映射与 Key；请求使用 tool_choice=auto、enable_thinking=false、parallel_tool_calls=false。Mock 提供稳定的直答和工具路径。保持现有 generate、stream、embed 行为。不要加入知识搜索、写工具或持久化。先不要操作 Git。
```

:::

为什么同时保留直答？`tool_choice=auto` 让模型自己选择；它可以认为问题无需工具。`required` 对本课的 Qwen 模型不是可靠保证。Mock 演示证明程序分支，真实调用证明 Provider 接口，两者各有作用。

## 第三步：接到登录后的工作台

新增受保护的 `POST /api/agent/run`。继续使用现有 Session、同源写保护、每用户每分钟 5 次 HTTP guard 和 10 个真实 Provider 单位预算。一次 Agent HTTP 请求可能有两次模型调用，所以必须**每次真实模型调用前分别扣 1 单位**；Mock 不消耗真实单位。请求体只接受研究目标和固定的教学演示模式，不接受 `userId`、`ownerId`、函数名、风险级别或工具实现。

在首页加一个小实验区：目标输入、直答/Tool 入口、运行、取消、终态、回答、模型/工具次数和几条受控步骤。它是学习入口，不是输出完整 Provider JSON 的调试台。

:::prompt{title="接入受保护 Route 和小型实验区"}

```text
在现有 Next.js 工作台加 POST /api/agent/run 和一个 AgentExperiment 组件，不重做首页。Route 先做现有同源保护、Session 认证、严格请求体校验和 5 requests/min/user 限制；身份只从 Session 得到。每次真实模型调用前复用当前 10 weighted Provider units/min/user 的预留函数，Mock 不扣真实单位。AbortSignal 从请求传到 Runtime、Provider fetch 与 Tool context；取消后不再开始新调用。UI 能选 Mock 直答或 Tool 演示，显示终态、回答和脱敏步骤，提供取消按钮。不要展示密钥、Cookie、system prompt 或原始响应。不要改变原 AI、知识库与 RAG 路由。先不要操作 Git。
```

:::

:::warning{title="Mock 与真实预算的含义不同"}
Mock 是稳定的教学替身，不花百炼费用；真实模式在发出每一次模型请求前预留一个 Provider 单位。一次工具闭环通常是两次模型调用，不是一条 HTTP 请求就算一个单位。
:::

## 故意让它失败

现在运行固定故障实验。可用 Mock 的受控模式或本地 Provider Stub，逐项观察页面状态和测试断言。故障实验不需要给工具增加危险能力。

| 故障 | 你应该看到 |
|---|---|
| 未知工具名 | `failed`；工具执行 0 次 |
| 坏 JSON 参数 | `failed`；没有猜测或修补参数 |
| 多余 `ownerId` 字段 | strict Zod 拒绝；工具执行 0 次 |
| 一次两个 Tool Calls | 整轮拒绝；工具执行 0 次 |
| 模型反复请求工具 | 到 `max_steps` 或 `max_tools` 后停止 |
| 预算不足 | `budget_exhausted`；下一次 Provider 请求没有发出 |
| 运行中取消 | `cancelled`；之后不再开启模型或工具 |

:::task{title="亲手复核三条安全边界"}
运行「未知工具」「多余字段」「多个工具」三种模式，记下每次工具执行数。再试预算不足与取消。回答自己：这些停止是谁决定的——模型，还是你的服务端？
:::

:::check{title="完成故障实验后"}
- `npm test` 覆盖直答、工具闭环、非法参数、多工具、上限、预算和取消。
- 多工具时没有执行第一个工具；取消后没有新调用。
- 失败信息只给受控类别，不泄漏 Provider 原文或服务端配置。
:::

## 最后再做一次真实调用

只有 Mock、Stub 测试和本机构建通过后，才把 `.env` 的 `AI_PROVIDER_MODE` 设为 `real`，填写你自己的北京地域百炼配置。用非敏感短主题先试普通解释，再试「请用 echo_research_topic 规范化主题 RAG，然后报告结果」。记录模型调用次数、工具执行次数、`finish_reason`、usage 与耗时，不保存完整请求、回答或 Key。

真实模型可能第一次选择直答。这不是程序坏了，也不要改成 `tool_choice=required`。最多换两次更明确的自然语言任务；若仍直答，就如实记录。代码正确性的硬证据是 deterministic Mock/Stub，真实验收用于检查集成链路。

## 看改动，保存可恢复版本

运行 `git status`、`git diff`、`git diff --check`。指出新增的 Tool 定义、参数校验、模型调用、循环停止、Route 与 UI 分别在哪个文件；确认原 Auth、RAG 和四次 migration 没被无关改动。检查暂存区没有 `.env`、Key、数据库连接串或运行日志，再保存一次版本，例如提交信息 `build limited agent loop`。

本课只得到一个**请求内**的只读小 Agent。下一课才把已有知识库检索接成真实业务工具；写入确认、MCP、多步工作流与持久化都在后续课程。现在你应该能清楚地说：**模型只是提出动作，执行权在服务端。**
