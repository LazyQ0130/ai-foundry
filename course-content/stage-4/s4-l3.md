## 刚才为什么停住了？

4.1 中，模型提出只读 Tool，服务端校验后执行；4.2 中，模型提出搜索 query，服务端用 Session 决定检索谁的资料。这次模型提出的是**写操作**。它可以建议标题和内容，但不能替你批准保存。

:::concept{title="HMAC 能保证什么？"}
HMAC 用服务端 Secret 给“当前用户、工具、精确参数和过期时间”做防篡改签名。浏览器提交的是凭证，不是重新选择写入内容。签名能发现参数被改，却不会自动记住凭证是否用过；本课稍后会亲眼测试重放。
:::

模型看到的 JSON Schema 只描述 `title` 与 `content`。服务端再次用 strict Zod 检查类型、长度和额外字段；`risk=write` 是 Tool Registry 的固定元数据。Runtime 根据这个风险停在 `waiting_approval`。提议不算工具执行，数据库也没有变化。审批规则放在 Runtime / Policy 层，以后接入其他工具时仍经过同一判断。

## 点击确认，只保存刚才看到的内容

现在需要让确认按钮真正保存，但浏览器不能在确认时重新发送标题、内容、ownerId 或工具名。否则用户看到的提议和最终执行的参数可能被偷换。

:::prompt{title="给确认动作绑定同一份参数"}

```text
请在服务端新增 AGENT_APPROVAL_SECRET 环境变量占位符；让我在本机 .env 里用加密安全随机数生成至少 32 字节的 Secret，不提交真实值。模型参数经 strict Zod 规范化后，用固定字段顺序 JSON.stringify({ title, content }) 生成 canonicalArgs。签发短时 HMAC-SHA256 Token，payload 绑定 v=1、当前 Session userId、固定 toolName=save_research_note、canonicalArgs、约 5 分钟 expiresAt 与随机 nonce；签名只用服务端 Secret。

新增 POST /api/agent/confirm：先检查同源与当前 Session，只接受 strict { approvalToken } 请求体；恒时比较 HMAC，检查过期、userId 与固定工具名，再将 Token 中的 canonicalArgs 重新用写工具的 strict Zod 解析。只从这份已验签参数执行 prisma.resource.create：title=title、desc=content、tag="文章"、ownerId=当前 Session 用户；important 保持数据库默认 false。仅返回安全字段和 saved 状态。确认时不要再次调用模型。

AgentExperiment 的「确认保存」只发送 approvalToken。按钮 pending 时可以禁用以免误触，但不要把它称作防重放。给我一个真实 PostgreSQL 测试：提议后 Resource 条数不变，确认后恰好多一条，保存字段与页面提议一致，确认接口模型调用数为 0。
```

:::

本机生成 Secret 后再次运行提议。先看清标题和内容，再点「确认保存」。资料列表现在应多 1 条，标题、简介与提议一致，分类为「文章」。确认请求只有 Token；最终写入参数来自服务端验证过的签名内容，归属来自此刻的 Session。模型没有第二次决定写什么。

:::warning{title="审批 Secret 只留在服务端"}
`AGENT_APPROVAL_SECRET` 只写进本机未提交的 `.env`；不要放进页面、`NEXT_PUBLIC_*`、课程笔记或 Git。课程与测试只使用变量名或安全占位值，不打印真实 Token。
:::

:::check{title="确认后的观察"}
- 未确认时新增 Resource 为 0；确认后新增 1。
- 保存的 `title`、`desc` 与规范化后的提议完全相同，`tag=文章`、`important=false`。
- `ownerId` 取自当前 Session；确认阶段模型调用为 0。
:::

## 故意偷换，再看哪里拒绝

:::prompt{title="验证参数、身份与时间边界"}

```text
请补测试，覆盖 save_research_note 的空值、错误类型、超长与 title/content 以外的 ownerId、userId、tag、important、id 等字段；未知写工具和一次多个 Tool Calls 也不能执行。确认接口带额外 title/content 字段要拒绝。分别修改已签 Token payload 的 title、content、toolName、userId、expiresAt、nonce，再修改 signature；保留旧签名的篡改都应拒绝且 DB 不变。Alice 的 Token 给 Bob 当前 Session 确认要拒绝；过期 Token 用可注入时钟或测试 helper 模拟，不等待五分钟。也验证不同 JSON 字段顺序无法改变服务端 canonicalArgs。

回归 echo_research_topic 与 search_knowledge、Embedding 预算不足和取消。保持 4.2 已做的缺少 Embedding 预算预留能力时拒绝搜索测试；本课只补写提议、验签、篡改和重放的验证。
```

:::

看测试时先问：谁能决定 `ownerId`？答案仍是 Session。谁能决定最终写入参数？用户看到的是模型提议，经服务端校验并签名的那一份；浏览器只能提交凭证。HMAC 使 Token 被修改后验签失败，短有效期缩小凭证可使用的时间窗口。

## 再做一次会成功的攻击：重放

把同一个**仍有效、未经修改**的 Approval Token 连续提交两次到隔离测试数据库。预期两次验签都成功，数据库增加 **2** 条相同笔记。把测试结果明确标为 `CURRENT KNOWN LIMITATION: stateless HMAC approval is replayable`，不要把这条测试当作失败，也不要把 Token 本文打印出来。

这说明**防篡改和防重放是两件不同的事**。HMAC 可以证明参数和身份绑定后没有被改；纯无状态 HMAC 不知道一枚合法 Token 是否已经使用过。前端禁用按钮只改善误触体验，不能证明服务器只执行一次。不要用内存 `usedTokens = new Set()` 假装解决：重启和多实例会失效。正式消耗状态、唯一幂等键与事务留到 4.6，本课应如实保留限制。

## 最后试真实模型

先运行 `npm test`、`npm run build`、隔离 PostgreSQL 验收和本地 Provider Stub。确认确定性路径通过后，把本机配置切到真实北京地域 `qwen3.7-flash`，保持 `tool_choice=auto`、`enable_thinking=false`、`parallel_tool_calls=false`。用非敏感短任务说「请提出保存一条研究笔记，标题为……，内容为……」。观察是否由一次模型决策产生 `waiting_approval`：确认前 DB 增量应为 0，确认后为 1，确认本身模型调用为 0。模型也可能直答；最多换少量更明确的自然语言问题，如实记录结果，不强制 Tool。

真实模式之后再跑 Direct、echo、知识搜索和取消，确认前两课仍能用。不要把 API Key、完整 Token、Cookie、数据库 URL、原始 Provider 响应写进日志或 Git。
