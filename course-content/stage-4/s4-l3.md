## 刚才为什么停住了？

4.1 中，模型提出只读 Tool，服务端校验后执行；4.2 中，模型提出搜索 query，服务端用 Session 决定检索谁的资料。这次模型提出的是**写操作**。它可以建议标题和内容，但不能替你批准保存。

:::concept{title="HMAC 能保证什么？"}
**Secret** 是只保存在服务端的一段随机秘密。**HMAC 签名**是服务端用它和提议内容计算出的校验标记；确认时重新计算，检查两者是否一致。它绑定“当前用户、工具、精确参数和过期时间”，这些字段与签名一起组成 **approvalToken（确认凭证）**。

例如 Alice 看到标题「Git 笔记」、内容「记录版本历史」，凭证就绑定这份提议。有人把内容改成别的文字却保留旧签名，检查应失败；Bob 拿 Alice 的凭证也不能批准。浏览器提交的是凭证，不是重新选择写入内容。签名保护的是内容未被偷换，**不是把内容加密藏起来，也不是证明 AI 写得对**；仍要由你阅读并确认。

签名不会自动记住凭证是否用过。**重放**指把同一份合法凭证再提交一次，不是让模型重新提议。本课稍后会观察重复写入，4.6 才让数据库记录这个动作已执行，保证同一动作只保存一条。
:::

模型看到的 JSON Schema 只描述 `title` 与 `content`。服务端再次用 strict Zod 检查类型、长度和额外字段；`risk=write` 是 Tool Registry 的固定元数据。Runtime 根据这个风险停在 `waiting_approval`。提议不算工具执行，数据库也没有变化。审批规则放在 Runtime / Policy 层，以后接入其他工具时仍经过同一判断。

## 点击确认，只保存刚才看到的内容

现在需要让确认按钮真正保存，但浏览器不能在确认时重新发送标题、内容、ownerId 或工具名。否则用户看到的提议和最终执行的参数可能被偷换。

确认时，浏览器只提交服务端签好的凭证，不重新选择写入内容。服务端核对“是谁、保存什么、凭证是否过期”；这次先防止参数被偷换。同一合法凭证能否被重复使用，还要按后面的重放实验亲自检查。

:::deepdive{title="给 AI 的技术备注：确认凭证的签名约定"}
字段和算法名可照抄；当前用户绑定、精确参数、过期拒绝、跨用户拒绝与重放实验都要验收。

必要约定：确认接口只接受 approvalToken。服务端 HMAC-SHA256 绑定当前用户、工具、同一份规范化参数、约 5 分钟过期时间与 nonce；审批 Secret 至少 32 字节且只留服务端。HMAC 保证防篡改，本课尚不保证防重放。nonce 是每次签发的随机标记，不是“已经使用过”的数据库记录。
:::

### 第一次生成审批 Secret：生成、保存、检查、重启

Secret 是只给服务端使用的随机签名密钥，不能自己写一个好记的密码。先在**自己的 Stage 4 项目根目录**用 `dir`／`ls` 确认 `package.json`。下面命令 Windows PowerShell 和 macOS 都可以复制，使用 Node 自带的加密随机数，不安装额外软件：

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

**成功标志：只输出一行 43 个字符的随机字符串。** 32 是随机字节数，43 是编码后的字符数，两者不同。由你本人在终端选中复制这行，Windows 可右键复制／Ctrl+Shift+C（视终端），macOS 用 Cmd+C；不要在运行中的 dev 终端按 Ctrl+C 试图复制。随机值不用发给 AI，也不写到课程笔记、截图或提交记录。

在编辑器打开与 `package.json` 同层的本机 `.env`；没有就新建 `.env`，开头有点且无 `.txt` 后缀。保留已有数据库与模型配置，追加**一行**（这是文件内容，不是终端命令）：

```text
AGENT_APPROVAL_SECRET="这里替换成刚生成的完整随机字符串"
```

不要连同终端提示符一起复制；文件里不能有两个同名项。若已有有效审批 Secret 就沿用，不为每次运行重新生成。Next 会优先读 `.env.local` 等配置；不要让这些文件或旧终端变量中有另一个同名值，让 AI 只核对文件名／键名并消除重复，不回显秘密。

:::concept{title="术语预告：MCP 的鉴权 Secret（4.4 才配置）"}
MCP 是后续接入外部工具的方式，现在不用记协议细节。4.4 会另生成 `MCP_AUTH_SECRET`，专门给服务间调用使用；当前的 `AGENT_APPROVAL_SECRET` 只签写入审批。两者必须不同，不提前填占位值冒充已配置，也不能拿同一个随机值兼任。
:::

在 `.gitignore` 保留 `.env*` 与 `/.runtime/`，先运行：

```bash
git check-ignore .env
```

再运行只显示路径的跟踪检查：

```bash
git ls-files -- .env .env.local .env.development .env.development.local
```

**成功标志：第一条输出 `.env`，第二条没有输出。** 若文件已跟踪，单纯加忽略规则不够；对一个明确文件执行 `git rm --cached -- .env`（换成实际已跟踪路径）只停止跟踪、保留本机文件，再核对两条检查。若真实秘密已经进过提交或分享出去，需要更换该秘密，不能声称加 gitignore 就抹掉历史。

还没复制 Stage 4 工具时，从下面下载，只复制 `scripts` 文件，不替换项目。同名文件先比较。配置检查会使用项目实际 Next 环境，终端只输出长度与通过标志，不回显 Secret：

:::resource{asset="stage4-tools"}
:::

```bash
node --input-type=module -e "import {loadCourseEnv} from './scripts/course-env.mjs'; loadCourseEnv(); const s=process.env.AGENT_APPROVAL_SECRET||''; if(!/^[A-Za-z0-9_-]{43}$/.test(s)||Buffer.from(s,'base64url').length!==32){console.error('FAIL APPROVAL_SECRET_CONFIG');process.exit(1)} if(process.env.MCP_AUTH_SECRET===s){console.error('FAIL SECRETS_MUST_DIFFER');process.exit(1)} console.log('PASS approval-secret: 32 random bytes / 43 characters');"
```

**成功标志：`PASS approval-secret: 32 random bytes / 43 characters`，没有 FAIL。** 这检查本次命令实际加载的格式，随机性来自前面的 randomBytes 生成命令；格式正确不能证明自己编的字符串足够随机。沿用的旧 Secret 若使用其他编码但满足服务端至少 32 字节约定，不为了此格式检查盲目换值，让 AI 核对实际服务端校验并报告长度、不回显值。

保存文件后，在 dev 终端按 Ctrl+C 停服务，重新在项目目录执行：

```bash

```

等 Local／Ready，再回页面**重新产生一份新提议**；旧提议取消即可。先看清标题和内容，再点「确认保存」。**成功标志：waiting_approval 时新增 0，确认请求返回成功，资料列表多 1 条，标题、简介与提议一致、分类为「文章」，确认阶段没有新增模型调用。** 最终写入参数来自服务端验证过的签名内容，归属来自此刻的 Session，模型没有第二次决定写什么。

:::stuck{title="Secret 已填写，但提议或确认仍失败"}
`node` 找不到先回环境页检查 Node 安装；模块找不到先复制工具并完成依赖安装。`FAIL APPROVAL_SECRET_CONFIG` 检查文件名、实际加载优先级、占位符、同名重复和首尾空格，不把随机值发给 AI。忽略检查无输出则先修 .gitignore／跟踪状态，不能暂存秘密文件。`APPROVAL_SECRET_NOT_CONFIGURED` 检查服务端是否读同一个键并已重启；浏览器不能读取 Secret 是正常设计，不改成 NEXT_PUBLIC。`SECRETS_MUST_DIFFER` 只为其中一个用途重新生成独立值，保存后重启。更换 Secret、提议过期或服务重启后，不反复点旧 Token；取消旧提议再生成新提议。确认接口仍拒绝时看脱敏错误类别和状态码，不打印 Token，也不关验签。
:::

如果误改了 Secret，先停止确认操作；仍有本人安全保存且从未泄漏的旧值，就只恢复 `.env` 的这一行并重启；没有可用旧值或怀疑泄漏，就新生成一个值并重启。**恢复标志：重新生成的提议可正常确认，旧 Secret 签发的提议不再使用。** 这不是撤销已写入的笔记，也不需要删除数据库记录。改密钥会让旧凭证失效；不要靠复制测试项目 `.env` 或回退整个配置文件恢复。

:::warning{title="审批 Secret 只留在服务端"}
`AGENT_APPROVAL_SECRET` 只写进本机未提交的 `.env`；不要放进页面、`NEXT_PUBLIC_*`、课程笔记或 Git。课程与测试只使用变量名或安全占位值，不打印真实 Token。
:::

## 再做一次会成功的攻击：重放

沿用 4.2 已完成的 `stage4_checks` 与 `npm run test:db`，让 AI 把本课 PostgreSQL 篡改／跨用户／过期和重放断言加进去，再运行。脚本在内存中取得和重发新 fixture 的 Token，不需要从浏览器复制凭证；只对测试库新增笔记计数，原日常库不变。报告分别显示拒绝时新增 0、合法确认 +1、同一有效 Token 两次确认合计 +2；测试断言通过与“当前可重放限制”同时记录。缺少入口先回 4.2 补测试开发，不能只运行无数据库的 npm test 就声称已看过重放。

把同一个**仍有效、未经修改**的 Approval Token 连续提交两次到隔离测试数据库。预期两次验签都成功，数据库增加 **2** 条相同笔记。把测试结果明确标为 `CURRENT KNOWN LIMITATION: stateless HMAC approval is replayable`，不要把这条测试当作失败，也不要把 Token 本文打印出来。

这说明**防篡改和防重放是两件不同的事**。HMAC 可以证明参数和身份绑定后没有被改；纯无状态 HMAC 不知道一枚合法 Token 是否已经使用过。前端禁用按钮只改善误触体验，不能证明服务器只执行一次。不要用内存 `usedTokens = new Set()` 假装解决：重启和多实例会失效。正式消耗状态、唯一幂等键与事务留到 4.6，本课应如实保留限制。

:::concept{title="术语预告：幂等与事务（4.6 才实现）"}
幂等在这里指同一确认动作重发，仍只保存一条笔记；事务会把保存笔记和标记“已执行”绑在一起，失败时一起撤回。现在不用记数据库字段和锁的写法。4.6 才实现这两项；本课必须如实留下“合法凭证仍可重放”的实验结果，不能提前把它说成只会写一次。
:::
